# internal-docs/ — внутренние документы, не публикуются

Каталог создан в FIX-43 (PRJ-02), 29.10.2026.

До этого 49 `.md` лежали в `docs/`. GitHub Pages отдаёт каталог `docs/`
целиком (источник — ветка, `.nojekyll` отключает Jekyll, поэтому
`exclude` из `_config.yml` не применяется вообще), и внутренние заметки
открывались по прямым адресам:

- `https://deadsno.github.io/brain-25-evidence/dev/STATE.md` → 200,
  журнал циклов с хэшами коммитов;
- `…/briefs/q14_audit.md` → 200;
- `…/adr/README.md` → 200.

Те же файлы теперь лежат здесь, по тем же относительным путям
(`internal-docs/dev/STATE.md`, `internal-docs/briefs/…`,
`internal-docs/adr/…`), поэтому перекрёстные ссылки внутри документов
продолжают работать. Ссылки на файлы, оставшиеся в `docs/`
(`openapi.yaml`, `postman_collection.json`, `batch_pipeline.bpmn`,
`methodology.html`, `faq.html`), обновлены на `../docs/…`.

## Правило

- **Публикуется** только `docs/`. Всё, что не должно быть доступно по
  URL, кладётся вне `docs/`.
- `.md` в `docs/` быть не должно: это признак того, что внутренний
  документ снова попал в публикацию. Проверка — `tests/test_no_bom.py`
  (скан двух корней) и `docs-sync` скилл.
- Секреты не кладём ни сюда, ни в `docs/`: репозиторий публичный.

## Что где

| Каталог | Содержимое |
|---|---|
| `dev/` | рабочие инструкции агентам, состояние цикла, мониторинг, очередь approve |
| `briefs/` | брифы батчей и аудитов |
| `adr/` | архитектурные решения |
| `api/v1/` | текстовые описания API (errors, sequence, схемы) — сами схемы остались в `docs/api/v1/` |
| `bpmn/` | описание процесса; `.bpmn` и скриншот остались в `docs/bpmn/` |
| корень | SRS, RTM, NFR, ERD, DFD, DMN, глоссарий, user stories, velocity и т.п. |
