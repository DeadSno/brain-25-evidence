# User Stories — требования к API и UI

> Формат: «Как [роль], я хочу [действие], чтобы [ценность]».
> Acceptance Criteria (AC) — как проверить что история выполнена.

## Эпик 1: Пользовательский UI

### US-01. Поиск добавки по названию
**Как** посетитель сайта, **я хочу** ввести название добавки в поиск, **чтобы** быстро найти карточку.

**AC:**
- [ ] Поле поиска видно в шапке на всех страницах
- [ ] Поиск работает по мере ввода (debounce 300ms)
- [ ] Учитывает регистр и раскладку (Креатин = креатин = Kreatin)
- [ ] Показывает до 10 результатов с подсветкой
- [ ] Enter открывает первую карточку

**Приоритет:** Must have
**Эстимация:** 3 story points

### US-02. Фильтрация по грейду
**Как** исследователь, **я хочу** фильтровать карточки по грейду (A/B/C/D), **чтобы** видеть только доказанные добавки.

**AC:**
- [ ] Чекбоксы A, B, C, D в сайдбаре
- [ ] Множественный выбор (A + B)
- [ ] Счётчик найденных обновляется мгновенно
- [ ] URL сохраняет фильтр (?grade=A,B)

**Приоритет:** Must have
**Эстимация:** 2 SP

### US-03. Сравнение двух добавок
**Как** пользователь, **я хочу** сравнить две добавки на радаре, **чтобы** выбрать лучшую для моей задачи.

**AC:**
- [ ] Выбор двух карточек через модалку
- [ ] Радар по 5 осям (grade, SI, MA, эффекты, механизмы)
- [ ] Экспорт PNG

**Приоритет:** Should have
**Эстимация:** 5 SP

### US-04. Просмотр взаимодействий
**Как** пациент, **я хочу** видеть все взаимодействия добавки с лекарствами, **чтобы** не навредить себе.

**AC:**
- [ ] Список в карточке с severity (low/medium/high/critical)
- [ ] Группировка по типу (лекарство / БАД / состояние)
- [ ] Ссылка на источник (PMID)

**Приоритет:** Must have
**Эстимация:** 3 SP

## Эпик 2: REST API

### US-05. Получить список добавок
**Как** внешний разработчик, **я хочу** получить полный датасет в JSON, **чтобы** построить свой сервис.

**AC:**
- [ ] `GET /api/v1/supplements.json` возвращает 130 карточек
- [ ] Ответ соответствует OpenAPI-спеке
- [ ] Content-Type: application/json
- [ ] Кэшируется CDN (Cache-Control: max-age=3600)

**Приоритет:** Must have
**Эстимация:** 2 SP

### US-06. Получить метаданные
**Как** LLM-агент, **я хочу** узнать количество добавок и эндпоинты, **чтобы** планировать запросы.

**AC:**
- [ ] `GET /api/v1/index.json`
- [ ] Поля: count, grades, categories_atomic, ids
- [ ] Ответ < 5 KB

**Приоритет:** Must have
**Эстимация:** 1 SP

### US-07. Фильтрация на сервере
**Как** разработчик, **я хочу** фильтровать через query-параметры, **чтобы** не грузить весь датасет.

**AC:**
- [ ] `?grade=A,B` — фильтр по грейду
- [ ] `?category=sport` — по категории
- [ ] `?limit=10&offset=0` — пагинация
- [ ] Возвращает `{ count, results: [] }`

**Приоритет:** Should have (v2)
**Эстимация:** 5 SP

## Эпик 3: Maintainer

### US-08. Обновить карточку без потери истории
**Как** maintainer, **я хочу** обновлять карточки через git, **чтобы** видеть историю изменений.

**AC:**
- [ ] Все правки через скрипты (не руками)
- [ ] Каждая правка — отдельный commit
- [ ] Тесты запускаются автоматически

**Приоритет:** Must have
**Эстимация:** Уже сделано

### US-09. Запустить batch за 1 команду
**Как** maintainer, **я хочу** добавить 10 добавок за час, **чтобы** расширять базу.

**AC:**
- [ ] CSV → _drafts → enrich → apply
- [ ] Один скрипт `run_batch.py --batch 18`
- [ ] Прогресс в stdout
- [ ] Ошибки с авто-retry

**Приоритет:** Should have
**Эстимация:** 8 SP
