## Главное: постановка задачи устарела

Пина `main h1 { font-size: 1.35rem !important }` **нет в коде уже две волны назад**.
Его снял коммит `756a2d0 fix(stage1c): a11y + i18n + bump ?v=423`. Текущий кэш — `?v=425`,
то есть 1C — это два бампа назад от HEAD.

Строка `style.css:1616` из задания — не правило, а строка внутри комментария-баннера
`/* ===== sup/* страницы (5 файлов) ... */`. Первое совпадение `1.35rem` в файле —
комментарий на строке 1803, который **сам фиксирует снятие пина**:

```css
/* docs/style.css:1806-1812
   v5.6.3 (этап 1C, A1): ОПОРА СНЯТА. Пин был не структурой, а следствием
   старой шкалы: 21.6px стояли на 144 страницах ... Теперь font-size здесь
   не задаётся вообще — h1 берёт 1.75rem из базового правила `h1` ... */

main h1 { font-weight: 700 !important;                      /* style.css:1813 */
  line-height: 1.25 !important; margin: 0 0 .8rem !important;
  color: var(--text) !important; }
```

`font-size` в `main h1` отсутствует — h1 проваливается в базовое правило.

### Две аномалии, обе объяснены

**1. `docs/google4a9d23e35c6c3e23.html` — h1 отсутствует.**
Файл верификации Google для site-verification. Заголовков не имеет по устройству страницы,
дефектом не является.

**2. `docs/offline.html` — h1 = 20.8 px.** Единственный настоящий остаток. Причина —
локальный `<style>` на `offline.html:47`:
```css
h1 { font-size: 1.3rem; font-weight: 600; margin: 0 0 10px; }
```
На странице **ноль h2 и h3** — инверсии нет, это пережиток эпохи пина, а не поломка
иерархии.

> **Почему не починено (осознанное решение, не пропуск).**
> Граница задания — только `docs/style.css`. Локальный `<style>` в `offline.html`
> подключается **после** `<link>` на style.css при равной специфичности (0,0,1),
> поэтому обычное правило в style.css проиграет. Победить можно только вернув
> `!important` — то есть тем самым анти-паттерном, ради устранения которого #19 и
> существует. Правильное лечение — убрать локальный `<style>`, но это правка
> `offline.html`, вне границы.
> Замер: h1 = 20.8 px на 1280 и на 375, `scrollWidth == clientWidth` на обоих.
