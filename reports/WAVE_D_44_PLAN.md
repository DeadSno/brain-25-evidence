# Диагностика #44 — a11y/снапшоты только в тёмной теме

Ветка `v5.6-dev`. Дата 2026-10-12. **Это диагностика, реализации не было.**

---

## Итог одной строкой

Механизм переключения темы **один и простой** — `localStorage['theme'] === 'light'`
даёт класс `light` на `<html>`, тёмная тема это отсутствие класса. Но затронуть надо
**4 места** с захардкоженной темой (порог остановки — «больше 3»), и главная цена
вопроса не в часах, а в том, что набор эталонов вырастет вдвое: 139 МБ → 280 МБ.

## ЧАСТЬ A — текущее состояние

### A1. Как тесты задают тему

**`tests/test_visual_snapshots.py`**

| Строка | Что там | Смысл |
|---|---|---|
| 114 | `EXPECTED_HTML_CLASS = {p: "" for p in PAGES}` | ожидание «на `<html>` нет класса `light`», т.е. тёмная |
| 120 | `COLOR_SCHEME = "light"` | **системная** тема браузера, не наш переключатель |
| 280–282 | `CONSENT_INIT_JS` → `localStorage.setItem('cookie-consent','rejected')` | единственная запись в localStorage во всём файле |
| 494–499 | сверка `document.documentElement.className` с `EXPECTED_HTML_CLASS` | `pytest.fail`, если тема «поменялась» |
| 639, 656, 720 | `color_scheme=COLOR_SCHEME` | три места создания контекста |

Подтверждено: `COLOR_SCHEME = "light"` — это `color_scheme` контекста Playwright
(то, что отдаёт `prefers-color-scheme`). К нашему переключателю отношения не имеет
и не переключает ничего, кроме `offline.html` (см. A3).

Про `localStorage['theme']` в тестах — **ноль упоминаний**. Тесты выходят в
свежий контекст, тема не задаётся, страница приходит в тёмной.

**`tests/test_a11y_axe.py`**

- `:78` импортирует `COLOR_SCHEME` из модуля снапшотов, `:289` — `color_scheme=COLOR_SCHEME`.
- `:281–297` — параметризация только по `page_name` и `width,height`.
- `:297` `_verify(f"{_slug(page_name)}-{width}", violations)` — ключ базы без темы.
- `:336` `expected = {f"{_slug(p)}-{w}" for p in PAGES for w, _ in VIEWPORTS}` — та же матрица.
- Отдельного `CONSENT_INIT_JS` нет: **баннер согласия на момент прогона axe видим**.

`tests/a11y_baseline.json`: 36 ключей вида `atlas-1280`, темы в ключе нет.

### A2. Как страницы переключают тему

Механизм **один на весь сайт**:

```js
// docs/script.js:233-236 и копии этого кода в каждом .html
var saved = localStorage.getItem('theme');
if (saved === 'light') setLight(true);   // v5.4.0 dark-first
```

Ключ — **`theme`**, значение — строго `'light'`. При `'light'` добавляется
`light` на `<html>` и на `<body>`; тёмная тема = **отсутствие** класса
(комментарий `style.css:185-190`, `script.js:234`).

Палитра (`docs/style.css`):
- `:36`, `:144`, `:184` — `:root` = **тёмная** (применяется по умолчанию).
- `:191` — `html.light{--bg:#f5f5f7;--text:#1c1c1e;--card-bg:#fff;...}` — светлая палитра.
- `:196` — `--grade-*-tx` для света; `:201-215` — 13 иконных токенов для света.
- Ещё ~25 селекторов вида `html.light ...` (кнопки, карточки, sidebar, баннер).
- Селекторов **`body.light` в CSS нет ни одного** (проверено: 0 совпадений) — класс на `<body>` декоративный.

Переключатель в разметке — `#themeBtn` (есть на всех 12 корневых + ~170 `sup/*`),
подпись меняется `🌞 Светлая тема` ⇄ `🌙 Тёмная тема`.

Светлая палитра не «заготовка» — она дописана под реальные нужды (v5.6.2 E3, v5.6.3 E1),
то есть light — рабочая тема, а не эксперимент.

### A3. `offline.html` — исключение, и оно ломает «всё dark»

`docs/offline.html`: **нет ни скрипта темы, ни класса `light`**. Тёмная тема там
задана только через `@media (prefers-color-scheme: dark)` (`offline.html:35`).

При `COLOR_SCHEME = "light"` браузер отдаёт `prefers-color-scheme: light` →
**эталон `offline` сегодня СВЕТЛЫЙ**, несмотря на общий девиз «снапшоты только dark».
Это уже зафиксировано в комментарии `test_visual_snapshots.py:110-113`.

Вывод: добавление light — не «переключить одну константу». Для 17 страниц тема
живёт в `localStorage`, для `offline.html` — в `color_scheme`. Нужна функция
`color_scheme(page, theme)`, а не одна константа.

### A4. Побочная находка (баг в проде, не в тестах)

`docs/trends.html:17`:

```js
try{if(localStorage.getItem('theme')==='light'){...add('light')...}
    else{...add('light')...}}catch(e){...add('light')...}
```

Все три ветви делают одно и то же. То есть на `trends.html` у `<body>` класс
`light` **всегда**, независимо от выбора пользователя. На вид не влияет (селекторов
`body.light` нет), но это мусор от копипасты. Отдельная задача, в оценку #44 не входит.

### A5. Стоп-условия — проверка

- ✅ «Не удалось понять как переключается тема» — **не сработало**, механизм разобран.
- ⚠️ «Больше 3 мест где тема захардкожена» — **сработало, мест 4**. Ниже список.
  Ни одно из них не требует неразрешимого решения, но порог формально пробит,
  поэтому решение остаётся за владельцем.

**Места, которые придётся параметризовать (4):**

1. `test_visual_snapshots.py:114` — `EXPECTED_HTML_CLASS`, словарь страница→класс.
2. `test_visual_snapshots.py:120` + `:639/656/720` — `COLOR_SCHEME` станет функцией `(page, theme)`.
3. `test_visual_snapshots.py:294/495/649` — имена эталонов `_slug(page)-{width}` и разбор ключа.
4. `test_a11y_axe.py:297/336` — ключ базы `_slug(page)-{width}` и матрица покрытия в

## ЧАСТЬ C — эталонов и место на диске

```
tests/snapshots/chromium/  38 PNG
tests/snapshots/webkit/    37 PNG
                          ─────
                          75 PNG   (в git — 77 файлов, +2 служебных .gitignore)
каталог целиком:          139.3 MB
git pack репозитория:     100.2 MiB
```

Расхождение 38/37 — не ошибка: webkit не снимает `index@412` целиком
(37402 px > потолок Playwright 32767 px, `FULL_PAGE_CAP_PX` на `:146`), там `pytest.skip`.

**Если добавить light:**

| | сейчас | с light |
|---|---|---|
| PNG | 75 | 150 |
| каталог | 139.3 MB | ~279 MB |
| git pack | 100.2 MiB | ~200 MiB |

Светлая тема — плоские заливки, PNG жмётся лучше тёмной, так что реально будет
ближе к 250–270 MB, но порядок тот же.

⚠️ Это и есть главное решение: **это не бесплатный удвоитель, это постоянный груз
в истории git на 100+ MiB.**

## ЧАСТЬ D — план реализации

### Текущее состояние (сводно)

- axe: **39 тестов** (36 прогонов), только тёмная
- snapshots: **76 тестов**, только тёмная (кроме `offline`, который светлый по факту)
- эталонов: **75 PNG, 139.3 MB**
- база a11y: 36 ключей, 29 записей, 25 из них — контраст тёмной темы

### Как добавить light

**Переключение темы — через `add_init_script`, не кликом.**

```python
THEME_INIT_JS = {"light": "try{localStorage.setItem('theme','light')}catch(e){}",
                 "dark":  ""}   # свежий контекст = тёмная
```

Почему так: скрипт выполняется **до** скриптов страницы, поэтому `html.light`
ставится синхронно в `<head>` — до `style.css`, без вспышки. Клик по `#themeBtn`
хуже: он срабатывает после `DOMContentLoaded`, оставляет полосу «мигания» в момент
первой отрисовки и добавляет ненадёжный элемент синхронизации. Прецедент в проекте
есть — `CONSENT_INIT_JS` (:280) ровно так и сделан.

Тёмная тема = пустой скрипт: свежий контекст и так тёмный, ничего задавать не надо.

**Для axe:**

- добавить `@pytest.mark.parametrize("theme", ("dark", "light"))`
- в контекст — `ctx.add_init_script(THEME_INIT_JS[theme])`
- ключ базы: `f"{_slug(page)}-{width}-{theme}"` (36 → 72 записи)
- поправить `test_a11y_baseline_covers_every_page:336` под новую матрицу,
  иначе база light посчитается «устаревшей» и тест упадёт наоборот
- **учесть**: cookie-баннер во время прогона axe видим. В light он отрисуется иначе —
  возможно, придётся включить `CONSENT_INIT_JS` и в axe, чтобы матрица была
  сопоставима с тёмной базой. Это отдельное решение, влияет на обе темы.

**Для снапшотов:**

- параметризация по `theme` в трёх тестах
- `EXPECTED_HTML_CLASS` → словарь `(page, theme)`: `""` для dark, `"light"` для light;
  `offline.html` — `""` в обоих случаях (класса не бывает)
- `COLOR_SCHEME` → `f(page, theme)`: для 17 страниц неважно, для `offline.html`
  `dark` требует `color_scheme="dark"` — иначе «тёмный» эталон offline окажется светлым
- имена: `{slug}-{width}-{theme}.png`, `modal-index-{theme}.png`,
  `cookie-banner-{theme}.png`

### Хранение: папки или суффикс

Рекомендую **папки** `tests/snapshots/{chromium,webkit}/{dark,light}/`:
`_assert_snapshot` и `snap_dir` (:345) уже работают с каталогом, добавление одного
уровня — три строки, а имена файлов остаются короткими и читаемыми
(`index-1280.png` вместо `index-1280-light.png`).
При суффиксе пришлось бы править формат имени в трёх местах и рисковать коллизией
при разборе ключа.

### Риски

1. **Контраст в светлой теме — неизмеренная территория.** 25 из 29 записей базы —
   `color-contrast`, и все они тёмные. Светлый `#fbbf24` на белой карточке даёт
   1.6:1 (это прямо написано в комментарии `style.css:199-200`) — такие места
   есть, и axe их найдёт. Это цель работы, но объём неизвестен.
2. **Дрейф движка в ×2.** `DIFF_TOL_PCT = 0.05` калиброван на 75 снимках в тёмной.
   На 150 снимках ложных падений станет больше просто потому, что сравнений вдвое
   больше. Порог может понадобиться пересмотреть — это отдельное решение, а не
   молчаливое ослабление.
3. **Размер репозитория ×2** (см. ЧАСТЬ C).
4. `offline.html` не имеет переключателя темы — для него light/dark различаются
   только через `color_scheme`. Это ломает «тема = одна ось» и требует отдельной
   ветки в коде.

### Стоп-сигналы для реализации

- axe в light даёт **> 20 нарушений** (учитывая, что в тёмной базе всего 25
  записей — это двукратный рост) → СТОП, разбирать точечно.
- Снапшоты light расходятся с dark по размеру более чем на **±10%** по высоте
  → СТОП, обсуждать (значит, светлая палитра тянет высоты, и это отдельная правка вёрстки).
- Один прогон даёт **> 10 снимков, не сошедшихся сразу** → СТОП, вероятен не
  индивидуальный дрейф, а системная нестабильность в light.
