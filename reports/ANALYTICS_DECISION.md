# ЧАСТЬ A — Текущее состояние

## A.1 / A.2 Где стоит

| Что | Страниц | Файл |
|-----|--------:|------|
| `mc.yandex.ru/metrika/tag.js` | **1** | `index.html` |
| `ym(…)` инициализация | **1** | `index.html` |
| пиксель `<noscript>` `mc.yandex.ru/watch/` | **1** | `index.html` |
| Clarity / GA4 / Plausible / Umami / Matomo | **0** | — |

Пиксель находится на **той же** странице, что и счётчик:

```html
<noscript><div><img src="https://mc.yandex.ru/watch/112465667"
  style="position:absolute; left:-9999px;" alt="" /></div></noscript>
```

Счётчик стоит **после `</head>`, в `<body>`** (позиция 7781 при `</head>` на
7674) — то есть грузится при рендере.

## A.3 Что счётчик настроен собирать

Полный код инициализации:

```js
ym(112465667, 'init', {
  ssr: true,
  clickmap: true,
  ecommerce: "dataLayer",
  referrer: document.referrer,
  url: location.href,
  accurateTrackBounce: true,
  trackLinks: true
});
```

| Параметр | Что означает | Оценка |
|----------|--------------|--------|
| `clickmap: true` | **тепловая карта кликов с координатами** | на сайте о здоровье — вопрос минимизации данных |
| `referrer` / `url` | полный URL и источник перехода | передаётся целиком, вместе с параметрами |
| `trackLinks: true` | внешние ссылки считаются переходами | полезно |
| `accurateTrackBounce` | точный отскок | полезно |
| `ssr: true` | серверная аналитика | при статике на GitHub Pages **смысла нет** |
| `ecommerce: "dataLayer"` | слой данных для ecommerce | ecommerce на сайте **нет** — параметр бессмысленный |
| `webvisor` | **запись сессий** | **не включён** — это хорошо |

## A.4 Приватность

| Что | Значение |
|-----|----------|
| настройки анонимизации IP в коде | **отсутствуют** |
| где настраивается анонимизация | в интерфейсе Метрики, **из репозитория не проверяется** |
| механизм согласия (cookie/consent) | **0 файлов** |
| `Do Not Track` | **0 файлов** |

Никакого механизма согласия нет ни в одном файле проекта — ни бана, ни
переключателя, ни заглушки на `Do Not Track`.

## A.5 Техническое ограничение, о котором надо знать заранее

**Пиксель `<noscript>` нельзя закрыть JavaScript-проверкой согласия.** Это
обычный запрос `<img>`, он уйдёт при любом состоянии, если не закрыть его
условным HTML-комментарием или не убрать. Любая схема согласия должна
предусматривать и его — иначе получится «согласие есть, а запрос всё равно
ушёл».

## A.6 Инфраструктура

| Что | Значение — и почему это главное |
|-----|----------------------------------|
| хостинг | **GitHub Pages**, `https://deadsno.github.io/brain-25-evidence/` |
| серверной части | **нет** — нет бэкенда, нет базы, нет места для своего счётчика |
| `robots.txt` | есть, указывает на sitemap |
| `sitemap.xml` | есть, **17 URL** |
| GitHub Actions | есть (`tests.yml`, `watchdog.yml`, `sync_version.yml`) |

Отсюда следует: **самостоятельный хостинг аналитики невозможен** без покупки
VPS. Это не деталь, а половина решения.

## B.1 Google Search Console — ✅ внедрять сейчас

**Что даёт.** Единственный инструмент из списка, который даёт данные, которых
нет больше ниоткуда: какие запросы приводят на сайт, что индексируется, какие
страницы отвалились. Остальные инструменты показывают, что делали те, кто уже
пришёл.

**Стоимость.** Ноль.

**Что нужно.** Аккаунт Google, верификация одного из двух способов — TXT-запись
в DNS или файл на домене. `robots.txt` и `sitemap.xml` уже есть и уже указывают
на правильный домен, то есть **половина подготовки сделана**.

**Код трогать не надо.** В отличие от счётчиков, GSC не пишет в браузер
посетителя.

**Когда.** До v5.2. Иначе рост с 18 до 130+ страниц пройдёт незамеченным, и
восстановить, какие страницы привели трафик, потом не получится.

## B.2 Cookie-баннер — ⚠️ нужен, но только если остаётся Метрика

Формально вопрос выглядит так: есть трекер, нет согласия. Но решение
разветвляется:

| Сценарий | Нужен баннер? |
|----------|---------------|
| Метрика снята | **нет** — трекера нет |
| Метрика перенесена на все страницы | **да**, плюс надо закрыть `noscript`-пиксель |
| Замена на инструмент без cookie | вопрос смещается: возможно, достаточно раскрытия, а не баннера |

**Но это юридический вывод, а не технический.** Нужен юрист — именно он
решает, достаточно ли раскрытия для инструмента без cookie. Скилл не имеет
права решать это за него.

**Что нужно технически.** Баннер плюс **гасирование обоих** запросов: и
`tag.js`, и пикселя. Пиксель — не JavaScript, его закрывать нужно иначе.

## B.3 Метрика — ⚠️ снять или перенести на все 18

Не оставить как есть. Текущий вариант плох по обеим причинам: риск без
согласия при почти нулевых данных.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Оставить на 1 странице | ноль работы | данные почти бесполезны; риск остаётся |
| Перенести на все 18 | наконец видно поведение | нужен баннер + работа по 18 файлам |
| **Снять** | риск снят, кода меньше | не видно посещаемости вовсе |
| Заменить на без-cookie | риск снижен, лёгкий код | нужна регистрация в стороннем сервисе |

**Рекомендация — снять или заменить.** Если владелец не смотрит в Метрику
сегодня (а счётчик стоит с 2026-09-14 и, судя по всему, не открывался),
точный счётчик на одной странице — это только риск без пользы.

Попутно, если оставлять: убрать бессмысленные `ssr: true` (при статике) и
`ecommerce: "dataLayer"` (ecommerce нет), и решить по `clickmap` — запись
координат кликов на сайте о здоровье.

## B.4 Microsoft Clarity — ❌ отложить

**Что даёт.** Запись сессий: видео, как человек двигает курсор. Плюс
тепловые карты, без которых нельзя понять, где человек не находит нужное.

**Стоимость.** Ноль. Но бесплатно — за счёт данных посетителей.

**Почему не сейчас.** Это **самый чувствительный инструмент из всего списка**.
Запись поведения на сайте о здоровье — это уже не агрегированная статистика.
`clickmap` в Метрике — меньшее зло, но уже включён; добавлять поверх запись
сессий незачем.

Может понадобиться позже — когда будет **v5.8 и отзывы**: понять, как
посетители пользуются блоком отзывов, тепловая карта на нескольких десятках
страниц оправдает себя. До этого — наблюдение за людьми без причины.

## B.5 GA4 — ❌ не внедрять

**Что даёт.** Продуктовая аналитика: воронки, события, сегменты, связь с
рекламой.

**Почему нет.** Дублирует Метрику — обе отвечают на вопрос «сколько людей
зашло и откуда». GA4 выигрывает только когда нужны воронки и рекламная
атрибуция; на сайте-справочнике с 130 статьями их нет.

Дополнительно: тяжелее Метрики заметно, и доступ к Google-сервисам из России
нестабирен — счётчик может молча перестать работать.

## B.6 Umami / Plausible — 🟡 замена, если аналитика нужна

**Что общего.** Оба легковесные, без cookie, без сбора персональных данных,
обычно самостоятельный хостинг. Ключевое отличие от Метрики — **не хранят
идентификаторы посетителей**, поэтому вопрос согласия смещается с «нужен ли
баннер» на «достаточно ли раскрытия». Это решение юриста, не наше.

**Стоимость — и здесь развилка:**

| Вариант | Цена | Требует |
|---------|------|---------|
| **Umami Cloud** | **бесплатно** (hobby) | аккаунт, один `<script>` |
| Plausible Cloud | от ~$9/мес | карта, один `<script>` |
| Свой Umami / Plausible | VPS ~$5/мес | сервер, Docker, домен |

**Свой хостинг отпадает:** сайт на GitHub Pages, сервера нет. Если владелец
не готов платить за VPS — остаются только облачные тарифы.

**Рекомендация — Umami Cloud.** Бесплатно, без cookie, ставится одним скриптом.
Plausible — если готовы платить: лучше поддержка и остаётся путь на
самостоятельный хостинг, если позже появится VPS.

**Что нужно.** Аккаунт, один `<script>` в общий `style`-паттерн подключения —
и **на все страницы**, иначе повторяется нынешняя проблема.
