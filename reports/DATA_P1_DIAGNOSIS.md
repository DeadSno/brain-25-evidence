## DATA-P1-02 — `hedges_g_outcome`

### Арифметика аудита не сходится

Формулировка «пусто у 86 карточек» неверна. Фактически по `docs/data.json`:

| Метрика | Значение |
|---|---|
| карточек всего | 130 |
| ключ `hedges_g` присутствует | 130 (у всех) |
| **непустой** `hedges_g` | **86** |
| ключ `hedges_g_outcome` присутствует | **86** |
| **непустой** `hedges_g_outcome` | **44** |
| есть `hedges_g`, но outcome пуст | **42** |
| outcome непустой, а ключа нет | 0 |

То есть «86» — это не число пустых, а число карточек **с ключом**.
Разбивка: **44 заполнено / 42 пусто / 44 карточки вовсе без ключа**
(44 без ключа = 130 − 86; из них 27 не нашли ни одного кандидата в
`hedges_g_all.json`, остальные 17 — не проходились прогоном).

### Главный факт: поле нигде не используется

```
docs/*.html — 0 совпадений
docs/*.js   — 0 совпадений
```
`hedges_g` (без суффикса) используется — `docs/script.js:981, 993, 1018`
(scatter «g × scienceIndex» и tooltip). `hedges_g_outcome` не
упоминается **ни в разметке, ни в скриптах**. Пустые 42 значения не видны
пользователю вообще.

### Почему 42 пустых — и почему это не чинится кодом

`scripts/extract_g.py::_outcome()` ищет в абстракте MA-статьи термин из
фиксированного словаря `OUTCOME_TERMS` (45 английских слов) в окне ±220
символов вокруг найденного g. Не нашёл — вернул `""`.

Проверено сетью: все 42 PMID перекачаны из PubMed, текущий словарь
воспроизводит **0 из 42** (значит данные не устарели — извлечение
детерминировано). Расширенный словарь (~130 терминов) находит **11 из 42**,
но половина — мусор:

| Карточка | «Исход» расширенного словаря | Вердикт |
|---|---|---|
| Биотин | vitamin d | шум |
| Псиллиум | chloride | шум |
| Селен | selenium | само-подстановка (это сам Селен, а не исход) |
| Кальций | vitamin d | шум |
| Витамин A | vitamin d | шум |
| Лизин | oxidative | спорно |
| Чеснок | hdl, ldl | правдоподобно |
| Инозитол | preterm, bmi, weight | правдоподобно |
| …31 карточка | ничего | — |

**Автоизвлечение исхода из чужой абстрактной MA-статьи методически
ненадёжно** — особенно для 44 карточек, где PMID вообще переиспользуется
между карточками (механизм `reused_shared` в `fetch_hedges_g.py`).

### Варианты (нужен выбор владельца)

| Вариант | Что делаем | Время | Итог |
|---|---|---|---|
| **A. Удалить мёртвое поле** | выкинуть `hedges_g_outcome` из `data.json` и `fetch_hedges_g.py`, поправить `reports/audits/data.md` | **30 мин** | P1 закрыт честно; на сайт ноль влияния |
| **B. Разметить вручную** | 86 карточек × выбрать исход глазами по статье | **2–4 ч** | Данные станут осмысленными, но поле всё равно не рендерится |
| **C. Отрендерить** | показать исход на карточках | 2 ч + снимки | Только после B, иначе покажем мусор |
| **D. Оставить как есть** | переформулировать пункт аудита | 10 мин | P1 → P3 как «косметика данных» |

**Рекомендация: A.** Поле не рендерится, автозаполнение не восстановимо,
а 42 пустых значения никто не видит. Это декоративная правка данных,
а не P1.
