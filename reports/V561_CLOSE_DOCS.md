### ⚠️ Важный побочный эффект, обнаруженный при merge

Файлы `q14_batch_*_proposal.json` читаются скриптами по относительному пути
(`scripts/apply_adv.py`, `apply_mechs.py`, `validate_proposal.py`,
`enrich_drafts.py` и др.). После `git rm --cached` они пропали **из рабочей
копии при переключении веток** — при checkout на `main` их стало 0, хотя на
`v5.6-dev` перед этим было 19.

Восстановлено из истории (`git checkout e3ab730 -- reports/q14_batch_*.json`)
и расиндексировано (`git restore --staged`), чтобы вернуть состояние
«на диске, но не отслеживается». Итог на `main`:

- 19 файлов на диске ✅
- 0 tracked ✅
- игнорируются правилом ✅
- `git status` чист ✅

**Что это значит для команды:** при свежем `git clone` этих файлов **не
будет**. Скрипты, которым нужен proposal-файл, придётся генерировать заново
либо брать из истории (`git show <rev>:reports/<файл>`). Это ожидаемое
следствие решения владельца, но стоит знать явно — см. вопрос 1.
