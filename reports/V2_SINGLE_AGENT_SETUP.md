## 0. Главное расхождение: здесь OpenCode **1.18.33**, а не v2

Задание исходило из того, что стоит v2. Проверено фактически:

```
opencode --version   -> 1.18.33
```

Это меняет три пункта задания:

| Пункт задания | Реальность |
|---|---|
| «OpenCode v2» | **1.18.33** |
| `disabled_providers` в конфиге | **ключа не существует** в v1 (сверено с типами установленного `@opencode-ai/sdk` 1.18.30 — ключа нет среди верхнеуровневых) |
| «Блок `lsp` оставить как есть» | блока `lsp` в конфиге **нет** вообще, LSP подхватывается автоматически |
| «Оставить только `mcp` и `lsp`» | осталось 4 ключа: `$schema`, `shell`, `plugin`, `mcp` |

### 1.3 OpenRouter отключён — не так, как в задании

`disabled_providers` добавлять нельзя: ключа нет в v1, он был бы молча
проигнорирован. Сделано через два обратимых шага:

1. `opencode auth logout openrouter` → «Logout successful», в `auth.json`
   стало **0 credentials** (была 1 — `openrouter`).
2. `OPENROUTER_API_KEY` удалена из **User-окружения** (73 символа).

Обратимо: повторный логин и восстановление переменной.

**Чего это пока не отменило:** `opencode models` всё ещё перечисляет
`openrouter/*`. Причина — процесс OpenCode унаследовал переменную до
изменения, и каталог моделей вообще строится из общего реестра, а не из
наличия ключа. Полная проверка требует перезапуска OpenCode.

## 2. GigaChat: **не настроен**, задание содержало нерабочий адрес

| Проверка | Результат |
|---|---|
| `github.com/Overman775/opencode-gigachat-plugin` | репозиторий существует (HTTP 200) |
| npm `@ai-sdk/gigachat` | **E404** |
| npm `opencode-gigachat` | **E404** |
| npm `gigachat` | 0.0.20 (другой пакет, не плагин OpenCode) |
| `GIGACHAT_CREDENTIALS` (User) | **не задана** |
| `GIGACHAT_API_KEY`, `SBER_API_KEY` | **не заданы** |

Причина, по которой я не добавил провайдера в конфиг: в задании указан
`baseURL: "https://api.gigachat.local/v1"`. Домен `.local` не резолвится —
это нерабочий адрес, и провайдер с ним молча не ответит. Плюс нет
учётных данных. Добавлять такую конфигурацию означало бы оставить в конфиге
работающий на вид, но не работающий резервный канал.

Что нужно от владельца: реальный `baseURL` GigaChat и credentials
(`GIGACHAT_CREDENTIALS` — authorization key или client secret, зависит от
режима авторизации). Плагин из репозитория есть, но ставить его без
проверки я не стал: у нас нет среды, где можно убедиться, что он грузится.
