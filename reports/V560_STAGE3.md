## 2. `docs/sup/index.html`: как построен и откуда данные

Страница **генерируется**, руками не писалась. Источник данных —
`docs/data.json`, тот же, что и у 130 страниц добавок.

### Разметка

```
<header class="top"> + <div class="trustbar">   — как на docs/sup/*.html
<nav class="breadcrumbs">  Назад → Главная → <strong>Каталог БАДов</strong>
<section id="controls">     поиск + «Любая категория» + «Любой грейд»
<section id="cardsContainer">
  <h2>Все добавки <span id="countBadge">показано 130 из 130</span>
  <div id="cardsGrid"> … 130 × <a class="card"> … </a>
<footer class="site-footer"> — тот же, что на страницах добавок
```

Собственных CSS-правил на странице **два**, оба в `<style>` шаблона:

```css
#cardsGrid .card{display:block;color:inherit;text-decoration:none}
#cardsGrid .card[hidden]{display:none}
```

Первое нужно потому, что карточка — это `<a>`, а в `style.css` есть голое
правило `a{color:var(--accent)}`: без снятия подчёркивания и цвета сетка из
130 карточек читалась бы как список синих ссылок. Второе — см. п.1.
Всё остальное (сетка `repeat(auto-fill,minmax(240px,1fr))`, стекло, hover
`translateY(-4px)`, тени, цвета, Inter, тёмная тема = отсутствие `.light`)
берётся из `style.css`. Своих цветов, своих шрифтов и своей темы страница
не вводит — иначе она была бы «как бы частью сайта».

### Что на карточке

Ровно пять полей из задания, ничего лишнего:

```html
<a class="card" href="kreatin.html" data-slug="kreatin" data-cat="Спорт/Когниция"
   data-grade="A" data-code="1" data-hay="креатин спорт/когниция работает a">
  <span class="cat">Спорт/Когниция</span>          ← категория
  <strong class="card-title">Креатин</strong>        ← название
  <div class="verdict v1">работает</div>            ← вердикт
  <span class="grade gA" title="Грейд A — …">Грейд A</span>   ← оценка
</a>                                                 ← slug в href и data-slug
```

`href` относительный (`{slug}.html`), потому что `index.html` лежит внутри
`sup/`. В Playwright проверил все 130 `href` регуляркой
`/^[a-z0-9-]+\.html$/` — неrelative-ссылок 0.

Классы бейджей взяты у главной страницы, а не придуманы: `.verdict.v1/.v0/.v-1`
(`style.css:790-792`) и `.grade.gA…gD` (`style.css:782-785`) — те же, что
рисует `script.js` на `docs/index.html`. Внешне карточка неотличима от
карточки главной.

### Категории: фильтр, а не группировка

В `data.json` **79 разных категорий на 130 записей**, больше половины — по
одной записи. Группировка по категориям дала бы ~79 секций с одним
элементом — это не каталог, а коллекция заголовков. Поэтому категория
работает фильтром: `<select>` из 79 пунктов с количеством
(`Кишечник (3)`, `Когниция (6)`), плюс фильтр по грейду (`A (8) B (45)
C (52) D (25)`) и поиск по названию/категории/вердикту. Модальные фильтры
главной (`#controls`, тот же блок разметки) переиспользованы: стили, раскладка
и поведение при ≤768px взяты из `style.css` без единого нового правила.

Фильтр — 25 строк JS, которые только **прячут** несовпавшие карточки.
Без JS страница читается полностью: все 130 карточек в разметке, а текст
счётчика «показано 130 из 130» проставлен генератором, а не скриптом.
Проверено: с отключённым JS каталог остаётся рабочим списком ссылок.

Проверка фильтров в браузере (Playwright, 1280×900):

| Действие | Счётчик | Кто остался |
|---|---|---|
| без фильтров | `показано 130 из 130` | 130 |
| грейд = A | `показано 8 из 130` | B9, Витамин D, Железо, Кальций, Кофеин, Креатин, Мелатонин, Сывороточный протеин |
| категория = `Когниция/Инсульт` | `показано 1 из 130` | CDP-холин |
| поиск `магний` | `показано 1 из 130` | Магний |
| поиск `zzzz` | `показано 0 из 130` | — |
| сброс | `показано 130 из 130` | 130 |

`display:none` у спрятанных проверен через `getComputedStyle`: у всех 122
скрытых карточек `display: none` (после починки из п.1).

## 3. Генерация: куда положил функцию и почему

### Решение

Функция `build_index()` добавлена **в `scripts/build_sup.py`** (рядом с
существующими `build_context()` и `make_env()`), шаблон —
`templates/sup_index.html.j2`.

Почему не отдельный `scripts/build_sup_index.py`:

1. **Один источник правды по слагам.** `slugify()`, `text()`, `html_val()`,
   `GRADE_COLORS`, предупреждения о грейдах и `load_records()` уже живут в
   `build_sup.py`. Второй скрипт обязан был бы их либо импортировать
   (тогда он не «отдельный»), либо продублировать — и через месяц две копии
   разошлись бы в трактовке `нет данных` и экранировании. Каталог ссылается
   на те же `{slug}.html`, что и страницы: разные слаг-правила здесь дали бы
   битые ссылки на 130 карточек.
2. **Один запуск = одно состояние.** `python scripts/build_sup.py` теперь
   пересобирает секцию целиком: 130 страниц и каталог. Отдельный скрипт
   означал бы два запуска и два места, где можно забыть.
3. **Проект уже так устроен.** В `scripts/` лежат `build_index.py`,
   `rebuild_index.py`, `build_interactions.py` — но они делают *другую*
   работу (сборка данных, а не рендер HTML). HTML рендерит только
   `build_sup.py` (+ `build_edu.py` для своей секции).
4. **Флаги остались те же.** Унаследованы `--data`, `--out`,
   `--template-dir`, `--dry-run`, добавлен `--skip-index` (когда правят
   только страницы добавок и каталог трогать не надо).

### Идемпотентность: вывод двух прогонов подряд

Защита от типичных причин расхождения заложена в коде, а не в hoped-for:

| Источник diff | Что сделано |
|---|---|
| дата/время генерации | не выводятся нигде (в 130 страницах их тоже нет) |
| порядок обхода словаря | карточки сортируются `sorted()` по `(название, slug)`; по сырым строкам, не по экранированным |
| плавающие числа | счётчики категорий и грейдов — `Counter` по тем же карточкам, не «последние N» |
| рандом | нет ни одного источника случайности |
| локаль | каталог всегда `sup/index.html`, в `--out` |

Фактический вывод (второй прогон подряд, сравнение sha256 всех 131 файла):


`git status --short docs/sup/` после обоих прогонов одинаков:

## 4. Breadcrumbs

### 4.1 Где был TODO и что заменил

`templates/sup.html.j2`, блок `<nav class="breadcrumbs">`:

```jinja
было:
    <nav class="breadcrumbs">
        <!-- TODO v5.6.0 этап 3: заменить на sup/index.html, когда появится индекс раздела -->
        <a href="../index.html">Главная</a> → <a href="../index.html">Все добавки</a> → <strong>{{ name }}</strong>
    </nav>

стало:
    <nav class="breadcrumbs">
        <a href="../index.html">Главная</a> → <a href="index.html">Все добавки</a> → <strong>{{ name }}</strong>
    </nav>
```

Ссылка **«Все добавки»** → `index.html` (соседний файл, то есть `sup/index.html`).
Ссылка **«Главная»** осталась `../index.html` — она ведёт на главную страницу
сайта, и из подкаталога `sup/` путь именно такой. Это ровно то различие,
которое задание просило не сломать.

Комментарий с TODO удалён, а объяснение перенесено в **Jinja-комментарий**
(`{# … #}`), а не в HTML: HTML-комментарий размножился бы на 130 страниц
(это и было причиной, по которой его писали в шаблоне, но печатать в вывод
не стоит). Jinja-комментарий в вывод не попадает — проверено побайтово.

### 4.2 Что ещё было не так в шаблоне (обнаружено попутно)

Побайтовая сверка генератора с эталоном (`build_sup.py --only` в отдельный
каталог + сравнение с `docs/sup/`) показала: **единственное** расхождение
между шаблоном и закоммиченными страницами — `?v=413` против `?v=414`.
То есть без правки любая перегенерация в рамках этапа 3 откатила бы бампер
CSS на всех 130 страницах. Шаблон приведён к `?v=414`; после этого
перегенерация даёт байт-в-байт совпадение с эталоном (проверено на 5
эталонных страницах: `IDENTICAL BYTE-FOR-BYTE`, 0 расхождящихся строк).

   `страниц с неожиданными правками: 0 из 130`.
2. **Ссылки.** Все 130 страниц перегенерированы; `TODO` в `docs/sup/*.html`
   — **0 совпадений** (и в `templates/*.j2` — 0).
3. **Локальные ссылки целиком.** Проверены все `href`/`src` на всех 131
   страницах: `1703 локальные ссылки, битых 0`. Сюда входят 130 ссылок на
   карточки, `../style.css`, `../version.js`, `../pwa.js`, `../share.js`,

4. **Клик в браузере.** `sup/kreatin.html` → клик по «Все добавки» →
   `http://127.0.0.1:8000/sup/index.html`, `h1 = «Каталог БАДов»`,

## 7. Красные флаги

1. **`sup/index.html` не внесён в `docs/sw.js`** (список прекеша) и в
   `docs/sitemap.xml`. Оба файла не мои. Последствие: офлайн-пользователь
   каталог не получит, а из `sitemap.xml` он не узнает о новой странице
   (хотя найдёт её по крошкам с 130 страниц).
2. **Ссылка на каталог с главной страницы не появилась.** `docs/index.html`
   — чужой файл. Сейчас каталог достижим только из крошек страниц добавок;
   посетитель, попавший на главную, о нём не узнает. Это дыра в обнаружимости.
3. **Новая страница не покрыта визуальными снапшотами и axe-проверками.**
   `PAGES` в `tests/test_visual_snapshots.py` задаётся константой, новой
   страницы там нет, поэтому регрессия вёрстки каталога поймает только
   `test_no_orphan_classes`. Это же означает, что её a11y (а `PAGES`
   импортируется в `test_a11y_axe.py`) не проверяется вообще.
4. **Надпись крошки на страницах добавок осталась «Все добавки»,** а не
   «Каталог БАДов». Это сознательно: переименование меняет пиксели и роняет
   20 эталонов снапшотов (5 страниц × 2 вьюпорта × 2 браузера). «Все добавки»
   — ровно та формулировка, которой на главной назван раздел
   (`docs/index.html:364`), так что она не выбивается из словаря сайта.
5. **79 категорий в одном выпадающем списке** — длинно. Это следствие
   данных (на 130 записей 79 категорий, из них больше половины с одной
   записью). Если владелец хочет 8–12 крупных групп, нужен маппинг категорий,
   и это решение по данным, а не по вёрстке.
6. **Число «130» зашито в HTML дважды** (заголовок и текст счётчика) и
   обновляется только перегенерацией. Так же устроены и 130 страниц
   (например, `Индекс науки: 1265`), так что это не новая проблема — но
   при `data.json` на 131 запись каталог разъедется, пока не пересобран.
7. **`pytest -q` сейчас не зелёный** из-за счётчика тестов в
   `docs/version.json` (п.5.7). До коммита 2 это нужно закрыть, иначе коммит
   уедет с красным прогоном.
8. **Починка `[hidden]` локальная.** Если тот же паттерн фильтра кто-то
   скопирует на другую страницу, `display:block` на карточке снова перебьёт
   `[hidden]`. Комментарий в шаблоне об этом есть; в `style.css` правило не
   выносил — это была бы правка чужого файла ради одной страницы.
