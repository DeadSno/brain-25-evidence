## 1. Стоп-условие: ветка не готова к merge

Три независимых блокера, каждый сам по себе достаточен.

### P0-1 · Тег v5.6.1 указывает на коммит из main, которого нет в v5.6-dev

```
git rev-list -n 1 v5.6.1   → 21f296f3926edb70c6b022a90f8bd89b2b1ae729
git describe --tags v5.6-dev → v5.6.0-65-g7c56970
git merge-base --is-ancestor 21f296f v5.6-dev → NO
git merge-base --is-ancestor 21f296f main      → YES
git branch --contains 21f296f → main, origin/main
```

Тег `v5.6.1` проставлен на коммите `21f296f`, который **принадлежит `main` и не входит в `v5.6-dev`**. При этом `git describe` для текущей ветки даёт `v5.6.0-65-g7c56970` — то есть с точки зрения ветки последний достижимый тег это **v5.6.0**, а не v5.6.1.

Почему это блокер: любой релизный процесс, который опирается на `git describe`, возьмёт неверную версию. Плюс `CHANGELOG.md:7-8` утверждает «Тег не поставлен — это решение владельца», а тег **уже стоит** и указывает на другую ветку. Документация и состояние репозитория противоречат друг другу.

### P1-2 · pytest даёт 813, а не 1010

Фактический прогон:

```
811 passed, 2 skipped, 1 warning in 22.18s
```

Задание и `docs/version.json` ждут **1010**. Расхождение объяснимо и **не является поломкой** — но требует решения, потому что цифра в `version.json` показывается пользователю.

Полная разбивка гейтов (замерено):

| Гейт | Переменная | Тестов | Примечание |
|---|---|---:|---|
| Обычный прогон | — | **813** | 811 passed + 2 skipped |
| + snapshots | `RUN_SNAPSHOTS=1` | +74 | 73 passed + 1 skipped |
| + a11y | `RUN_A11Y=1` | +39 | axe-core, нужен браузер |
| + tabs | `RUN_TABS=1` | +42 | нужен :8000 и браузер |
| + graph | `RUN_GRAPH=1` | +42 | нужны :8000 и браузер |
| **Итого собрано** | | **1010** | |

813 + 74 + 39 + 42 + 42 = 1010 — сходится точно.

Механика: `tests/conftest.py:14` `pytest_collection_modifyitems` **удаляет** (`items[:] = [...]`) пункты с маркерами `snapshots`, `a11y`, `tabs`, `graph` при отсутствии переменных окружения. `--collect-only` показывает 1010, потому что считает до удаления; фактически исполняется 813.

**Существенная деталь:** маркер `e2e` не удаляется, а помечается `skip` — поэтому 2 e2e-теста видны как skipped, а не исчезают.

**Это ровно техдолг #87** из `ROADMAP.md:1373`:

> `check_state.py` показывает tests:989, `pytest` собирает 792. Расхождение — счётчик ведёт свой подсчёт (включая deselected). Уточнить формулу или синхронизировать с pytest. | **v5.6.2**

Находка уже заведена владельцем и стоит на v5.6.2. Значит это не новая проблема, а подтверждение существующей — с уточнением: **1010 в `version.json` — это `testscollected` до фильтрации, а не число реально выполненных тестов.**

Побочный эффект: тест `tests/test_version_json_counts_match_reality.py::test_version_json_tests_match_collected` проходит, потому что сверяет `version.json` с тем же предфильтровым счётчиком. То есть гейт подтверждает согласованность цифры с формулой, но не то, что тесты реально выполняются.

**СТОП. Ветка не готова к merge.**

Стоп-условие задания («release-check находит неготовность к merge → СТОП») сработало по трём независимым причинам:

3. **P1** — CHANGELOG не документирует 37 коммитов работы.

Плюс два открытых пункта техдолга, прямо привязанных к v5.6.2: **#87** (счётчик тестов) и **#93** (неполный mobile-аудит, объявленный условием merge).

### Порядок действий

1. Влить `main` в `v5.6-dev`, разрешить конфликты по `docs/sitemap.xml`, `docs/feed.xml`, `docs/version.json`.
2. Прогнать `pytest -q` на разрешённом дереве — убедиться, что 813 на месте.
3. Прогнать `RUN_SNAPSHOTS=1 pytest -q -m snapshots` — ожидается 73 passed, 1 skipped.
4. Решить по #87: либо `tests: 1010` переименовать в «собрано» / вывести фактическое число 813, либо считать по-разному явно.
5. Решить по #93: провести mobile-аудит или письменно отложить.
6. Написать секцию `## [v5.6.2]` в CHANGELOG.
7. Обновить хвост ROADMAP (L1627–1628) и бамп `docs/version.json` до 5.6.2.
8. **Тег ставить последним**, после мержа и зелёного прогона. Текущий тег v5.6.1 — либо переставить, либо задокументировать решение владельца.

## 6. Ограничения отчёта

- CI проверен по публичному GitHub API без авторизации: видны conclusion и ветка, но не логи конкретного шага. Один failure 2026-10-08T03:44 не разбирался — он перекрыт двумя последующими success, но содержимое неизвестно.

- Проверка `main` против `v5.6-dev` сделана на локальных копиях веток; `git fetch` не выполнялся, состояние origin может отличаться.
