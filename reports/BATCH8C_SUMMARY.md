## 1. `DATA-P1-02` — `hedges_g_outcome` (вариант A)

Арифметика исходной находки была неверна. Факт по `docs/data.json`: 130
карточек, ключ есть у **86**, непустых значений **44**, `hedges_g` при пустом
outcome — **42**. То есть «86» — это число карточек **с ключом**, а не с
пустым значением.

Решающий аргумент: `hedges_g_outcome` **не читается ни одним** `docs/*.html`
и ни одним `docs/*.js` (проверено grep). Само `hedges_g` используется —
`docs/script.js:981, 993, 1018`. Поле занимало место, не давая эффекта.

Почему значения пусты: `_outcome()` в `scripts/extract_g.py` ищет в абстракте
MA-статьи термин из фиксированного словаря `OUTCOME_TERMS` (45 английских
слов) в окне ±220 символов вокруг g. Сетевая перепроверка всех 42 PMID из
PubMed: текущий словарь — **0/42** (значит, данные не устарели, а извлечение
детерминировано), расширенный (~130 терминов) — **11/42**, из них мусор
(«Биотин → vitamin d», «Псиллиум → chloride», «Селен → selenium»,
«Кальций → vitamin d», «Витамин A → vitamin d`).

Удалённая запись в `scripts/fetch_hedges_g.py` + ключ из `docs/data.json`,
`tests/snapshot_data.json`, `data/supplements_slim.json`. Верификация:
сравнение `git show HEAD:<file>` с рабочей копией карточка-в-карточку —
изменилось **только** снятие ключа, ни одно другое значение не тронуто.

Диагностика целиком: [`DATA_P1_DIAGNOSIS.md`](DATA_P1_DIAGNOSIS.md).

### Ловушки, найденные попутно

1. **`tests/snapshot_data.json` — байтовый слепок `docs/data.json`**, тест
   `tests/test_snapshot.py` сравнивает их `assert cur == snap`. Пересоздаётся
   только через `UPDATE_SNAPSHOT=1 python -m pytest tests/test_snapshot.py`
   (тест при этом SKIP с явным текстом — не зелёный «успех»). Pre-commit
   (`pre-commit:128-130`) гоняет `-m "not network and not snapshot_data"`,
   то есть хук это **не поймает** — поймает только полный прогон или CI.
2. **Форматы файлов различаются**: `docs/data.json` — indent=2 **с** переводом
   строки в конце; `tests/snapshot_data.json` — indent=2 **без** перевода
   строки; `data/supplements_slim.json` — без отступа и без перевода строки.
   Скрипт обязан сначала проверить `assert dump(data, indent, nl) == raw`.
3. **`Path.write_text()` на Windows пишет CRLF** (`\n` → `os.linesep`), после
   чего git начинает ругаться `CRLF will be replaced by LF`. Любая запись
   JSON через `write_text` в этом репозитории требует последующей замены
   байтов `b'\r\n' → b'\n'`.
4. `src/config.py:142 OUTCOME` — **не** то же поле; это отдельная таксономия
   исходов, защищена тестом `tests/test_src_config.py:95` («ядро OUTCOME»).

### Арифметика §1

Правило `AUDIT_MASTER` (§1): индекс = **фактическое число строк** таблиц
«Открыто»/«Закрыто» в `audits/*.md`.

- Открыто: seo −4 (убраны MKT-P1-07/08 как дубли, закрыты MKT-P1-03/05),
  data −1 (`DATA-P1-02`) → **83 → 78**
- Закрыто: seo +4, data +1 → **126 → 131**
- Из пяти «движений» только **три** — новое закрытие, два — исправление
  недосчёта, который был в индексе с батча 8A.
- Сходимость §2: `1 + P1 + 49 + 1 + 17` = §1 «Открыто». При P1 = 10 → 78 ✓
- Сумма §1 сохраняется: `78 + 131 = 209 = 83 + 126` ✓

**Расхождение с заданием, о котором стоит знать.** Задание предлагало §1
«Открыто 83 → 81, Закрыто 126 → 128» (= −2/+2, только MKT-P1-03/05), но
одновременно требовало seo «11/14 → 7/18» (= −4/+4, с MKT-P1-07/08). Числа
взаимоисключающи. Проверка «81 + 128 = 209» не различает варианты, потому
что сохранение выполняется в обоих. По правилу §1 верно 78/131. Дополнительно
текущее значение seo по правилу — 11/**16**, а не 11/14.
