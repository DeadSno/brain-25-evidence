## 2. A1 — Bootstrap: измерение подтверждает решение владельца

### 2.1 Где используются bootstrap-классы в разметке проекта

Поиск по всем `docs/*.html` (без `docs/vendor/`):

| Класс | Где | Комментарий |
|---|---|---|
| `card-body` | **1 вхождение**, `graph.html:193` — `<div id="mynetwork" class="card-body">` | единственный класс, реально приходящий от bootstrap |
| `btn` | ~40 вхождений, все страницы | **проектный**: `.btn` полностью переопределён в `style.css` |
| `badge` | `atlas.html:493,494` | **проектный**: 5 правил `.badge` в `style.css` |
| `list-group` | **0** | существует только в вендоренном bootstrap (см. §5 отчёта `VIS_CHART_VENDOR.md`) |

То есть из всего bootstrap разметка использует ровно **один класс** —
`.card-body` на контейнере графа. Всё остальное, что на первый взгляд
выглядит «bootstrap», переопределено проектом.

### 2.2 Сколько раз `.card-body` встречается в вендоренных файлах

| Файл | Вхождений `card-body` |
|---|---:|
| `docs/vendor/bootstrap-5.0.0-beta3.min.css` | **1** |
| `docs/vendor/bootstrap-5.0.0-beta3.min.js` | **0** |
| `docs/style.css` | **0** |
| все `docs/*.html` (кроме vendor) | 2 — из них 1 в комментарии `graph.html:23`, 1 в разметке `graph.html:193` |

Ноль в `style.css` — то есть класс **не отменён проектом** и пришёл из
bootstrap. Единственное вхождение в минифицированном CSS ожидаемо: всё
правило `.card-body{padding:1rem;background-clip:border-box}` склеено в одну
строку без пробелов, поэтому и ровно одно.

### 2.3 Что конкретно даёт bootstrap странице graph.html

Замер: страница как есть vs. вариант без двух тегов подключения. Вариант
собран в копии `docs/` во временном каталоге — удалены ровно два фрагмента
(`<link href="vendor/bootstrap-...css">` и `<script src="vendor/bootstrap-...js">`),
строка за строкой, без regex по содержимому. Контроль: рабочий
`graph.html` в копии побайтово не изменён.

`route.abort()` через эту обёртку Playwright **не работает** — зарегистрированный
обработчик не срабатывает ни разу, включая контрольный шаблон `**/vendor/**`.
Проверено отдельным замером: 0 попаданий при заведомо верном шаблоне. Поэтому
замер сделан на файловых вариантах, а не на перехвате сети.

| Свойство `#mynetwork` | С bootstrap | Без bootstrap |
|---|---|---|
| `padding` (все 4 стороны) | **16px** | **0px** |
| `background-color` | `rgb(34,34,34)` | `rgb(34,34,34)` |
| `border-top` | `1px solid rgb(211,211,211)` | `1px solid rgb(211,211,211)` |
| бокс контейнера | 1112×800 | 1112×800 |
| **canvas** | **1078×766** | **1110×798** |
| `window.bootstrap` | `object` | `undefined` |

**Расхождение с §1 исходного отчёта, и оно важное.** Там записано, что
bootstrap даёт «фон #222 и рамку 1px», и что canvas становится
`1112×800`. Оба утверждения не подтвердились:

- **Фон и рамку задаёт не bootstrap, а сам проект.** В `graph.html:37-44`
  есть локальное правило `#mynetwork { background-color:#222; border:1px solid lightgray; }`.
  Оно и даёт и `#222`, и рамку. Без bootstrap оба значения **те же самые**.
- **Canvas без bootstrap равен 1110×798, а не 1112×800.** Бокс контейнера
  1112×800 — это ширина и высота `#mynetwork`, а не канваса. Канвас на 2 px
  меньше по каждой оси из-за рамки 1px, и без bootstrap он на 32 px шире
  и на 32 px выше из-за снятых отступов.

Вывод владельца при этом **не меняется, но обоснование уточняется**:
bootstrap нужен, потому что `.card-body` даёт **16 px внутренних отступов**,
из-за которых канвас на 32×32 px меньше. Подложка и рамка — заслуга
локального CSS проекта, а не вендора.

### 2.4 Вывод

Bootstrap остаётся вендоренным: он меняет геометрию канваса на 32×32 px,
и без него `graph.html` отдаёт канвас другого размера — это видимый
регресс, а не косметика. Замер воспроизведён независимо; цифры в §1
исходного отчёта уточнены выше.

**Ничего не менялось.** Ни одного байта в `bootstrap-*.min.{css,js}`.

## 3. A2 — `display: contents` на trends

### 3.1 Где объявлено

`docs/style.css:505`:

```css
body.trends-page .site-header { display: contents; }
```

Селектор — класс `trends-page` на `<body>` (`trends.html:206`) плюс
обёртка `.site-header` (`trends.html:209`). Обёртка содержит ровно два
блока: `.trustbar` (плашка «Открытые данные») и `header.top` (шапка).

Второе правило пары — `docs/style.css:517`:

```css
body.trends-page .trustbar { position: sticky; top: 0; z-index: 100; }
```

### 3.2 Что оно делает по факту

`display: contents` убирает у обёртки бокс: она перестаёт быть
`containing block` для sticky-потомков. Оба блока входят в поток `<body>`
напрямую, как до появления обёртки. Само правило ничего не двигает —
оно лишь снимает ограничение, которое сама обёртка создала. Замер:

| | с `display: contents` | без него (`display: block`) |
|---|---|---|
| бокс `.site-header` | **высота 0** | высота **168 px** |
| `position` плашки | `sticky` | `sticky` |
| **плашка, `scrollY=600`** | **top = 0** | **top = −443** |
| шапка, `scrollY=600` | top = −541 | top = −541 |
| `#main`, `scrollY=600` | top = −392 | top = −392 |

Разница ровно та, что описана в комментарии `style.css:475-492`: без
`contents` sticky удерживается обёрткой, которая сама уехала со страницей
(−576 px), и уносит плашку с собой.

### 3.3 Плашка 24 px до прокрутки — подтверждено

`scrollY=0`: `.trustbar` на `top=24`, высота 35. Причина — не `display:
contents`, а `skip-link` высотой 24 px (`trends.html:207`), который стоит
перед плашкой в потоке. Это видно из замера: плашка на 24 px **и с
`display: contents`, и без него** — значение не зависит от правила.

### 3.4 Вывод

Оставляем. `display: contents` — единственное, что возвращает липкой
плашке её прежнее поведение после появления обёртки `.site-header`;
без него плашка уезжает на −443 px вместо 0. Побочный эффект 24 px
до первой прокрутки — это `skip-link`, а не этот гард.

**Ничего не менялось.**

## 4. A3 — `vis-network-9.1.9.min.css`: доказанно мёртв, УДАЛЁН

### 4.1 Подключение

| Путь | Подключён на страницах |
|---|---|
| `docs/vendor/vis-network-9.1.9.min.css` | **`graph.html` — только**, строка 19 |
| `docs/vendor/vis-network-9.1.9.min.js` | `graph.html:20`, `atlas.html:252`, `interactions.html:33` |

`atlas.html` и `interactions.html` рисуют сеть vis-network и **никогда**
не подключали этот CSS. Замер подтвердил: на обеих страницах
`link[rel=stylesheet]` содержит только `style.css`, при этом
`.vis-tooltip` присутствует в `<style>` и JS внедряет **226 707** и
**225 971** символов стилей соответственно. Граф на обеих рисуется
(канвас 1167×658 и 1217×698). То есть две из трёх страниц с vis-network
живут вообще без этого файла — и это не дефект.

### 4.2 Метод замера

`route.abort()` не сработал (см. §2.3), поэтому отключение сделано
файловым вариантом: из копии `graph.html` удалена **одна строка** —
`<link rel="stylesheet" href="vendor/vis-network-9.1.9.min.css" />`.
Никакого `display: none` и никакого подменного `add_style_tag`.

Проверка, что отключение реально сработало, а не «замер врёт», —
обязательна, и она дала неожиданный результат:

```
vendorSheets на варианте без CSS: []   ← <link> действительно убран
styleTagsTotal: 8
styleTagsWithVis: 6
injectedChars: 220120        ← JS внедрил 220 120 символов сам
```

**Причина найдена в исходниках, а не угадана.** `vis-network.min.js`
содержит функцию внедрения:

```js
function _e(g,t){ ... document.createElement("style") ... }
_e(".vis-overlay{bottom:0;left:0;position:absolute;...}");
...
_e("div.vis-tooltip{background-color:#f5f4ed;border:1px solid #808074;...}");
```

Всего **7 вызовов** `_e(...)` с CSS-текстом, суммарно **220 163 символа**
при 220 211 символах вендоренного `.css`. Сверка всех **88 селекторов**
вендоренного CSS со стилями во внедрениях: **0 не найдено**.

Структура файла: 220 211 байт, из них **205 437 (93.3%)** — это
`url("data:image/png;base64,...")` для иконок кнопок навигации. Текст
правил — всего ~15 060 символов. Содержательных правил 88, и все они
есть в JS.

### 4.3 Что сломалось без CSS

Ничего. Замеры:

| Что измерялось | С CSS | Без CSS |
|---|---|---|
| canvas | 1078×766 | 1078×766 |
| контейнер | 1112×800 | 1112×800 |
| **закрашенных пикселей на канвасе** | **366 827** | **366 827** |
| стили тултипа (позиция, фон, рамка, padding, шрифт, nowrap, тень) | как в vis CSS | **те же самые** |
| размер тултипа | 176×54 | 176×54 |
| **`div.vis-navigation` (кнопки зума)** | **отсутствует** | **отсутствует** |
| **`div.vis-manipulation` (панель правки)** | **отсутствует** | **отсутствует** |
| скриншот контейнера, 1280 | 242 365 Б | 242 365 Б — **`Buffer.compare` = 0** |
| скриншот контейнера, 412 (с тултипом) | 68 237 Б | 68 237 Б — **`Buffer.compare` = 0** |
| скриншот страницы, 1280 | 276 443 Б | 276 443 Б — **`Buffer.compare` = 0** |
| скриншот страницы, 412 | 99 979 Б | 99 979 Б — **`Buffer.compare` = 0** |
| **светлая тема** (`html.light`), страница | 331 586 Б | 331 586 Б — **`Buffer.compare` = 0** |
| фон в светлой теме | `rgb(245,245,247)` | `rgb(245,245,247)` |

Ключевое: `div.vis-navigation` и `div.vis-manipulation` **не создаются
ни с CSS, ни без** — то опции графа их не включает. Значит, весь
класс правил, ради которых существует этот файл (панель навигации,
панель правки, color-picker, configuration-модалка, `vis-active`),
на странице не применяется **и так**. Приглушённые подписи, цвета узлов
и позиции рисуются на канвасе библиотекой, CSS на них не влияет.

### 4.4 Решение: файл УДАЛЁН

Удалены `docs/vendor/vis-network-9.1.9.min.css` и его `<link>` в
`docs/graph.html:19`. Обоснование — не «не нашёл, где используется», а
четыре независимых доказательства:

1. **Побайтовая идентичность отрисовки** в четырёх конфигурациях
   (1280/412 × тёмная/светлая), включая состояние с показанным тултипом.
2. **JS доставляет те же стили сам** — 220 120 символов, все 88 селекторов.
3. **Две другие страницы с vis-network** (`atlas`, `interactions`) работают
   без этого файла годами — то есть проект от него не зависил никогда.
4. **Ни одно правило файла не применяется** на `graph.html`: панели
   навигации и правки не создаются, `vis-active` не используется.

Экономия: **220 211 байт**, `docs/vendor/` с 1 349 823 → 1 129 612 байт
(−16.3%).

Файл удалён и `<link>` снят. Контрольный замер уже по **рабочей** странице,

## 8. Красные флаги

1. **§1 исходного отчёта содержит неверные числа по bootstrap.** Записано,
   что bootstrap даёт фон `#222` и рамку, и что canvas без него
   `1112×800`. Фактически фон и рамку даёт локальный CSS проекта
   (`graph.html:37-44`), а canvas без bootstrap = **1110×798**. Вывод
   владельца верен, обоснование стоит поправить в `VIS_CHART_VENDOR.md` §1.
   Рекомендую при следующей правке отчёта — иначе расхождение будет
   выглядеть как ошибка вендоринга.

2. **`route.abort()` не работает в этой Playwright-обёртке.** Зарегистрированный
   обработчик не срабатывает ни разу, включая заведомо верный шаблон
   `**/vendor/**`. Любой будущий замер «без CDN/без CSS», построенный на
   перехвате сети, даст **ложный нулевой результат** и может привести к
   выводу «ресурс не используется». Проверено и обойдено файловыми
   вариантами; если есть тест-обвязка, где перехват работает, стоит
   зафиксировать это в `tests/conftest.py`.

3. **Удаление CSS не покрыто снапшотным гейтом.** См. §7.3. Риск низкий
   (четыре побайтовых совпадения), но непроверенным остаётся.

4. **Вендор на 1.13 МБ живёт в истории Git навсегда.** Это не техническая
   проблема, а решение владельца; отмечено, чтобы не потерялось. SHA-256
   теперь защищает содержимое, но не размер репозитория.

5. **Хеши придётся пересчитывать при любом обновлении библиотеки.** При
   смене версии `vis-network` или `chart.js` гард упадёт — это не ложная
   тревога, а напоминание. Обновлять нужно **и** `EXPECTED`, **и**
   `VIS_CHART_VENDOR.md` §2; гард на обрезке хеша уже падает.

6. **В `docs/vendor/` лежат только используемые файлы.** Проверено: после
   удаления `vis-network.min.css` каждый оставшийся файл подключён хотя бы
   на одной странице. Осиротевших нет.
