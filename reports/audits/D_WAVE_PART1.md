## #47 — инлайн opacity → CSS-переменная (F1, `b393e4a`)

**Суть проблемы.** JS в map.html собирал span-подписи с инлайном
`style="opacity:.6"`. Инлайн-свойство нельзя перебить обычным CSS-правилом,
поэтому в light-теме пришлось ставить `opacity: 1 !important`.

**Что заменено (только map.html):**

| Место | Было | Стало |
|---|---|---|
| map.html JS (подпись категории, бывш. 387) | `<span style="opacity:.6;…">` | `<span style="--inline-opacity:.6;…">` |
| map.html JS («· N механизма», бывш. 391) | то же | то же |
| map.html CSS (бывш. 85-86) | `html.light #chain … { opacity: 1 !important }` | база `#chain … { opacity: var(--inline-opacity, 1) }` + `html.light #chain … { opacity: 1 }` без !important |

Механика: инлайн теперь задаёт только **переменную**, а не саму `opacity`.
Светлая тема перебивает базовое правило обычной специфичностью
(`html.light` добавляет class-level), поэтому `!important` больше не нужен.

**Проверка вживую** (Chromium, `http://localhost:8000/map.html`,
выбралась добавка «Омега-3»):

- тёмная тема: оба span → computed `opacity: 0.6` ✓ (как раньше)
- светлая тема: оба span → computed `opacity: 1` ✓ (как раньше)

Визуально ничего не изменилось — снапшоты не переснимались и не требуются.

**Что НЕ тронуто и почему:**

- `style.css:1390` (`.top .v { opacity:.65 !important }`) — пришёл из bulk-правки
  a69425e, а не из JS-инлайна; он конфликтует с CSS-правилом `style.css:1414`
  (`opacity:.5`), а не с инлайном. Снятие `!important` молча поменяло бы
  opacity бейджа версии на всех страницах (.65 → .5) — это уже не #47, а
  отдельное решение владельца.
- `script.js:522`, `tracker.js:148,210,211,225`, `calculator.html:604-606`,
  `graph.html:445`, инлайны в `map.html:415,599,628,633,656,657,674,676` —
  там нет CSS, который их перебивает через `!important` (никакого
  «принудительного» переопределения), то есть проблема #47 отсутствует.
  Тост-анимации (calculator) и вовсе завязаны на реальную `opacity` —
  переводить их на переменную без CSS-потребителя значило бы сломать fade.

## #40 — формы выпуска на sup-страницах (F3, `a82e070`)

**Шаблон.** `templates/sup.html.j2` — новый блок «Формы выпуска» перед
секцией «Как выбирать»:

```jinja
{% if forms %}    <div class="sup-section">
        <h2>Формы выпуска</h2>
        <p>{{ forms }}</p>
    </div>

{% endif %}    <div class="sup-section">
```

Условие инлайновое (как `{% for %}` в эффектах) — чтобы при отсутствии
данных вывод байт-в-байт совпадал со старым: без пустых строк и без
сдвигов на 123 страницах с `forms: null`.

**Контекст.** `scripts/build_sup.py::build_context` —
`"forms": html_val(rec.get("forms")) if rec.get("forms") else ""`
(пустая строка, а не NO_DATA-заглушка — иначе `{% if forms %}` срабатывал
бы на заглушку и блок рисовался бы на всех 130 страницах).
