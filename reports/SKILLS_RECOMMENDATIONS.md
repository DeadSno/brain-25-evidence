# ЧАСТЬ D — Находки, которые секция не закрывает

## D.1 В 4 скиллах уже есть блок `## Рекомендации`

`ui-ux-deep-audit:196`, `qa-deep-audit:183`, `marketing-deep-audit:158` — все
три с отступом в 4 пробела, то есть **внутри примеров вывода отчёта**.

Расхождение в именовании: новая секция велит выводить блок «Что можно улучшить»,
а примеры показывают `## Рекомендации`. Агент, читающий и то и другое, получит
два разных имени одного блока.

## D.2 В 2 скиллах инструкции прямо противоречат новому правилу ⚠️

Это главное. Новое правило: **агент НЕ оценивает приоритет**.

```
mobile-deep-audit:252   ## Итоговая рекомендация
                        В конце отчёта — раздел "Что критично исправить":
                        - ТОП-5 проблем (по приоритету)
                        - Порядок фиксов
                        - Оценка времени
```

```
project-audit:156       4. Раздел 9. Рекомендации — три уровня приоритета:
                           критично / важно / можно отложить
```

Оба требуют ровно того, чего новая секция запрещает, и оба стоят **позже** по
файлу, чем новая секция, — то есть при буквальном исполнении победит более
поздняя инструкция.

**Что предлагаю** (не применял — правила секции меняет владелец):

| Скилл | Предложение |
|-------|-------------|
| `mobile-deep-audit` | «ТОП-5 (по приоритету)» → «ТОП-5 (по охвату на пользователя)»; «оценка времени» убрать — это уже оценка приоритета |
| `project-audit` | «три уровня приоритета» → «три уровня **сложности**», либо вынести в отдельный блок с явной пометкой «это приоритет, владелец переставляет» |

Либо, если приоритеты всё же нужны, тогда новое правило надо смягчить до
«агент не **назначает приоритет находкам**» — сейчас оно читается как полный
запрет и сталкивается.
