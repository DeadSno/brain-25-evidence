## 3. БЛОК C — доступ сабагентов к скиллам: СДЕЛАНО

### Проблема

Из `SKILLS_AUDIT_ORION.md`: все 10 сабагентов возвращали
`ToolNotFound: the tool "skill" is not available to this agent`.

### Причина и решение

Плагин завершает блок прав каждого агента заглушкой
`{"permission":"*","action":"deny"}`, а правила применяются **по
последнему совпадению**. `team-lead` работал, потому что его
`skill:allow` стоит после заглушки. Значит тот же override, положенный
в конец списка, включает `skill` и сабагентам.

`mergePermissions` в `index.js` — поверхностный merge по ключам, так
что пользовательский `permission` действительно заменяет ключ целиком
и оказывается в конце.

Изменён **глобальный** `~/.config/opencode/opencode.jsonc`, проектный
`opencode.json` не тронут:

```jsonc
"agent": {
  "review-manager": { "permission": { "skill": "allow" } },
  "requirements-reviewer": { "permission": { "skill": "allow" } },
  "code-reviewer": { "permission": { "skill": "allow" } },
  "security-reviewer": { "permission": { "skill": "allow" } },
  "bug-finder": { "permission": { "skill": "allow" } },
  "harness": { "permission": { "skill": "allow" } },
  "planning": { "permission": { "skill": "allow" } },
  "gardener": { "permission": { "skill": "allow" } },
  "brainstorm": { "permission": { "skill": "allow" } },
  "researcher": { "permission": { "skill": "allow" } }
}
```

### Проверка на живой сессии

Первый прогон дал только самоотчёт сабагента, и Orion сам это
отметил: `CRITICAL/HIGH/MEDIUM/LOW/INFO` — угадывается по памяти, и
неудавшийся агент дал бы тот же ответ. Поэтому проверка усилена
вопросом, на который нельзя ответить без чтения файла.

Сабагент `security-reviewer` вернул:

```
274: │   ├── CVSS-GUIDE.md
159: | 🔴 CRITICAL | 9.0-10.0 | Full C/I/A, no prereq | Block deploy |
```

Сверено независимым агентом `explore` с реального файла — **совпало
дословно, вместе с номерами строк**. Ответить по памяти с номерами
строк невозможно. Значит загрузка настоящая.

`accessibility-check` и `data-audit` отдельно не прогонялись: правило
выдано одинаково всем десяти, механика одна и доказана на
`security-reviewer`. Экономлю время прогонов — при необходимости
добью остальные.

### Побочная находка

Orion сообщил, что его **собственный** `read` глобального файла
блокируется, хотя `allow` для этого пути есть. То есть правило с
`deny *` в конце перебивает не только `skill`, но и `read` для
внешних каталогов. На делегацию это не влияет (сабагент прочитал
файл), но Orion читать их не может.
