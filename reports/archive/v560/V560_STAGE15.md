## Часть A — источник точек

### Как искал

Открыл `/sup/paba.html` в Chromium и снял computed styles по всем
элементам, а не смотрел на картинку.

Результат первого прохода:

```json
{
  "badge": {
    "text": "Грейд D",
    "textDecoration": "none",
    "rect": {"top": 295, "left": 116, "w": 98, "h": 38}
  },
  "badgeChildren": [
    {
      "tag": "ABBR",
      "cls": "(none)",
      "title": "Грейд A-D — шкала доказательности (см. glossary.html)",
      "decoration": "underline dotted",
      "line": "underline",
      "style": "dotted"
    }
  ]
}
```

### Что исключено замером

| Гипотеза | Проверка | Результат |
|---|---|---|
| `ul/li/dl` рядом | `querySelectorAll('ul, li, dl, dt')` + `listStyleType` | **0 элементов** |
| псевдоэлементы бейджа | `::before`/`::after` всех элементов | только у `body` (`content:""`, это фон сайта) |
| `border-bottom` | `borderBottomStyle` в зоне бейджа | `none 0px` везде |
| другие dotted | скан всех элементов на `dotted` | **1 совпадение — тот самый ABBR** |

Единственный источник:

| Селектор | Свойство | Значение |
|---|---|---|
| `.grade-badge > abbr` | `text-decoration` | `underline dotted` |

Это умолчание браузера для `<abbr title>`: шкала грейдов расшифровывается
по наведению, и браузер показывает это пунктиром. На белом фоне читается
нормально, на цветном бейдже — как артефакт вёрстки, что и вы и увидели.

### Фикс

```css
.sup-wrap .grade-badge abbr { text-decoration: none; }
```

Одна строка в `style.css` рядом с существующим правилом бейджа.

**Отступление от предложенного в задании фикса.** Вы предлагали убрать
`<abbr>`, оставив голый span. Сделал иначе — подавил подчёркивание
точечно, потому что `<abbr>` и его `title` несут смысл: подсказка
объясняет шкалу A-D и отсылает в `glossary.html`. Убрав обёртку, потеряли
бы объяснение у грейда на всех 130 страницах. Точечность правила важна:
`.sup-wrap .grade-badge abbr` не задевает `abbr` в `glossary.html` и
`methodology.html`, где такое подчёркивание уместно.

Бейдж «Грейд D» на месте, размер не изменился.

Ваши номера строк совпали точно:

| `.inter-critical` | строка 1211 | **строка 1211** | подтверждено |

```css
/* style.css:682 */
.grade.gC { background: #b45309 !important; color: #fff !important; border-color: #b45309 !important; }
/* style.css:1211 */
.inter-critical { border-color: #991b1b; }
```

### Где я ошибся и почему

Искал регулярками **HTML-образной формы** — с кавычкой после класса:

```
\.inter-(high|medium|low|critical)"[^>]*>
```

Такая регулярка физически не может совпасть с CSS-правилом, где после
класса идёт `{`, а не кавычка. По `.grade.gC` искал только инлайн-стили
в HTML и `.grade-badge` в CSS — обе формы есть на sup-страницах, обе
пропускают `.grade.gX`. Правило существовало, но мои запросы к нему не
обращались. Это была ошибка поиска, а не отсутствие данных.

В отчёте прошлого этапа я написал «цвета нет ни на одной странице сайта,
ни в style.css» — утверждение было неверным.

### Что это меняет для этапа 2

Полная палитра `style.css` для грейдов:

| Грейд | `.grade.gX` | Записей в data.json |
|---|---|---|
| A | `#15803d` | 8 |
| B | `#4d7c0f` | 45 |
| C | **`#b45309`** | 52 |
| D | `#b91c1c` | 25 |

И вся шкала взаимодействий:

| Уровень | Правило | Записей |
|---|---|---|
| low | `.inter-low` | 92 |
| medium | `.inter-medium` | 74 |
| high | `.inter-high` | 24 |
| critical | **`.inter-critical`** | 9 |

Моё предположение из прошлого отчёта — взять `#f59e0b` по аналогии с
`.s-weak` — было лишним: цвет C уже есть в проекте, причём он же
используется в `.verdict.v0` (`#b45309`), то есть это канонический
«жёлтый» сайта.

### Одна оговорка, не блокер

`.grade.gX` — это бейдж в общем оформлении, а страницы sup используют
другой: `.grade-badge` с цветом инлайном, `.sup-wrap .grade-badge`
в `style.css:1193`. Палитры различаются:

| Грейд | sup (инлайн) | `.grade.gX` (style.css) |
|---|---|---|
| A | `#22c55e` | `#15803d` |
| B | `#84cc16` | `#4d7c0f` |
| C | — | `#b45309` |
| D | `#ef4444` | `#b91c1c` |

Причина расхождения, судя по комментарию на `style.css:413`, —
`!important` в `.grade.gX` перебивал `sup` и давал контраст 0,2-0,3
против белого текста. Инлайн-цвета в sup подобраны так, чтобы белый текст
на них читался.

Поэтому для генератора есть два рабочих варианта, и это решение владельца:

- **взять `#b45309` из `.grade.gC`** — палитра проекта, но на бейдже с
  белым текстом даёт контраст, который сам проект уже признал плохим;
- **взять `#f1c40f`** — как в `.grade-C` на `calculator.html` (строка
  76), но там это цвет текста на светлой подложке, а не заливка.

Ни один не угадываю. Для `.inter-critical` правило есть и сработает без
правок — класс подставляется генератором напрямую.

### Побочный эффект: упавший тест

После правки `sw.js` тест
`test_silent_handlers.py::test_unprotected_chains_match_reviewed_list`
упал:

```
sw.js:177: self.clients.matchAll().then(function (clients) {...})
sw.js:350: caches.keys().then(function (keys) {...})
```

Причина — не регрессия. Тест ключует перечень беззащитных цепочек
**номером строки**, а моя запись `v79` в шапку `sw.js` сдвинула файл на
13 строк: было 164 и 337, стало 177 и 350. Обновил номера в
`ACCEPTED_UNPROTECTED`, сохранив прежние причины, и добавил пояснение
о сдвиге. Сами цепочки не менялись — это тот же `notifyOffline` и то же
очистка кэшей в `activate`.

Стоит отметить: такой ключ по номеру строки хрупкий — любая правка
`sw.js` роняет тест. Не трогал, это отдельный вопрос.
