## 2. Правка #1 — `:hover`

### 2.1 Что сделано

- **Обёрнуто: 25** — 24 критичных + `.card:hover` (решение владельца: подъём
  карточки на 4px на тач-экране держится после тапа и считается критичным).
- **Не тронуто: 11 косметических** — только `opacity` / `transform` /
  `box-shadow` / `text-decoration`. Их залипание не меняет заливку, рамку и
  раскладку, а `opacity` не мешает следующему тапу.
- **Обёртка на месте.** Каждое правило осталось на своей строке внутри
  `@media (hover:hover){…}` — ни один блок не перенесён в конец файла.

Формат однострочных правил сохранён, многострочные сдвинуты на 2 пробела:

```css
@media (hover:hover){.preset:hover{border-color:var(--accent)}}

@media (hover:hover){
  .tagChip:hover {
    background: rgba(127,127,127,.3);
    opacity: 1;
  }
}
```

Перед первым правилом (строка 221) добавлен комментарий на 8 строк с
объяснением: почему обёртка точечная, почему косметические оставлены и почему
собирать в один блок нельзя.

### 2.2 Почему «на месте», а не в общем блоке

`@media` не меняет ни специфичность, ни порядок каскада, пока стоит на месте
правила. Перенос в конец файла сдвинул бы `.btn:hover` относительно блока
`.btn.c-*` — а это ровно тот порядок, который специально оговорен комментарием
на строках 1548-1552:

> *«Стоит ПОСЛЕ блока `.btn.c-*`: у `.btn:hover` и `.btn.c-home` одинаковая
> специфичность (0,2,0), и без этого порядка `.btn.c-home` перебивал бы
> наведение.»*

## 4. Touch — залипания нет

Контекст Playwright: `viewport 375×812`, `hasTouch: true`, `isMobile: true`.
Проверено, что среда действительно сенсорная, иначе тест ничего бы не значил:

```
hover: hover  → false
hover: none   → true
pointer: coarse→ true
navigator.maxTouchPoints → 1
загруженных правил @media (hover:…) → 25
```

Cookie-баннер закрыт перед замерами, переходы по ссылкам заблокированы
(`preventDefault` в capture), чтобы тап не уводил со страницы и не ломал
сравнение «тот же элемент до и после».

| Элемент | `:hover` после тапа | Критичное свойство до | после | Залип? |
|---|---|---|---|---|
| `.card` | **залип = true** | `transform: none` | `transform: none` | ✅ нет |
| `.btn.c-feedback` | **залип = true** | `background: rgba(132,204,22,.12)`, рамка `rgb(132,204,22)` | без изменений | ✅ нет |
| `.btn` (переключатель темы) | **залип = true** | `background: rgb(44,44,46)` | `rgb(255,255,255)` — это **переключение темы**, не hover | ✅ нет |
| `.tagChip` | залип = false | `background: color(srgb .082 .502 .239 / .14)` | без изменений | ✅ нет |
| `.manual-badge` | залип = false | `rgb(209,209,214)` / `rgb(28,28,30)` | без изменений | ✅ нет |
| `.preset` | залип = false | `rgb(209, 209, 214)` | без изменений | ✅ нет |

**Это и есть суть правки.** Псевдокласс `:hover` на тач-устройстве
залипает — он продолжает матчиться после тапа (столбцы «залип = true»).
Но критичные свойства внутри `@media (hover:hover)` больше не применяются:
ни подъём карточки, ни заливка кнопки, ни рамка не «застревают».

Показателен `.btn` без класса `c-*`: после тапа фон равен `--card-bg`
(`#fff` в светлой теме), а не `--border` (`#d1d1d6`). Если бы обёртки не было,
фон стал бы `var(--border)`.

  `RUN_SNAPSHOTS` **не задаётся**.
- `tests/conftest.py:57` при отсутствии `RUN_SNAPSHOTS` вырезает все тесты
  с ключевым словом `snapshots`.
- Шага `playwright install` в workflow **нет** — браузеры в CI не ставятся.

Значит «CI зелёный» не означает «снапшоты совпадают». Оно означает «снапшоты
не выполнялись». Утверждение «в CI снапшоты проходят» неверно.

### 10.3 Движок совпадает с тем, на котором сняты эталоны

В `%LOCALAPPDATA%\ms-playwright` лежат `chromium-1234, -1243, -1247`,
`webkit-2336, -2359` и др. Playwright 1.63.0 ожидает **chromium-1243 и
webkit-2359** (`playwright install --dry-run`: Chrome for Testing
153.0.8010.12, WebKit 26.6). Нужные сборки на месте; лишние (1234, 1247,
2336) — от других версий Playwright, на прогон не влияют. Дрейфа движка нет.

### 10.4 Реальная причина — рассинхрон «страница изменилась, эталон не переснят»

Разбор 52 падений по типу:

| Вьюпорт | SIZE (высота страницы) | DIFF (пиксели) |
|---|---|---|
| 412 | **31** | 2 |
| 1280 | 0 | 17 |

**Все 31 размерное падение — только на 412px, ни одного на 1280.** Это не
«размытие», а другая высота страницы: дельты +1…+46px (interactions +16,
calculator +22, sup-* +45…+46). Единственная причина, способная изменить
высоту на 412 и не тронуть 1280 — правило в мобильном `@media`.

Решающий эксперимент: подставлена версия `docs/style.css` **до 1A-1**
(`git show d8253bb~1:docs/style.css`, 116046 байт против текущих 119606).

```
после 1A-1 и 1A-2:  27 failed   [-k chromium]
до 1A-1 (baseline): 18 failed   [-k chromium]
```

Итого **этап 1A-1 добавил 9 падений** — все SIZE, все на 412. Это ровно
`.actions > * { flex-shrink: 0; white-space: nowrap; }` из `d8253bb`:
запрет переноса в шапке поднял её высоту на узком экране. Легальное
изменение вёрстки, а не регресс.

Оставшиеся **18 падений — DIFF, ни одного SIZE**, и они независимы от 1A-1:
cookie-баннер 2.235% и «серый» шум 0.05…2.4% на interactions, methodology,
calculator, faq, trends, sup/*. Причина установлена прямо:

```
git log c3a4dda..HEAD -- tests/snapshots   →  0 коммитов
git diff --stat c3a4dda..HEAD -- docs/     →  149 файлов, +734/−467
```

Эталоны последний раз пересняты в `c3a4dda` (08.10). После этого `docs/`
менялся 149 файлов, а эталоны — ни разу. В частности `89978b1`
(восстановление drag/pan графика, `docs/interactions.html`) и `b92dade`
(FA2 continuous physics) объясняют просадку `interactions` на 2.4%.

### 10.5 Итог

| Утверждение | Факт |
|---|---|
| «локальный Playwright новее, чем в CI» | версия одна и та же, `1.63.0` |
| «в CI снапшоты совпадают» | в CI снапшоты не запускаются вовсе |
| «дрейф движка относительно эталонов» | движок совпадает; причина — 9 падений от 1A-1 + 18 от изменений `docs/` после `c3a4dda` без пересъёма |
| «CI зелёный ⇒ проблема не в снапшотах» | CI зелёный, потому что снапшоты там не исполняются |

**Практический вывод.** Ничего чинить не нужно — это не баг сборки, а
технический долг по эталонам. Правильное действие — переснять эталоны
**один раз, осознанно, на версии `c3a4dda`+все последующие коммиты `docs/`**,
и зафиксировать это решение владельцем. Слепой пересъём зафиксирует в
репозитории нежелательную вёрстку, а «не запускать снапшоты локально»
узаконит слепое пятно.
