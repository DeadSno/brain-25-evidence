## 2. Смысловые утверждения: что нашёл, что спорно

Ниже — расхождения между формулировками README и данными. По условию
задания **ничего не правил**, только зафиксировал.

### 2.1 Версия релиза в README противоречит CHANGELOG и version.json

README, 334:

> **v5.6.0** — стабильный релиз (в дереве есть незаписанный шаг v5.6.1, см. CHANGELOG)

Факты:

- `CHANGELOG.md:5` — `## [v5.6.1] - 2026-10-06`. Шаг **записан**.
- `docs/version.json` — `{"app": "5.6.1", ...}`. Версия в данных — **5.6.1**.

То есть утверждение «незаписанный шаг v5.6.1» неверно в обе стороны:
шаг записан, и именно 5.6.1 стоит в данных. Похоже, строка писалась под
состояние до `df2f2f2`.

**Не правил** — это утверждение о статусе релиза, а не измеримая цифра.
Нужно решение владельца: какая формулировка считается верной.

### 2.2 `src/parsers.py` в README не существует

README, 252 перечисляет три модуля в `src/`:

```
│   ├── config.py                  # 130 добавок: запросы, нормы
│   ├── content.py                 # категории, эффекты, протоколы, механизмы
│   └── parsers.py                 # PubMed, OpenAlex, Wiki, ClinicalTrials
```

Замер: в `src/` лежат `config.py`, `content.py`, `ct_terms.py`,
`wiki_map.py`, `__init__.py`. **`parsers.py` отсутствует.** Заодно не
упомянуты `ct_terms.py` и `wiki_map.py`.

Комментарий к строке «PubMed, OpenAlex, Wiki, ClinicalTrials» по факту
распределён по `scripts/` (`fetch_papers.py`, `fetch_evidence.py`,
`wiki_map.py` в `src/`, `enrich_trials.py`) и по корню `app.py`.

**Не правил** — это описание структуры, а не цифра. Нужно знать, куда
ушли парсеры: переименовать строку, переписать список `src/`, или
восстановить файл.
