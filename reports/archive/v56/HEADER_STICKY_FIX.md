## 1. Что было в CSS до правки

### `.trustbar` — style.css:417

```css
.trustbar{position:sticky;top:0;z-index:100;background:var(--card-bg);
  color:var(--text);border-bottom:1px solid var(--border);
  text-align:center;font-size:.8rem;font-weight:600;
  padding:.45rem var(--space-2);letter-spacing:.02em}
```

### `header, .header` — style.css:298

```css
header, .header {
  position: sticky; top: 0; z-index: 50;
  backdrop-filter: blur(12px); -webkit-backdrop-filter: blur(12px);
  background: rgba(255,255,255,.65);
  padding-top: env(safe-area-inset-top, 0px);
}
```

### `.top` — style.css:991

```css
.top {
  display: flex; justify-content: space-between;
  align-items: center; gap: var(--space-4);
  flex-wrap: wrap; margin: 0 0 var(--space-4);
}
```

**Ключевое: `position: sticky` у `.top` не был объявлен нигде.** Липкость
приходила из правила `header, .header` — селектора тега. Замер показал:
в проекте **142 элемента `<header>`, и все 142 имеют `class="top"`**,
других нет. То есть правило со селектором тега работало как «липкая
шапка», объявленная в другом месте, — неявный контракт вместо прямого.

### Конфликт

Оба блока липнут к `top: 0`: плашка с `z-index: 100` перекрывает шапку
с `z-index: 50`. При прокрутке логотип в шапке уходил под плашку.

### Про `trends.html`

Единственная страница с `position: static` — из-за локального
`position: static !important` в её `<style>`. Перекрытия у неё не было
и раньше, то есть расхождение из `HEADER_UNIFY.md` («10 кнопок против 9»
у map и trends) к этому дефекту отношения не имело.

## 2. Что изменено в CSS

Три добавления, ни одного удаления кроме `position` из `.trustbar`.

```css
.site-header { position: sticky; top: 0; z-index: 100; }
.site-header .trustbar,
.site-header .top { position: static; }

.trustbar{background:var(--card-bg);color:var(--text);   /* sticky убран */
  border-bottom:1px solid var(--border);text-align:center;font-size:.8rem;
  font-weight:600;padding:.45rem var(--space-2);letter-spacing:.02em}
```

Правило `header, .header` **сохранено** — как и просили в A2. Селектор
тега попал бы в любой будущий `<header>`, и его удаление сломало бы
страницы, где липкость ещё понадобится. Вместо удаления добавлен
комментарий, объясняющий, что для `.top` внутри обёртки это правило
перебито: специфичность `.site-header .top` — 0,2,0 против 0,1,0 у
`header`. Замер после правки: `position` у `.top` — `static` во всех
50 комбинациях.

Оба места снабжены комментами с замером и указанием строк, чтобы правку
не откатили как «лишнюю».

**Имя `.site-header` проверено на конфликт:** `.sup-header` уже занят —
это шапка карточки внутри `main` (`style.css:1209`, 3 вхождения). Имена
разные и похожие; смешивать их в этой правке нельзя, поэтому
`.sup-header` не тронут.

### Эталон `modal-index` разошёлся — и это ожидаемо

| Движок | Расхождение | Порог |
|---|---:|:---:|
| chromium | 2.921% | 0.05% |
| webkit | 2.642% | 0.05% |

**Правку снимков не делал** — 2.9% это в 58 раз больше прежних 0.05%,
и «съехало из-за обёртки» здесь не является достаточным объяснением,
пока не доказано, что вёрстка цела.

Доказано измерением. Сценарий теста повторён на версии из `HEAD` и на
текущей:

| Метрика `index@1280` | До | После | Дельта |
|---|---:|---:|---:|
| `scrollY` после прокрутки к карточке | 1974 | 1974 | **+0** |
| Высота `.top` | 44 | 44 | **+0** |
| Высота плашки | 35 | 35 | +0 |
| Первая карточка (top) | 295 | 295 | **+0** |
| `#cardsGrid` (top / left) | 295 / 64 | 295 / 64 | **+0** |
| Шапка на экране (top) | 0 | 35 | **+35** |
| Плашка на экране (top) | 0 | 0 | +0 |

`scrollY` совпадает — значит снимки сравнивают один и тот же участок
страницы. Контент не сдвинулся ни на пиксель: карточка на 295 в обоих
случаях. Единственное изменение — шапка теперь стоит под плашкой
(top 35 вместо 0), то есть логотип виден вместо перекрытого.

Дополнительно исключены альтернативные причины:

- **Откат только CSS** (разметка с обёрткой) → расхождение **3.750%**,
  хуже, чем с полной правкой.
- **Откат только разметки** (CSS с обёрткой) → расхождение **3.467%**,
  тоже хуже.
- **Полный откат `docs/`** → тест проходит (2 passed).

То есть расхождение вызвано правкой, а не её частичной откаткой, и
полная правка даёт **наименьшее** расхождение из трёх вариантов.
Разбивка по вертикали: 33 776 пикселей в первых 100px (полоса шапки) и
7 015 ниже — на `diff.png` красным отмечена именно верхняя полоса.

**Вывод:** эталон `modal-index` описывает старое поведение, где логотип
перекрыт плашкой. Правка это поведение изменила — намеренно. Эталон
следит за рендером, а не за дефектом, поэтому пересъёмка здесь
означала бы закрепление правильного состояния.

**Решение за владельцем:** переснимать `modal-index` (только его, в двух
движках) или оставить красным до следующей плановой пересъёмки. Сам не
переснимал: в прошлый раз я обосновал отказ от пересъёмки на 0.0013%,
а здесь 2.9% — другой масштаб, и решение одно на все 130 страниц.

## Осталось за владельцем

1. **Переснимать ли `modal-index`** в двух движках. Расхождение
   локализовано в полосе шапки, вёрстка не сдвинулась — но это решение
   одно на 130 страниц, и оно ваше.
2. **Локальные `<style>` с `.top`** на 7 страницах (`index`, `map`,
   `atlas`, `calculator`, `interactions`, `feedback`, `trends`) — из
   `HEADER_UNIFY.md` не сделано. Теперь, когда липкость вынесена в
   обёртку, дословные копии правил из `style.css` стали ещё на одну
   сущность лишними. У `atlas` отдельно `body.fs .top { display: none }`
   — это полноэкранный режим, а не копия, его нельзя удалять.
3. **Bump кэша.** Изменился `style.css`, он входит в `STATIC_ASSETS` и
   отдаётся через SW с `cacheFirstForStatic`. По процедуре из `sw.js`
   нужны `?v=413 → 414` в 17 страницах и `CACHE_VERSION v79 → v80`.
   Не делал: в задании этого не было, а без обоих бампов фикс не дойдёт
   до пользователей.
