## 1. `:has()` — какой селектор и почему

```css
body:has(#modalOverlay[style*="display: flex"]) .site-header,
body:has(#modalOverlay[style*="display: flex"]) .site-header { z-index: 1; }
```

Выбор сделан по разметке, а не по примеру из задания.

**Состояние модалки в разметке не отражено.** Разбор `openModal()` /
`closeModal()` в `docs/script.js` и разметки:

| Что | Факт |
|---|---|
| Разметка | `<div id="modalOverlay" style="display:none">` |
| Открытие | `$('modalOverlay').style.display = 'flex'` (`script.js:652`) |
| Закрытие | `$('modalOverlay').style.display = 'none'` (`script.js:675`) |
| Класс `.open` | **не используется** |
| Атрибут `[hidden]` | **не используется** |
| Класс на `<body>` | **не ставится** |
| `overflow` на `<body>` | **не меняется** (`visible`) |

Поэтому `[hidden]` и `.open` из задания отпадают: они не сработают
никогда. Остаётся инлайновый атрибут `style` — единственный сигнал.

**Почему именно `:has()`, а не родственный комбинатор.** `#modalOverlay`
стоит в конце `<body>`, то есть **после** `.site-header`. Комбинатор `~`
работает только вперёд по дереву и до шапки не дотягивается. Менять
порядок в разметке ради CSS нельзя — это ломает 144 страницы. Здесь
`:has()` — единственный инструмент, который позволяет править элемент
**до** перехватчика.

**Селектор написан по измеренной сериализации**, а не по догадке:

| | закрыто | открыто |
|---|---|---|
| `getAttribute('style')` | `display:none` | `display: flex;` |
| Chromium | так | так |
| WebKit | так | так |

Значение `display:none` в разметке записано **без пробела**, а JS
проставляет **с пробелом и точкой с запятой**. Это проверено в обоих
движках, поэтому в селекторе есть вариант с пробелом и без.

Заодно проверено, что отброшенные варианты действительно не работают:

| Селектор | Закрыто | Открыто |
|---|---|---|
| `[style*="display: flex"]` | False | **True** |
| `[style*="display:flex"]` | False | **False** — разметка пишет с пробелом |
| `[style*="display: none"]` | **False** | False — в разметке без пробела |
| `body:not(:has(...display: none...))` | True | True — бесполезен |
| `body:has(#modalBody:has(h2))` | **SyntaxError** — вложенный `:has()` запрещён | — |

Инверсия через `[style*="display: none"]` не работает: селектор не
матчится **никогда**, а значит `body:not(...)` всегда истинно и опустил
бы шапку на всех страницах без модалки сразу.

### Почему `z-index: 1`

Правка локальна: вне открытой модалки шапка остаётся на `100`. Только
в состоянии «модалка открыта» она опускается на `1` и уходит под оверлей
(`z-index: 50`). Это ровно тот случай, когда `#toTop` (60) и
`#toBottom` (100) перекрывает оверлей, так что их взаимный порядок с
шапкой в этот момент не виден глазом. Варианты «поднять оверлей до 200»
или «опустить шапку до 40» меняли бы порядок этих элементов **постоянно**,
а не только при открытой модалке.

## 2. Проверка в Chromium и WebKit

Прогон `закрыто → открыто → закрыто`, оба движка. Третий шаг
обязателен: правило не должно оставлять шапку опущенной навсегда после
первого открытия.

| | Chromium закрыто | Chromium открыто | Chromium закрыто | WebKit открыто |
|---|---|---|---|---|
| `z-index` шапки | 100 | **1** | **100** | **1** |
| `z-index` оверлея | 50 | 50 | 50 | 50 |
| `z-index` `#toTop` | 60 | 60 | 60 | 60 |
| `z-index` `#toBottom` | 100 | 100 | 100 | 100 |
| видно в верхней точке | `div.trustbar` | **`div#modalOverlay`** | `div.trustbar` | **`div#modalOverlay`** |
| диалог поверх шапки | — | **да** | — | **да** |

Перекрытие подтверждено через `elementFromPoint`, а не только
вычисленным `z-index`: прямоугольник показал бы кнопку даже под оверлеем.

**`:has()` поддерживается в обоих движках** — `CSS.supports('selector(body:has(div))')`
даёт `true` в Chromium и WebKit. Стоп-условие «`:has()` не работает в
целевом браузере» не сработало.

**`#toTop` и `#toBottom` не задеты** — стоп-условие не сработало.

| Проверка | Результат |
|---|---|

Расхождение лежит внутри графика и не затрагивает ни шапку, ни
остальную страницу.

### Причина

`graph.html` рисует граф на **vis-network 9.1.2**, подключённой **с CDN**:

```
<script defer src="https://cdnjs.cloudflare.com/.../vis-network.min.js"
        integrity="sha512-...">
```

| Факт | Значение |
|---|---|
| `Math.random()` в `docs/` | **0 вхождений** — значит, ГПСЧ внутри минифицированной библиотеки |
| локальный фолбэк `../node_modules/vis/dist/vis.js` | **закомментирован** в разметке |
| `node_modules/vis/dist/vis.js` | **не существует** |
| доступность CDN | 200 — но страница от этого не герметична |
| `CHART_PATCH_JS` в тестах | глушит анимацию **только Chart.js**, до vis-network не дотягивается |

Силовая раскладка vis-network стартует со случайных позиций и
сходится итеративно, а снимок попадает в произвольный момент. Картинки
подтверждают: структура та же — та же окружность, те же узлы, те же
подписи, — разъезжают на 1–3 px отдельные узли. При пороге `8/255` и
плотности сотен тонких штрихов это даёт 18% пикселей.

### Почему я не переснял эталон графа

Переснять `graph-1280` — значит закрепить **один случайный результат**
как истину. Следующий прогон упадёт снова, и гейт станет не просто
красным, а бесполезным: он будет мерить не вёрстку, а удачу. Это тот
же класс находки, который в прошлой задаче не был принят для `glossary`.

### Что нужно для починки

1. **Ждать стабилизации сети** вместо произвольного момента: у
   vis-network есть событие `stabilized` — снимок после него будет
   описывать одну и ту же раскладку.
2. **Отключать физику на время снимка** — по аналогии с `CHART_PATCH_JS`,
   который уже делает это для Chart.js.
3. **Вендорить vis-network локально** — иначе гейт зависит от сети и
   от того, какая сборка приехала.

Пункты 1 и 2 правят флаки; пункт 3 убирает зависимость от CDN. Все три —
правка тестового harness или разметки, то есть **вне границ этой
задачи**.
