### Добавлено

Три блока из задания, плюс два правила, которые реально помешали.

**`## Multi-agent mode`** (6 правил)
- **read-only может снять состояние до конца write-задачи.** Написано
  именно так, потому что иначе это нарушают по незнанию: «read-only снимает
  состояние ПОСЛЕ write; вывод формулируется с привязкой к коммиту, а не
  как утверждение о релизе». Приведён случай agent-4 vs agent-2
  (`sup/index.html`) и сказано, что дефект ушёл в чужой отчёт как правда.
- Один файл — один владелец, с указанием, почему: две правки одного файла
  не дают merge-конфликт, последняя молча побеждает, `git status` чист.
- Каждый агент пишет свой отчёт и перечисляет свои пути — не брать чужие
  из `git status`.
- Отчёты не источник правды для чисел: пример «81 против 130».
- Говорить, что не проверил.

**`## Parallelism`** (3 правила)
- **Порт `:8000` закреплён за одним агентом.** Сформулировано через
  последствие, а не как запрет: «снапшоты скипаются молча при недоступном
  сервере: тесты становятся skipped, код выхода зелёный, прогон вхолостую —
  поэтому порт закреплён за одним агентом, остальные гоняют `pytest -q`».
  Указано и измеренное прошлое: тихо скинулось 74 теста и это выглядело
  как успех.
- Гейт всех остальных — `pytest -q`; нужен `RUN_SNAPSHOTS=1` — сказать в
  отчёте и отдать порт владельцу.
- Перед тем как взять порт, проверить `Invoke-RestMethod
  http://localhost:8000/version.json`: отвечает — порт не твой.

### Как исправил и почему именно так

**Правка ссылки, а не заголовка:** строку 181 сделал
`## Данные (сентябрь 2026) {#данные}`.

Обоснование:
1. **Цель ссылки должна быть устойчива, а не её текст.** Оглавление
   (`[Данные](#данные)`) переживёт переименование заголовка; привязка к
   автославу — нет. Следующая правка даты («октябрь 2026») снова разорвёт
   якорь, и ровно это уже произошло один раз.
2. **Заголовок несёт дату намеренно** — это содержательная часть («данные
   на сентябрь»), выбрасывать её ради слага значило бы ухудшать текст.
3. Явный `{#id}` на GitHub **заменяет** автослаг, а не добавляется вторым,
   поэтому дубля заголовков не возникает.

Проверено, что решение безопасно: строка `#данные-сентябрь-2026` не
встречается ни одной ссылкой во всём репозитории (только в тексте двух
отчётов как описание проблемы). После правки скрипт даёт **0 битых якорей**,
а сам скрипт научен понимать `{#id}` — иначе он проверял бы несуществующий
слаг и рапортовал бы о проблеме, которой нет.

## 6. Три шаблона: решение — **заполнить, не удалять**

Задание предлагало удаление и аргумент «пустой файл в ряду заполненных
создаёт ложное впечатление проверенности». **Проверка этого аргумента его

### Что показала проверка

| Проверка | Результат |
|----------|-----------|
| ровно 3 файла < 1 КБ с `_TBD_` | подтверждено: `PABA.md` 380 Б, `Пролин.md` 388 Б, `Серин.md` 386 Б |
| остальные 33 файла с `_TBD_` крупные | подтверждено: 2 602–8 513 Б, по 12 вхождений `_TBD_` каждый, **не тронуты** |
| **это единственные 3 файла из 117 без единого PMID** | подтверждено: `re.search(r"\b\d{7,8}\b")` — 114 с PMID, 3 без |
| **«лежит рядом с заполненной карточкой того же вещества»** | **ЛОЖЬ**: заполненной карточки того же вещества рядом нет. Ближайшая заполненная — `Фосфатидилсерин.md` (4 682 Б), а это **другое вещество** (фосфатидилсерин ≠ серин). У PABA и Пролина таких нет вообще |
| **«проверки не было»** | **ЛОЖЬ, и это переворачивает решение.** Проверка была: `reports/q14_batch_17c_proposal.json` содержит полные вердикты по всем трём (PABA `D`/`не подтверждено`, Пролин `D`/`не подтверждено`, Серин `C`/`зависит от контекста`) с 7 полями и PMIDs, и эти данные **уже применены** в `docs/data.json` — PMIDs совпадают до штуки |
| **«на эти 3 файла никто не ссылается»** | **ЛОЖЬ**: `docs/briefs/q14_batch_17c.md`, строки 55–57, раздел «Что читать» перечисляет `reports/evidence/PABA.md`, `Пролин.md`, `Серин.md`. В скриптах упоминаний нет (проверено отдельно по `*.py`, `*.js`, `*.json`, `*.yml`) |
| тесты зависят от этих файлов | нет: `git grep evidence tests/` — совпадений по этим путям нет |

Итог: ситуация обратная заявленной. Не «непроверенное вещество с пустым
файлом», а **проверенное вещество, у которого не записали артефакт
проверки**. Пустой файл тут не врёт о substance — он врёт о самой себе,
и это вдобавок ломает рабочую ссылку в брифе.

### Решение и как сделано

Удаление отклонено по трём причинам: оно разорвало бы три ссылки в
`docs/briefs/q14_batch_17c.md` (файл не мой, исправить не могу); стёрло бы
след проверки, которая реально была; и «ложное впечатление проверенности»
здесь не возникает по построению.

Заполнено — **только проверенными данными, ничего не выдумано:**

| Источник данных в файле | Откуда |
|-------------------------|--------|
| шапка `grade` / `verdict` / `scienceIndex` / `metaCount` / число `key_sources` | `docs/data.json` (уже применённый результат проверки) |
| 7 полей карточки (`about` … `how_to_choose`) | `docs/data.json`, те же значения |
| abstracts | **реальный `efetch` PubMed** по PMIDs из `key_sources`, тем же кодом, что `scripts/fetch_evidence_abstracts.py` |

Формат снят с `reports/evidence/Фосфатидилсерин.md` — заполненной карточки
того же батча 17c, а не придуман: шапка в `**grade:**` виде, поля в
`_текст_`, abstracts как `### PMID [x](url)`.

Забрано **2 abstracts из 2** по каждому файлу, HTTP 200, ни одного
`_TBD_` не осталось:

| Файл | Было | Стало | PMIDs |
|------|------|-------|-------|
| `reports/evidence/PABA.md` | 380 Б | 5 225 Б | 8151563, 8176012 |
| `reports/evidence/Пролин.md` | 388 Б | 6 883 Б | 39086044, 39259166 |
| `reports/evidence/Серин.md` | 386 Б | 5 847 Б | 30626650, 41265180 |

Проверено скриптом на гардах проекта: **UTF-8 без BOM, 0 символов
U+FFFD, переводы строк как у соседей по каталогу** (весь `reports/evidence/`
хранится в CRLF — 117 из 117 файлов, я не стал ломать соглашение каталога).

### Важно для коммита 3: `git rm` был невозможен в принципе

**`reports/evidence/` находится в `.gitignore` (строка 194), и в git не
отслеживается ни один из 117 файлов** (`git ls-files reports/evidence/` → 0).

- `git rm` на этих файлах неприменим — они не в индексе;
- добавить их в коммит 3 тоже нельзя, `.gitignore` их отфильтрует;

Так как они вне git, выбор «удалить или заполнить» не имеет последствий для
истории — он сделан по существу, по содержанию файлов.
