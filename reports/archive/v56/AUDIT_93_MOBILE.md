## 5. Часть D — safe-area

### env() правила работают и являются несущей конструкцией

Контрольный эксперимент (режим `control`, инсеты = 0) против эмулированного режима на iPhone 14 Pro Max:

| | control (без env) | emulated (с env) |
|---|---|---|
| Пропавших под вырез текстов на index | **3** (trustbar, ссылка-логотип, `span.h1-emoji`) | **0** |
| `trustbar` padding-top | 7.2 px | **59 px** |
| Текст trustbar, `top` | 17 / 26 / 23 | **69 / 85 / 78 / 75 / 75** |
| `.site-footer` padding-bottom | 16 px | **34 px** |

То есть 12 вхождений `env(safe-area-inset-*)` в `style.css` (строки 235, 241, 384, 390, 397, 817, 818, 1637, 1638, 1677, 1678) реально держат контент под Dynamic Island и над home indicator. **Это не риск, это работающая конструкция.**

### Две дыры

| Находка | Severity | Деталь |
|---|---|---|
| **D-1** `.skip-link:focus` под вырезом | **P1** | `style.css:1500-1501` — нет `padding-top: env(...)`. При фокусе рендерится в `top: 2`, текст «Перейти к содержимому» перекрыт на **57 px** (14 Pro Max) и **18 px** (SE). Воспроизведено во **всех 20 прогонах**. Фикс проверен инъекцией (`padT: 59px` → перекрытие исчезает), но не применён — read-only |
| **D-2** `#toTop` наезжает на home indicator | **P1** | `style.css:432` — `bottom: 1.2rem` без `env()`. Измерено `bottom: 913` при `homeTop: 898` → **перекрытие 15 px**, `clear: false`. Только `index.html`, все iPhone с home bar |

Плюс P2: **D-3** — ни одного правила с `env(safe-area-inset-left/right)` во всём `style.css`, в landscape вырез уходит на бок; **D-4** — `.toBottom` (`bottom: 5rem`) чист случайно (зазор 46 px при 34-пиксельном баре), правила нет.

**Дисклеймер не перекрыт ни на одной из 5 страниц** — `.site-footer { padding-bottom: env(safe-area-inset-bottom) }` работает.

## 8. Приоритизация

### Волна 1 — два P1 (safe-area, 3 файла правок)

Оба в `style.css`, оба в одну строку. Highest impact на реальных iPhone.

```
/* P1-1 */  .skip-link:focus { padding-top: max(8px, env(safe-area-inset-top, 0px)) }
/* P1-2 */  #toTop          { bottom: calc(1.2rem + env(safe-area-inset-bottom, 0px)) }
```

P1-1 фикс уже проверен инъекцией в прогоне — работает.

### Волна 2 — поля ввода и подписи (5 правок, снимают 5 × P2)

| Приоритет | Элемент | Сейчас | Цель |
|---|---|---|---|
| 2.1 | `#consent` (feedback) | 16 × 16 | 44 × 44 (или псевдоэлемент поверх) |
| 2.2 | `input#search` (index), `input#supSearch` (sup) | 24 | 44 |
| 2.3 | `input#pWeight`, `#pAge` (calculator) | 36.4 | 44 |
| 2.4 | `label` «Вес/Пол/Возраст» (calculator), «Добавка 1/2» (index) | 19.2 / 20 | 44 |
| 2.5 | ссылки футера «глоссарии» / «методологии» (`sup/index.html`) | 15 | 24 (WCAG AA) |

Заметьте: у `input#search` высота 46 px на 1024 — то есть правило на 44 px уже существует, но не применяется ниже 1024. Похоже на `@media`-пробел, а не на осознанное исключение. Похожее с `input#q` (38 px на ≤393, 44 px с 412) и `select` на trends, где #94 уже закрыл `min-height: 44px`. **Проверить перед правкой — возможно, нужен один общий селектор.**

### Волна 3 — safe-area по бокам и `.toBottom` (P2-9, P2-10)

```css
/* P2-9 */  .toBottom { right: calc(1.2rem + env(safe-area-inset-right, 0px)) }
```

Требует проверки на реальном устройстве в landscape — runtime-измерение в этом прогоне не выполнялось.

### Волна 4 — мелкий текст и кегль (P3-2, P3-1, P3-6)

621 узел на index и 260 на `sup/index.html` — это правила `.bestBadge`, `.manual-badge`, `.tagChip`, `.cat`, `.grade.*`, `map h3`. Поднимать до 12 px — механическая правка семи правил, но меняет вертикальную раскладку списка на index, поэтому требует регресса по высоте страницы.

`label`-логотип (26 px, 136 страниц) — один селектор `.site-header .top a` или `.brand`.

### Волна 5 — шапка-лента и манифест (P3-3, P3-4, P3-5)

- Показать полосу прокрутки или индикатор свайпа на ≤428, либо ужать кнопки до 4 в строку.
- Убрать `orientation: "portrait-primary"` из манифеста — landscape работает и лучше portrait.
- Привести light-`theme-color` к `#1c1c1e`, раз сайт тёмный по умолчанию.

## 10. Ограничения всего аудита

1. **Инсеты эмулированы, а не считаны с устройства.** Playwright WebKit всегда возвращает `env(safe-area-inset-*)` = `0px` (проверено внедрённым пробным элементом). Значения 59/34 px для iPhone 14 Pro Max и 20/0 px для SE подставлены инъекцией CSS. **Наивный аудит safe-area на Playwright всегда даёт ложный PASS.**
2. **`display-mode: standalone` не эмулируется.** Всегда `browser`. Проверены только косвенные признаки.
3. **Landscape-вырезы по бокам не измерялись** (P2-9) — эмуляция покрывала только top/bottom. Статический анализ плюс геометрия iPhone; уверенность средняя.
4. **`result-panel` в landscape** зафиксирована по Computed-стилю; фактическое перекрытие контента не измерялось.
5. **Часть B измерена на одной ширине** (412 px) — по заданию. 320 px проверена отдельно в Части A на 5 страницах и ведёт себя так же.
6. **Регистрация service worker** в HTML не проверялась (вне объёма); сам `sw.js` отдаётся 200.
7. `route.abort()` в этой обёртке не работает — замеров «без CDN» не делалось.
8. **Ни один фикс не применён.** Задача read-only. Инъекции для проверки фикса D-1 существовали только внутри прогона и в файлы не попали.
