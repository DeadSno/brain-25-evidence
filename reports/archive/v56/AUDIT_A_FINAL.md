## 2. DATA-P1-1: риск реален, но формулировка неточна

### 2.1 Что делает код

`scripts/build_key_sources.py`, функция `main()`, строки 101–116:

```python
for s in data:
    name = s["name"]
    s["price_date"] = pdates.get(s["id"], "дата неизвестна")
    q = SUPPLEMENTS.get(name)
    if not q:
        s["ma_top3"] = []          # ← строка 106: обнуление
        continue
    try:
        pmids = top3_ma(q)
        ...
        s["ma_top3"] = summaries(pmids)
    except RuntimeError as e:
        print(f"⚠️ {name}: {e}")
        s["ma_top3"] = []          # ← строка 115: обнуление и при сбое
        continue
```

Скрипт **не дописывает** поле, а **присваивает его заново** для каждой
карточки. Карточка без запроса в `SUPPLEMENTS` попадает в ветку
`if not q` и получает пустой список — независимо от того, что там было.

### 2.2 Измерение на фактах

Пересчитал независимо от отчёта, читая `docs/data.json` и импортируя
`SUPPLEMENTS`:

| Величина | Значение |
|---|---|
| карточек в `data.json` | 130 |
| записей в `SUPPLEMENTS` | 74 |
| карточек с заполненным `ma_top3` | 80 |
| из них **без** запроса в конфиге | **56** |
| суммарно записей `ma_top3` у этих 56 | **165** |

Кросс-таб сошёлся с отчётом до цифры:

| | `absent` | `[]` | заполнено |
|---|---:|---:|---:|
| запрос есть (74) | 49 | 1 | 24 |
| запроса нет (56) | 0 | 0 | **56** |

Симуляция цикла `main()` на копии данных (без сети, ничего не писала):

```
карточек затронуто : 56
записей потеряно  : 165
потеряно 3: у 54 карточек
потеряно 2: у 1 карточки
потеряно 1: у 1 карточки
```

Примеры под ударом: Мелатонин, ГАБА, Глицин, Валериана, Бета-аланин,
L-цитруллин, Витамин C, Эхинацея, Коллаген, 5-HTP.

### 2.3 Три поправки к формулировке

Находка верна по сути, но в своде она сформулирована неточно — три
расхождения, которые меняют характер выводов:

| # | В своде | На самом деле | Почему важно |
|---|---|---|---|
| 1 | «уничтожит 165 записей у 56 карточек» | 165 — это **суммарное число PMID** (по 3 на карточку), а не 165 отдельных записей | Число выглядит большим, но масштаб — 56 полей по 3 элемента |
| 2 | виноват `src/config.py:6-81` | Механизм в **`scripts/build_key_sources.py:104-107`**, конфиг — только данные | Правка конфига не уберёт мину; уберёт её правка скрипта |
| 3 | «уничтожит» | Строго — **обнулит** | Поля PMID сохранятся в истории git и в `git diff`; это обратимо, не безвозвратно |

Плюс формулировка «весь хвостовой когорт» противоречит самим данным
свода: без запроса в конфиге оказались Мелатонин, ГАБА, Витамин C,
Коллаген — это головная часть списка, а не хвост.

### 2.4 Насколько это срочно

**Стоп-условие владельца «реально может уничтожить данные → СТОП,
срочный алерт» — формально сработало, но по факту ситуация мягче.**

| Фактор | Оценка |
|---|---|
| Данные уже повреждены? | ❌ **Нет.** `data.json` чист, `git status` пуст |
| Прогон случается сам? | ❌ Нет. Скрипт запускается вручную, последний раз — 17.09.2026 |
| Есть ли тест, который поймает? | ❌ Нет. `build_key_sources` не упоминается ни в одном тесте |
| Обратимо ли? | ✅ Да. `git diff` покажет 56 обнулений, откат — `git checkout` |
| Бьёт ли по продакшену молча? | ⚠️ Да — `ok` считает только успешные, и при `ok > 0` файл пишется тихо |

**Вердикт: не авария, а мина с предохранителем.** Данные целы, откат
тривиален. Но мина настоящая: скрипт написан так, что прогон без
намерения стирает треть данных, и ничто — ни тест, ни сообщение —
это не остановит. Защита — дисциплина: **не запускать скрипт, пока
не исправлен**.

### 2.5 Чего скрипт не делает

Важно для приоритизации — ущерб ограничен:

- `price_date` перезаписывается у **всех** карточек, но из
  `price_history.csv`; при отсутствии файла ставится
  «дата неизвестна» — это заметно в `git diff`.
- Строка 123: `if ok:` — если ни один запрос не отработал, файл **не
  пишется** вовсе. Есть аварийный предохранитель, но он срабатывает
  только при полном провале сети, а не при описанной потере.
- `s["ma_top3"] = []` в строке 115 стоит в `except RuntimeError` — то
  есть сетевой сбой по одной карточке тоже обнулит её данные.

### 2.6 Как защититься

| Вариант | Что меняется | Оценка |
|---|---|---|
| **A. `continue` вместо `= []`** | Строка 106 → `continue`. Карточки без запроса не трогаются. Сохраняются все 165 записей | ✅ Убирает мину целиком, 1 строка |
| B. Дописать 56 запросов в `SUPPLEMENTS` | Данные и конфиг сойдутся | ⚠️ 56 запросов, спорные ключевые слова, DATA-P1-4 всё равно мешает |
| C. Только предупреждение в ROADMAP | Ничего не меняет в коде | ❌ Мина остаётся |

Вариант A проверен симуляцией: 74 карточки с запросом обновляются,
56 остаются нетронутыми, 165 записей сохранены.

Опционально к A — убрать и обнуление в `except` (строка 115): при сбое
сети по одной карточке её прежние данные тоже не должны исчезать.

### 2.7 Отдельно: DATA-P1-4 в том же файле

`top3_ma()` (строки 59–62) не передаёт `sort=relevance`. Топ-3
возвращаются по дате публикации. Это делает **любой** прогон этого
скрипта сомнительным по качеству, даже после фикса A: он перезапишет 24
карточки с запросом свежими, но нерелевантными метаанализами. Оба
находки лечатся в одном файле — их стоит закрывать одним заходом.
