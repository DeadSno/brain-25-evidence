## P0

### P0-1. Skip-link через `left:-9999px` рвёт вёрстку на 11264px при `dir="rtl"`

- **Где:** `docs/style.css:1545-1546` (`.skip-link{left:-9999px}` / `:focus{left:0}`)
  — правило на **всех 144 страницах**.
- **Что:** при `dir="rtl"` ширина документа становится **11264px** вместо 1265px в LTR
  (вьюпорт 1280). То есть горизонтальная прокрутка примерно на 10000px на 100% страниц.
- **Как доказано:** элемент найден поиском выхода за вьюпорт — `a.skip-link`,
  `cssLeft:-9999px`, `cssRight:-9802`. Временное `display:none` на skip-link возвращает
  ширину документа **ровно 1265px**, как в LTR. Причина установлена однозначно.
- **Почему латентная:** сайт русскоязычный, `dir="rtl"` никем не выставляется, пользователь
  этого сегодня не увидит. Это мина на будущее, а не текущая поломка.
- **Почему P0, а не P2:** дефект не в «отсутствии поддержки», а в конкретной строке CSS.
  Стандартный способ скрыть skip-link — `clip-path`/`transform`/клиппинг, а не отрицательный
  отступ, потому что отрицательный отступ создаёт область прокрутки. Одна строка даёт
  эффект на каждой странице.
- **Не исправлено** — режим «только отчёты».

## P1

### P1-1. RTL-подготовки в CSS нет вообще: 0 логических свойств при 13 физических позициях

| Свойство | В `docs/style.css` |
|---|---|
| Логические (`margin-inline`, `padding-inline`, `inset-inline`) | **0** |
| Физические отступы/границы | 23 (`margin-left` 10, `margin-right` 3, `padding-right` 2, `border-left` 8) |
| `left:` / `right:` отдельным свойством | 13 |
| `direction:` / `writing-mode:` / `unicode-bidi:` | 0 |

Конкретные места: `style.css:284` `#modalClose{right}`, `:344`+`:352` `.favBtn{right}`,
`:475` `#toTop{right}`, `:1338` `.toBottom{right}`, `:1545` `.skip-link{left}`,
`:1651` `.sb-close{right}`, `:1708` `#atl-sidebar .close-x{right}`.
Проверено вживую в RTL: `#toTop`, `.favBtn`, `#modalClose`, `.toBottom` остаются справа.

Бонус: vendor bootstrap даёт 498 физических свойств, но он почти не используется —
переписывать нужно `docs/style.css`, а не `vendor/`.

### P1-2. `dir`-атрибут не встречается ни разу — инфраструктуры RTL нет

- **Где:** все 146 HTML. Ни одного вхождения `dir=`.
- Там же 0 вхождений `data-i18n*` — нет даже заготовки под вынос строк.

### P1-3. `button#pngBtn` переполняется на 375px — и без перевода тоже

- **Где:** `docs/interactions.html` (`#pngBtn`), скриншот `reports/i18n/i18n_interactions_375_pngbtn.png`
- **Замер:** `clientWidth 42` против `scrollWidth 46` при вьюпорте 375px. Текст обрезается:
  «📷 Скачать PNG 📷 Ска…».
- **Важно:** переполнение есть **без** псевдолокализации — перевод его усугубляет, но не
  создаёт. Это самостоятельный мобильный дефект, попавший в i18n-аудит.
- **Причина:** фиксированная ширина + `nowrap` на кнопке.

### P1-4. Явного контроля переноса нет нигде, кроме модалки

- **Замер:** 157 из 157 проверенных `p/li/td/.card/.chip` на `index.html` имеют
  `overflow-wrap: normal` и `word-break: normal`.
- Wrap-контроль есть только у модалки (`style.css:862-864`).
- Немецкие составные слова — классический случай, который ломает именно такую вёрстку.

### P1-5. Фиксированные ширины в CSS там, где скилл прямо требует гибких

- `style.css:831` `#search{min-width:250px}`, `:882` `#compareResult table{min-width:520px}`,
  `:334` `.calcResult{white-space:nowrap}`, `:651-652` `text-overflow:ellipsis; white-space:nowrap`.
- Обрезание через `ellipsis` на переводе превращается в потерю смысла.

### P1-6. Четыре нативных диалога с зашитыми строками

| Файл:строка | Вызов |
|---|---|
| `docs/atlas.html:641` | `prompt('Скопируй ссылку:', location.href)` |
| `docs/calculator.html:823` | `confirm('Очистить список?')` |
| `docs/calculator.html:849` | `prompt('Скопируйте текст:', text)` |
| `docs/calculator.html:859` | `prompt('Скопируй ссылку:', location.href)` |

Кнопки `prompt()`/`confirm()` рендерятся в локали **браузера**, а текст — в локали сайта.
При любом переводе пользователь получит смесь двух языков в одном окне. Эти четыре вызова
нельзя локализовать подстановкой строки — нужен свой UI.
