## 5. Проверка данных и полный прогон

```
git diff --stat docs/data.json   → пусто
sha256 docs/data.json            → 87AB0E48C91E3294...  (совпадает с backup)
git status --short                → M scripts/build_key_sources.py
                                   M docs/version.json
                                   ?? tests/test_build_key_sources.py
                                   ?? reports/legal_questions_for_lawyer.md
                                   ?? reports/DATA_P1_FIX.md
                                   ?? reports/AUDIT_A_FINAL.md
                                   ?? reports/INFRA_FINAL.md
                                   ?? Modelfile
```

`docs/data.json` не тронут — это была стоп-проверка, и она чистая.

Полный прогон:

```
python -m pytest -q  → 795 passed, 2 skipped, 1 warning
```

Одно падение по пути и его причина. `tests/test_version_json_counts_match_reality.py::test_version_json_tests_match_collected`
сверяет счётчик в `docs/version.json` с числом реально собранных тестов;
5 новых тестов подняли число 989 → 994, и тест потребовал обновить файл.
Обновлено `"tests": 989 → 994`. Это штатное поведение самого теста, а не
регрессия: тот же файл прямо предупреждает, что после добавления любого
теста его придётся править.

Базовая линия до моих изменений — `789 passed, 2 skipped` плюс то же одно
падение счётчика (989 против 994 только из-за нового файла). Итог
`795 passed` = 789 + 5 новых + 1 починенный счётчик.
