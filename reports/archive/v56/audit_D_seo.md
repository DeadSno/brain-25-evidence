## 1. Главный вопрос: почему Google видит 1 страницу из 143?

**Короткий ответ: технической блокировки нет. Причина внешняя — возраст сайта (месяц в проде) и отсутствие авторитета/внешних ссылок.**

Это важное изменение рамки задачи: исходная гипотеза батча была «найти техническую блокировку». Её не существует. Проверено 9 технических гипотез, все отрицательные:

| # | Гипотеза | Проверка | Итог |
|---|----------|----------|------|
| 1 | robots.txt блокирует | файл прочитан | `Allow: /`, sitemap объявлен — **не блокирует** |
| 2 | `noindex` на страницах | скан всех 145 файлов | только `offline.html` (корректно) — **чисто** |
| 3 | canonical указывает на 404 | сверка со sitemap | все 143 указывают на себя — **чисто** |
| 4 | sitemap неполный/битый | сверка с `docs/` | 143 <loc>, соответствует — **чисто** |
| 5 | страницы отдают не 200 | HEAD по всем 143 URL | **143 × 200**, ни одного отличного кода |
| 6 | `X-Robots-Tag` в заголовках | `curl -I` | заголовка нет ни на одной — **чисто** |
| 7 | «Сиротские» страницы | разбор внутренних ссылок | `sup/index.html` линкует 137 страниц — **сирот нет** |
| 8 | Тонкий контент | замер текста по 131 sup | медиана 5043 символа, минимум 4294 — **не тонкий** |
| 9 | Файл верификации GSC | `curl` | `google4a9d23e35c6c3e23.html` → **200** |

Вердикт по гипотезам: **блокировки нет ни в одной из форм.** Google имеет полный технический доступ ко всем 143 страницам.

### Что остаётся — и это вне нашего контроля

- **Возраст.** Сайт в проде с **2026-09-08** — примерно месяц. Для нового домена без ссылок это нормальный срок; 1 индексированная из 143 к месяцу — в пределах ожидаемого, а не аномалия.
- **Авторитет.** `deadsno.github.io` — поддомен чужого домена `github.io`. Внешних ссылок на сайт нет. Для краулера это нулевой стартовый вес.
- **Конфликт бренда.** Версия «DeadSno — актёр озвучки» остаётся непроверяемой изнутри репозитория. Не влияет на краулинг (имя в URL домена читается как `deadsno.github.io`, а не как `deadsno`), но может влиять на поисковую выдачу по брендовым запросам. Учтено как фактор, не как находка.

**Практический смысл:** чинить индексацию не нужно. Нужно дождаться и нарастить авторитет. Спешка с оптимизацией мета-тегов индексацию не ускорит — но и не навредит.

## 2. Находки

### P0 — 1

**P0-1. Мета-тег Google-верификации содержит плейсхолдер — в репозитории и в проде**

`docs/index.html:12`
```html
<meta name="google-site-verification" content="ВСТАВЬТЕ-КОД-ИЗ-GSC">
```

Подтверждено на живой версии: `https://deadsno.github.io/brain-25-evidence/` отдаёт тот же плейсхолдер (не экранированная текстовая копия, а байты из репозитория).

Владелец подтвердил: код **не подставлялся** при деплое. То есть это не шаблон, а незакрытая задача.

**Почему это P0, хотя само по себе не блокирует индексацию:**
- Мета-тег с невалидным содержимым Google просто игнорирует — **краулинг он не блокирует**.
- Но верификация через этот метод не проходит. Сайт удерживается только на HTML-файле `google4a9d23e35c6c3e23.html`, который работает (200), но это единственный способ подтвердить владение.
- Комментарий над строкой ввёл в заблуждение, что тег «инертен»: он инертен для краулинга, но **не** для процесса верификации.

**Последствие:** нельзя пользоваться инструментами индексации GSC (Coverage, URL Inspection — все, что требует верификации свойства). При текущих 0 кликах и 1 странице это заметно ослабляет наблюдаемость.

**Фикс:** вставить реальный код из GSC → Настройка сайта → Подтверждение.

### P2 — 4

**P2-1.** `docs/sup/*.html` — description дублируется в трёх местах: `meta description`, `og:description`, `JSON-LD @description`. Расхождение любых двух — ошибка. Копируется генератором, поэтому фикс точечный, но проверять надо все три синхронно.

**P2-2.** `docs/index.html:4` — `<script defer src="version.js?v=312">` стоит **до** `<meta charset="utf-8">`. По спецификации `charset` должен быть в первых 1024 байтах. На GitHub Pages работает (сервер отдаёт заголовок), но валидатор ворвёт. Риск при переезде на другой хостинг.

**P2-3.** `docs/index.html` содержит только 1 ссылку на `/sup/` (на каталог). До 130 карточек — 2 перехода от главной. Не «сироты», но глубина краулинга на единицу больше, чем можно. Прямые ссылки на популярные добавки с главной сократили бы путь до 1 перехода.

**P2-4.** `lastmod` в sitemap для всех 131 sup-страницы — `2026-10-07`, при этом страницы фактически менялись в батче C (`e8da7d3`, 2026-10-08). Генератор берёт дату коммита — после свежей правки пересборка обязательна, иначе Google увидит «свежесть» без изменений.

## 3. Что прошло проверку

- **robots.txt** — `Allow: /`, sitemap указан, `/sup/` не блокируется
- **`noindex`** — только `offline.html`, что правильно (это офлайн-заглушка для service worker)
- **Canonical** — на всех 143, указывает на собственный URL
- **JSON-LD** — `MedicalWebPage` на sup-страницах, валидный, с `about: Drug`
- **Open Graph** — `og:title`, `og:description`, `og:image`, `og:url`, `og:type` на месте; `twitter:card` = `summary_large_image`
- **`lang="ru"`** — на всех страницах
- **Viewport** — на всех страницах
- **Sitemap** — 143 URL, lastmod из git-коммитов (не дата сборки), соответствует `docs/`
- **Битые ссылки** — 0. Все 143 URL отдают 200
- **Сиротские страницы** — 0. `sup/index.html` покрывает 137 ссылок
- **Контент** — медиана 5043 символа, минимум 4294. Не doorway, не тонкий контент
- **Заголовки HTTP** — нет `X-Robots-Tag`, нет `Content-Disposition`, HSTS включён

## 4. Итоговая оценка

**Индексация: не сломана.** Все технические предпосылки выполнены. Причина 1 из 143 — возраст сайта (месяц) и нулевой авторитет, что лечится временем и ссылками, а не правкой кода.

**Состояние SEO-гигиены: 7/10.** Мета-теги и разметка в порядке; слабые места — длины заголовков и незакрытая верификация GSC.
