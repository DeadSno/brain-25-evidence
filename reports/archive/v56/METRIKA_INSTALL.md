## 1. Cookie-баннер: работает

- `docs/cookie-banner.js` — чтение `localStorage['cookie-consent']`:
  `accepted` → сразу `loadMetrika()`; `rejected` → ничего; нет ключа →
  показ баннера, кнопки вешают обработчики. `typeof loadMetrika` guard: если
  metrika.js не загрузился, страница не падает с ReferenceError.
- Разметка `<div id="cookieBanner" hidden>` со `role="dialog"` и кнопками
  «Принять»/«Отклонить» + ссылкой на privacy.html — на всех 144 страницах.
- Стили — в `style.css` (`#cookieBanner`, тёмная/светлая через var()).
  Ключевая ловушка обойдена: UA-правило `[hidden]{display:none}` слабее
  авторского `display:flex`, поэтому базовый `display:none`, а flex только
  на `:not([hidden])`. Без этого баннер показывался бы до всякого согласия.
- Значения `1rem`/`1.5rem` вместо `var(--space-*)` в width/bottom — требование
  test_css_tokens.py (токены отступа запрещены в не-отступных свойствах).

## 2. Метрика: только после согласия

- `docs/metrika.js` — единственная точка загрузки tag.js. Стаб `window.ym`
  + `ym(112465667, 'init', {...})` c `clickmap`, `trackLinks`,
  `accurateTrackBounce`, `webvisor` (вебвизор + карта скроллов) — по решению
  владельца. Защита от двойной загрузки: `yaCounter112465667` и флаг
  `__metrikaLoading`.
- **Сознательно нет `<noscript><img src=".../watch/112465667">`**: пиксель
  в noscript грузится браузером без JS и до всякого согласия — ровно то, что
  запрещено правилом. Пользователи без JS в статистику не попадают.
- Замеры Playwright (Chromium):
  - первый визит index.html: баннер виден, **запросов к mc.yandex.ru — 0**;
  - клик «Принять»: `metrika/tag.js`, `watch/112465667`, `ytm-config` —
    загрузились, `localStorage='accepted'`, баннер скрылся;
  - «Отклонить»: 0 запросов, ключ `rejected`;
  - повторный визит с согласием: баннера нет, Метрика грузится сразу.
- Мобилка 375×667 и 430×932: баннер 351/406 px без горизонтальной
  прокрутки, кнопки 44 px высотой, accept работает, 0 ошибок консоли.

## 7. Стоп-условие по снапшотам и его разбор

Первый прогон снапшотов: **69 из 73 failed** — сработало стоп-условие «>5
файлов». Разбор причины (два слагаемых, оба намеренные):

1. Ссылка «Приватность» в футере — требование задания. На узких вьюпортах
   она переносится на новую строку: support-412 = высота 2022→2072 (+50 px),
   размер кадра меняется → тест честно даёт 100%. На 1280 diff мелкий и
   локализован: map-1280 = 0.053%, область x[395..530] y[1199..1217] — ровно
   текст «· Приватность», 939 пикселей.
2. Баннер виден в свежем контексте (нет согласия) и попадал в кадр всех
  полностраничных снимков — это предсказало задание в D5.

**Решение владельца:** снимать страницы с предустановленным
`localStorage['cookie-consent']='rejected'` + отдельный тест баннера.

Реализация в `tests/test_visual_snapshots.py`:
- `CONSENT_INIT_JS` (init-скрипт, а НЕ KILL_CSS-маска — урок #95: маска
  через CSS делала баг непроверяемым). При `rejected` Метрика не грузится,
  прогон не шлёт запросов к mc.yandex.ru и не засоряет статистику.
- `test_cookie_banner_visible_first_visit` — зеркало: контекст БЕЗ выбора,
  asserts (баннер видим, 0 запросов к mc.yandex.ru), клик «Принять» →
  tag.js запрошен, consent=accepted, баннер скрыт; свой эталон
  `cookie-banner.png` в обоих движках (по-движково, как все снимки:
  метрики шрифтов у webkit и chromium разные).

Итог: **75 passed, 1 skipped** (skip — index@412 в webkit, лимит высоты
Playwright). Из 69 «красных» после фикса 34 оказались реальными
