**Дата:** 2026-10-07
**Версия:** OpenCode Desktop v2.0.24
**Цель разведки:** облачный агент делегирует лёгкие задачи локальной
Ollama-модели `qwen-coder-top`
**Статус:** ✅ Разведка завершена. **Устанавливать ничего не нужно** —
механизм есть нативный.

## 1. Нативный `small_model`: его нет. Делегирование — есть.

### 1.1 `small_model` в V2 отсутствует

Прямая цитата из документации по компакции, раздел «Limits»:

> | Model | Compaction uses the session's model. **There is no separate
> compaction model.** |

Дополнительно из документации по моделям: корневое поле `model`
«retains only the default provider and model, not a variant» — второго
модельного слота в корне нет.

Скрытые агенты `compaction`, `title`, `summary`, которые в V1 обслуживались
через `small_model`, в V2 **выполняют работу на модели сессии** и не
переключаются на дешёвую.

Отдельно: гайд по миграции V1→V2 перечисляет
`experimental.provider.small_model` среди V1-хуков, для которых **нет**
прямого V2-аналога.

### 1.2 Что есть вместо этого — нативно, без плагинов

Делегирование в V2 строится на трёх штатных механизмах.

**а) Поле `model` у агента.** Агент — именованный профиль с промптом,
моделью, разрешениями. Свою модель агент задаёт сам:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "local-fast": {
      "description": "Лёгкий локальный исполнитель: поиск, чтение, правки",
      "mode": "subagent",
      "model": "ollama/qwen-coder-top:latest",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" }
      ]
    }
  }
}
```

Прямая цитата: *«A subagent uses its configured model, or inherits the
parent session's model when none is configured.»* То есть не задал —
унаследует облачную модель, задал — получит локальную.

**б) Инструмент `subagent`.** Агент с `mode: subagent` запускается
только через этот инструмент, в дочерней сессии со свежим контекстом.
Облачный агент делегирует локальному — обычным вызовом инструмента.

**в) Разрешения по действию `subagent`.** Родительский агент может быть
ограничен так, чтобы запускать только конкретных детей:

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "local-fast", "effect": "allow" }
      ]
    }
  }
}
```

Правило «последнее совпадение выигрывает»: широкие правила ставятся
перед исключениями.

### 1.3 Ollama обнаруживается автоматически

Из документации по моделям, раздел «Local»:

> OpenCode automatically discovers models from Ollama, LM Studio, and vLLM
> at their default local addresses.

При Ollama на `http://127.0.0.1:11434` модель доступна по идентификатору
провайдера `ollama`:

```jsonc
{ "model": "ollama/gemma3:4b" }
```

**Следствие для плана из прошлого задания.** Пункт F («добавить провайдер
`ollama` с `"npm": "@ai-sdk/openai-compatible"` в `opencode.jsonc`»)
**не нужен**: встроенный провайдер `ollama` уже это делает. Ручной блок
с `@ai-sdk/openai-compatible` создал бы второй, конкурирующий путь к той
же модели.

Тонкость к проверке перед применением: наш тег — `qwen-coder-top:latest`,
а в документации примеры без суффикса (`:latest` опускается). Точный
идентификатор видно в `/models` в TUI; в конфиг надо ставить тот, что
там показан.

Отключается так: `"plugins": ["-opencode.provider.ollama"]`.

### 1.4 Смежное: `warming` — про другое

Есть встроенная настройка `warming`: периодические запросы к модели сессии
для сохранения **провайдерского** кэша промптов во время паузы. По
умолчанию выключена. Для локальной модели бесполезна (кэшировать нечего,
только греет CPU), для облачной — жжёт токены. **Оставлять выключенной.**

### 2.2 На чём вывод о V1/V2

Маркер — имя пакета типов: V1 = `@opencode-ai/plugin`, V2 =
`@opencode/plugin`. Это переименование, а не добавление.

И решающая цитата из гайда по миграции:

> **V1 plugin implementations do not run in V2.** Moving a file or
> renaming its config entry is not enough.

Форма тоже разная: V1 — `export const X: Plugin = async ({...}) => ({...})`,
V2 — `export default Plugin.define({ id, setup(ctx) })`.

`tui-model-router` peer-зависимостей не объявляет вовсе, поэтому версия
определена по README — там прямо перечислены его хуки, и все три —
V1-точки расширения (`config`, `experimental.chat.system.transform`,
`chat.message`).

### 2.3 Дополнительные находки по плагинам

**`opencode-tui-model-router` — не просто V1, но и неверен по смыслу.**
Плагин внедряет в промпт оркестратора протокол делегации, где модель
обучена вызывать `Task(subagent_type="fast", prompt=...)`. Это API Claude
Code. В OpenCode инструмент называется `subagent` и принимает
`{ agent, description, prompt, ... }`. Даже после портирования на V2
внедрённый промпт учил бы модель несуществующему инструменту.

Отдельный риск репутации: репозиторий создан 2026-07-22 и последний раз
обновлён **того же дня** — 42 КБ, 0 звёзд, 0 форков, лицензия в репозитории
не указана (в README заявлен MIT). Ветка по умолчанию — `master`, не
`main`. Принимать такое за основу маршрутизации не стоит.

**`opencode-jev-router-plugin` — работает, но не для этой машины.** Требует:

1. Провайдера с эндпоинтом JEV `systemone` — по умолчанию **OpenRouter**,
   плюс API-ключ к нему. В этом проекте OpenRouter отключён
   (`opencode auth logout openrouter`, провайдер заблокирован в РФ) —
   см. `AGENTS.md`, раздел «Резервные каналы».
2. Целевые модели берутся из реестра OpenCode. Поля `cheap`/`powerful`
   допускают любого провайдера, то есть `ollama/qwen-coder-top` как цель
   выставить можно — но классификатор всё равно останется облачным.

**Приватность, о которой стоит знать заранее.** Плагин отправляет
классификатору: текст промпта (без `@file`/`@skill`-упоминаний, но сам
текст — да), имена упомянутых файлов с оценкой размера, список скиллов,
каталог проекта и сводку предыдущего хода. Для репозитория на 130 карточек
и обсуждений БАДов это выписка за периметр.

Плюс он **сам переключает модель сессии** по решению классификатора, то
есть влияет на все последующие запросы в сессии, включая те, где
делегирование не предполагалось. Автор прямо просит пинить версию.

## 3. LiteLLM: работает, но не нужен

| Проверка | Результат |
|---|---|
| Версия | `1.104.0` |
| Требуемая Python | `>=3.10,<3.15` |
| Поддержка Ollama | ✅ штатная, префиксы `ollama/` и `ollama_chat/` |
| OpenAI-совместимость | ✅ прокси слушает `:4000`, путь `/v1/chat/completions` |
| Установка | `pip install litellm` либо `uvx litellm` (есть console-script) |
| Запуск | `litellm --config config.yaml` |

### 3.1 Вердикт: для этой задачи — лишний слой

LiteLLM исправно поддерживает Ollama и отдаёт OpenAI-совместимый API.
Проблема в другом: **OpenCode V2 уже делает ровно это сам, встроенным
провайдером `ollama`.** Прокси между OpenCode и локальной моделью не
убирает ни одного узкого места, но добавляет:

- ещё один постоянно висящий процесс на 4000-м порту;
- ещё одно место, где ломается конфигурация;
- задержку на каждом запросе.

### 3.2 Когда LiteLLM всё-таки оправдан

| Сценарий | Оправдано? |
|---|---|
| Единый ключ на все облачные провайдеры | ✅ |
| Учёт трат и лимитов по командам | ✅ |
| Каскад fallback: облако → локалка → облако | ✅ |
| Единая точка логирования запросов | ✅ |
| Просто «чтобы локалка была видна OpenCode» | ❌ встроенный `ollama` покрывает |

## 4. Рекомендация: не ставить ничего

### 4.1 Что делать

Определить одного subagent с локальной моделью в
`~/.config/opencode/opencode.jsonc`. Ни плагина, ни прокси, ни
LiteLLM.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "local-fast": {
      "description": "Лёгкий локальный исполнитель: поиск по коду, чтение, предварительный разбор. Без коммитов и веток.",
      "mode": "subagent",
      "model": "ollama/qwen-coder-top:latest"
    }
  }
}
```

Плюс строка в `AGENTS.md`: облачный агент делегирует локальному только
задачи из белого списка (чтение, grep, поиск по репозиторию), всё
остальное — сам.

### 4.2 Чего НЕ делать

| Не ставить | Почему |
|---|---|
| `opencode-delegation` | V1, не запустится |
| `opencode-subagent-delegate` | V1 (пинит API 1.4.0), не запустится |
| `opencode-tui-model-router` | V1 + учит несуществующий инструмент `Task(...)` |
| `opencode-jev-router-plugin` | V2, но требует OpenRouter и выписывает текст промптов наружу |
| LiteLLM | встроенный провайдер `ollama` уже покрывает задачу |
| Провайдер `ollama` вручную в `opencode.jsonc` | дубль встроенного; из прошлого задания этот пункт снимается |

### 4.3 Что проверить перед применением

| # | Проверка | Как |
|---|---|---|
| 1 | Точный идентификатор модели | `/models` в TUI — с `:latest` или без |
| 2 | Модель видна как `ollama/...` | каталог моделей после перезагрузки конфига |
| 3 | Модель тянет tool calls | локальный `qwen-coder-top` — 7.6B Q4_K_M; у встроенного агента инструменты должны работать |
| 4 | Фактический выигрыш | замер: одна и та же задача на облаке и на локалке, сравнить и качество, и время |

Пункт 3 — главный риск плана. Delegation = subagent с инструментами.
Если локальная модель не умеет вызовы инструментов корректно, агент будет
делегировать вхолостую. Это дешёвый тест, но он определяет всю идею.
