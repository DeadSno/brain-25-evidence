## 2. Баг `version.js`: инструкция в файле была невыполнима

`docs/dev/IDEAS.md` предлагал: *«найти, где хранится дата каждой карточки в
index.html, после чего `data.json` применится, `version.json.data` =
последняя дата коммита»*.

**Даты в `index.html` нет.** Замерено: в `docs/index.html` ноль вхождений
`2026-`, ноль `data-supplement=`, ноль карточек. Их рисует `script.js`.

Функция, которая решает, какую дату показать — `script.js:62`:

```js
function updatedLine(s) {
  const fromVersion = (window.APP_VERSION && window.APP_VERSION.data) || null;
  const d = fromVersion || s.updated || '—';
```

Либо **все** карточки показывают `version.json.data`, либо (если версия ещё не
пришла) **все** падают на своё `s.updated`. Расхождение «120 из 130» — это не
индивидуальный дрейф, а проигранная гонка.

### Что в `data.json`

```
карточек: 130
2026-09-16: 81
2026-09-23: 26
2026-09-22: 13
2026-09-25: 10   <- свежо
```

81 + 26 + 13 = **120**. Совпадает с заметкой до единицы. Значит формулировка
«120 из 130» верна — но относится к `data.json`, а не к отрисовке.

### Где ломается

`version.js:39` перерисовывает карточки после загрузки версии, но под гейтом:

```js
if (typeof applyFilters === 'function' && window.supplements && supplements.length) {
```

`script.js:7` объявляет `let supplements = []`. **`let` верхнего уровня не
создаёт свойство на `window`** — в отличие от `var`. Замерено в браузере:

```json
{"window_supplements": "undefined",
 "bare_supplements": "array len=130",
 "APP_VERSION": "{\"app\":\"5.0.0\",\"data\":\"2026-09-25\", ...}"}
```

`window.supplements` — `undefined`, при этом `supplements` существует как
обычная переменная. **Гейт мёртв всегда**: перерисовка не произойдёт ни при
каком порядке загрузки.

### Воспроизведение в браузере

Снос сервис-воркера и его кэшей (`v67-static`, `v67-data`) полностью убирает
маскировку — SW отдавал `version.json` так быстро, что гонка всегда выигрывала
на localhost. 8 обычных перезагрузок: 130/130 со свежей датой. После сноса SW:

```
на  2с: {"2026-09-16":81, "2026-09-23":26, "2026-09-25":10, "2026-09-22":13}
на  6с: то же
на 12с: то же   ← восстановления нет
```

`APP_VERSION` при этом уже `2026-09-25`. Данные есть, отрисовка не происходит.

**Фикс — одна строка:** убрать `window.supplements && ` из условия.

### Связь с флейком `index@1280`

`tests/test_visual_snapshots.py:281-290` уже описывает ровно этот механизм и
специально **не чинит** страницу:

> *«Дата «Обновлено:» берётся из `APP_VERSION.data`, если версия уже пришла,
> и из самой карточки иначе… version.json грузится асинхронно, поэтому есть
> гонка. Замерено на этой копии: при одной загрузке 1 из 20 показывала
> индивидуальную дату вместо общей.*
> *Важно: страницу здесь НЕ чиним. Раньше хелпер дёргал `applyFilters()` за
> неё, и это было неверно — такой тест замаскировал бы возврат бага.»*

Тест ждёт сходимости, которой при проигранной гонке не будет, — поэтому он
падает. Один корень, три наблюдения: строка 1 (баг), строка 3 (`index@1280`,
35.610%) и строка 4 (1 загрузка из 20).

В роадмапе это отмечено явно, чтобы строку 1 не закрыли, а строку 4 не
пытались чинить хелпером.

## 3. «Мёртвые ссылки NMN / NR / B6 / Пиперин» — не подтверждается

Корневой `IDEAS.md`: *«Мёртвые ссылки (NMN/NR, Витамин B6, Пиперин)»*.

Замер по `docs/data.json`:

- у карточек **0 из 130** полей `url` или `link` — ссылаться нечем;
- `wiki` хранит **int** (например `181494`), то есть ссылка строится как
  `ru.wikipedia.org/?curid=<id>`; мёртвость без HTTP-проверки не проверить;
- карточка `NMN` есть (`name`, `caution`, `pubmed_term`), карточка `B6` есть;
- карточек `NR` и `Пиперин` **нет**;
- `Пиперин` встречается 1 раз — в `synergists` карточки «Куркумин».

Поэтому строка записана как «не подтверждается как заявлено» с версией
«требует уточнения», а реальная смежная находка (перекрёстное упоминание без
своей карточки) внесена рядом.
