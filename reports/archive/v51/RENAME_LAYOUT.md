## 3. Этап 3 — `#graph`

### 3.1 Три способа достать контейнер — и два из них невидимы для grep

Это главная находка этапа. Контейнер доставали **тремя разными
способами**, и строковые не содержат решётки:

| Способ | Где | Сколько |
|---|---|--:|
| CSS-селектор `#graph` | CSS-правила, `querySelector('#graph canvas')`, комментарий | 14 |
| `id="graph"` в разметке | `<div id="graph"></div>` | 2 |
| `getElementById('graph')` | interactions, JS | 2 |
| `$('graph')` | atlas, JS | 1 |
| | **Итого** | **19** |

Подсчёт только по `#graph` даёт 16 — **на 3 меньше**. Ровно та же
ловушка, что с `dataset.tab` в прошлом заходе, только дороже по
последствиям: вместо молчаливо мёртвой кнопки был бы пустой контейнер
и «почти не отличающийся» снимок.

### 3.2 Что подтверждено чтением, а не предположением

`atlas.html:252`:

```js
const $ = id => document.getElementById(id);
```

`$` — локальный алиас `getElementById`. Значит `$('graph')` указывает на
id и **обязан** быть переименован: иначе `vis.Network` получил бы `null`.
Это нельзя было решить по аналогии — будь это `querySelector`, строка
искала бы тег `<graph>` и уже ничего бы не находила.

Заодно подтверждена конвенция префикса: на atlas уже есть `atl-sidebar`
(`$('atl-sidebar')`).

## 5. Негативный контроль: дыра, найденная и закрытая

Логика: тест, который всегда зелёный, хуже отсутствующего. Три реальные
поломки этого этапа:

| Сценарий | Ловит? | Упало проверок |
|---|---|--:|
| A. `getElementById('int-graph')` откачен на `'graph'` | да | 4 |
| B. `$('atl-graph')` откачен на `$('graph')` | да | 3 |
| C. `querySelector('#int-graph canvas')` откачен на `#graph` | **было нет** | 0 |

**Сценарий C сначала прошёл незамеченным**, и это стоило разбора.

`interactions.html:517` и `atlas.html:612` — это обработчик кнопки
экспорта PNG:

```js
document.getElementById('pngBtn').onclick = () => {
  const canvas = document.querySelector('#int-graph canvas');
  if (!canvas) return;                      // ← тихий выход
  ...
};
```

При старом селекторе `canvas` был бы `null`, сработал бы ранний `return`,
и кнопка экспорта **молча ничего не делала бы**. Ни снимок, ни проверка
графа на canvas это не ловят: экспорт вообще не выполняется при загрузке
страницы.

В коде поломки не было — вхождение было переименовано верно, это
подтвердил grep. Дыра была в приёмке, и она теперь закрыта: добавлена
проверка экспорта, которая подменяет `HTMLAnchorElement.prototype.click`,
нажимает кнопку и требует дойти до `a.click()` с настоящим PNG-payload.

Замеры после починки приёмки:

| | interactions | atlas |
|---|---|---|
| payload | 83 642 симв. `data:image/png` | 127 554 симв. |
| имя файла | `interactions-supplements.png` | `atlas-2026-10-04.png` |

Повторный негативный контроль: **все три сценария краснеют**, код
возвращён, приёмка зелёная.

## 6. Ошибки этого захода

Пять, все пойманы проверками. Пятая — обобщение остальных четырёх.

**1. Проверка с базой HEAD вместо состояния «до».** Первая версия скрипта
`.tabs` сравнивала счётчики с HEAD. Но переименование `.tab` → `.tr-tab`
из этого же захода ещё не закоммичено, и HEAD не содержит `.tr-tab` —
четыре ожидания из четырёх разошлись с верным кодом. Правило владельца
«сверять с HEAD» работает для закоммиченного состояния; пока в дереве
лежит незакоммиченная работа, база — это снимок непосредственно перед
операцией.

**2. Производные счётчики сравнивались с нулём.** Подсчётчики вида
`.tabs .spacer` обязаны переехать в `.tr-tabs .spacer`, то есть их дельта
не ноль. Я вывел их в отдельную проверку с инвариантом «сумма пары
неизменна», но в коде оставил сравнение с нулём — и они стабильно давали
FAIL при верном коде.

**3. Ожидания, записанные числами, разошлись в шестой раз.** Подсчётчик
`.int-layout` показывал 4 вместо ожидаемых 3, потому что я забыл, что
сам же дописал оба имени в комментарий `style.css`. Ожидания переведены
на вывод из фактических счётчиков замен.

**4. Проверка существования строки вместо инварианта.** Я искал
`vis.Network(container` в interactions, но там аргумент стоит на
отдельной строке — проверка ругалась на верный код. Заменена на проверку
инварианта: контейнер для сети взят из `getElementById('int-graph')` и
передан в `vis.Network`.

**5. Опечатка в пути маскировалась как «класс не найден».** В приёмке
страница была задана как `interactions.html`, а скрипт дописывал `.html`
— получался `interactions.html.html`, 404. Диагностика уводила не туда:
.container не найден на странице, которой нет. Добавлена проверка
статуса ответа, чтобы опечатка давала «страница не найдена».

**6. Проверка была бессмысленной, а не просто неверной.** Требование
«имя файла содержит новый id» к PNG `interactions-supplements.png`
невыполнимо: id в имени файла не было никогда.

Общий знаменатель прежний, и он усилился за заход: **ожидания, написанные
от головы, оказываются неверными чаще, чем кажется.** Шесть расхождений
из шести при верном коде. Сверка с состоянием «до» — обязательна, и
ожидания должны выводиться из счётчиков, а не из чисел.
