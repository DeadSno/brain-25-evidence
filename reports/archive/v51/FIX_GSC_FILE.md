## 1. Что случилось

`docs/google4a9d23e35c6c3e23.html` — файл верификации Google Search
Console, 53 байта, одна строка:

```
google-site-verification: google4a9d23e35c6c3e23.html
```

GSC требует, чтобы файл лежал в корне сайта, то есть рядом со
страницами. `scripts/audit_classes.py::collect()` отбирал файлы по
расширению:

```python
pages = sorted(DOCS.glob("*.html"))
```

и принял файл верификации за страницу. `tests/test_no_orphan_classes.py`
упал: аудит разобрал 19 страниц вместо 18.

Падение поймал pre-commit-хук, а не ручной прогон: между последним
прогоном и коммитом файл появился в рабочей копии.

---

## 2. Выбор основания для исключения

Владелец предложил два варианта. Оба проверены замером по всем 19 файлам
`docs/*.html`:

| файл | байт | `<html>` | `<!DOCTYPE` | `<title` |
|---|--:|:--:|:--:|:--:|
| все 17 обычных страниц | — | да | да | да |
| `offline.html` | 4 416 | **да** | да | да |
| `sup/*.html` (5 файлов) | — | да | да | да |
| `google4a9d23e35c6c3e23.html` | 53 | **нет** | нет | нет |

Итог: тег `<html>` есть у всех 18 страниц и отсутствует только у файла
верификации. Оба варианта дают одинаковый результат — 18.

**Выбран вариант Б: отбор по наличию тега `<html>`.**

Причина — устойчивость при изменении, а не симпатия к формулировке:

| | Вариант А: `google*.html` | Вариант Б: нет тега `<html>` |
|---|---|---|
| Что перечисляет | имена сервисов | суть: аудит разбирает страницы |
| Верификация Bing или Яндекса | нужна новая строка | отсеется сама |
| Страница с именем `google-search.html` | **молча выпадет из аудита** | попадёт в аудит, как и должна |
| Замена файла верификации | правило надо менять | ничего менять не надо |
| Служебный файл с любым именем | попадёт в аудит | отсеется |

Вариант А перечисляет сервисы. Вариант Б отвечает на вопрос, который
задаёт сам тест: аудит классов имеет дело со **страницами**, а файл без
полного HTML-документа страницей не является.

## 3. Где сделано

### `scripts/audit_classes.py`

```python
HTML_DOC = re.compile(r"<\s*html[\s>]", re.I)

def is_page(path: Path) -> bool:
    head = path.read_text(encoding="utf-8", errors="replace")[:4096]
    return HTML_DOC.search(head) is not None
```

Отбор перенесён **в инструмент, а не в тест**, и это принципиально.
`audit_classes.py` — не только модуль для импорта: это CLI, который
запускается руками и печатает «Страниц разобрано: N» в отчёты о
переименованиях. Починив только тест, я бы оставил инструмент печатать
19 и продолжил кормить неверными числами будущие отчёты.

Это тот же класс ошибки, что уже всплывал дважды: цифра в трекере
разошлась с кодом, потому что её взяли из отчёта, а не перемерили.

Читаются только первые 4 КБ — файл верификации это 53 байта, а целиком
читать 40-килобайтные страницы ради проверки одного тега незачем.

### `tests/test_no_orphan_classes.py`

Само число `EXPECTED_PAGES = 18` не менялось. Добавлено пояснение, почему
оно 18, а не 19: иначе оно выглядит как число, которое молча уехало бы
в следующий раз.

## 4. Почему фильтр не является дырой

У варианта Б есть слабое место: настоящая страница без тега `<html>`
молча выпала бы из аудита. Проверено, что этого не произойдёт.

| сценарий | ожидание | факт |
|---|---|---|
| Настоящая страница `faq.html` с намеренно снятым тегом `<html>` | счётчик уйдёт на 17, тест упадёт | **падает:** «аудит разобрал 17 страниц вместо 18» |
| Служебный файл без тега `<html>` | не попадёт в аудит | **отсеян**, 18 страниц |
| Файл верификации | отсеян | **отсеян**, 18 страниц |

То есть обратная ошибка не проходит молча: `test_audit_covers_every_page`
требует ровно 18 страниц, и страница без тега уронила бы счётчик с
падением теста. Проверено на реальном файле, не рассуждением.

После проверки `faq.html` восстановлен, `git status` по нему чист.

### `docs/dev/GSC_SETUP.md` противоречил reality

Документ рекомендовал **HTML tag** и прямо писал про HTML file «не
выбирать… лишняя сущность». Владелец выбрал файл, и после этого
документ советовал против того, что сделано.

Раздел 3 переписан: выбранный метод, его особенность и то, что из-за
него сломался аудит. Заглушка в `docs/index.html:12` сохранена как
запасной вариант — она пригодится при переезде на домен.

Добавлен раздел 6 про файл верификации и инструменты проекта: почему
отбор сделан по тегу, почему он не дырявый и что делать с файлом при
переезде на свой домен (токен привязан к `deadsno.github.io`, старый
надо удалить).

Это третий случай за серию, когда написанное раньше стало ложным. Два
предыдущих: строка техдолга 34 утверждала «джоб на месте» после того,
как джоб сняли, и раздел про `.top`/`.site-title` предлагал то, что
замер показал невыполнимым.

### Побочная находка, не связанная с фиксом

`docs/graph.html` — единственная страница **без `<!DOCTYPE html>`**.
Остальные 17 его имеют. На аудит не влияет, но расхождение есть и
зафиксировано здесь, а не потеряно.
