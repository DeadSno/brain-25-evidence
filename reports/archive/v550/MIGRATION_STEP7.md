### Что осталось литералом и почему

План это предписывает, и причины разные:

| Значение | × | Причина |
|----------|--:|---------|
| `50%` | 4 | круг и овал, не шкала |
| `10px` | 3 | план: «`sup/*`-карточки — своя локальная система» |
| `12px 12px 0 0` | 2 | односторонний, своя геометрия |
| `20px` | 2 | вне шкалы |
| `2px` | 2 | вне шкалы (в `atlas.html`) |
| `0 0 6px 0` | 1 | односторонний |
| `11px`, `14px`, `72px` | 4 | вне шкалы (`graph.html`, `map.html`) |
| `0 !important`, `50% !important` | 2 | `!important` вне шкалы, план не маппит |

Равных значений, которые можно было бы слить, нет: 10px ≠ 8px, 4px ≠ 6px.
**Округлять не стал** — это сдвинуло бы пиксели и потребовало новых эталонов,
ровно как 521 значение вне шкалы на шаге 6.

## 3. Тени: 21 значение → 4 токена + 5 исключений

| Токен | Значение | Заменил |
|-------|----------|:-------:|
| `--shadow-sm` | `0 2px 6px var(--shadow)` | `.card` (1) |
| `--shadow-md` | `0 2px 8px rgba(0,0,0,.15)` | кнопка «вниз» (1) |
| `--shadow-lg` | `0 12px 32px rgba(0,0,0,.16)` / `.5` по теме | `.card:hover` (2) |
| `--shadow-xl` | `0 24px 80px rgba(0,0,0,.55)` | оверлей в `map.html` (1) |

5 замен. Осталось 16 значений-литералов, и это не недосмотр, а решения плана:

- **сайдбар** `0 -8px 32px`, `12px 12px 0 0` — оверлей со своей геометрией;
- **заглушки загрузки** в `graph.html` (`2px 0px 4px`, `0px 0px 4px`,
  `0px 0px 10px`) — тень рисует прогресс-бар, а не elevation;
- **фокусные кольца** `0 0 0 1px var(--accent)`, `#5aa9ff` — индикатор
  фокуса, а не тень;
- **акцентные** `0 2px 8px rgba(31,111,165,.35)`, `0 2px 12px …,.5`,
  `0 2px 8px rgba(243,156,18,.4)` — привязаны к цвету, а не к высоте;
- **highlight** `0 0 0 3px #f1c40f, 0 0 20px …` — два слоя, не уровень.

### `--shadow-lg` и тема

Единственный тематический токен. В `style.css` было две строки:

```css
.card:hover       { transform: translateY(-4px); box-shadow: 0 12px 32px rgba(0,0,0,.16); }
body.dark .card:hover { box-shadow: 0 12px 32px rgba(0,0,0,.5); }
```

Проверил до правки, что это действительно две темы одного элемента, а не два
разных места: `.card:hover` — светлая, `body.dark .card:hover` — тёмная.
Схлопнул в `var(--shadow-lg)`, объявленный в `:root` (`.16`) и в
`html.dark,body.dark` (`.5`). Кастомное свойство резолвится на самом элементе,
поэтому карточка внутри `body.dark` возьмёт тёмное значение сама. Обе
`box-shadow` строки оставлены — лишняя Specificity ничего не ломает, зато
если бы расчёт темы был неверным, тёмное правило всё равно перебило бы
светлое.

Проверено замером в тёмной теме (см. §5).

## 6. Три бага в моём же скрипте

Скрипт токенизации пришлось откатить и переписать трижды. Все три бага дали бы
**молча** сломанный CSS — `pytest -q` был бы зелёным.

**1. `box-shadow: box-shadow: var(--shadow-lg)None`.** `m.group(3)` — необязательная
группа `!important`, при отсутствии это `None`, и вставка `None` в файл дала
мусор. Плюс `m.group(1)` уже содержит имя свойства, а я дописывал его ещё раз.

**2. Потерянное имя свойства.** После первой правки стало
`.card:hover { transform: translateY(-4px); var(--shadow-lg) ; }` — я убрал
`group(1)` из результата, убрав и `box-shadow:`.

**3. Незакрытый `/*`.** Комментарий `/* ── Шаг 7: радиусы и тени ──` был
открыт, но не закрыт. Всё оттуда до ближайшего `*/` — комментарий, то есть
**весь `:root`**, включая исходные переменные цветов. Поймал не снапшот, а
свой же verify-скрипт: он искал объявления `--radius-*` после вырезания
комментариев и нашёл только `--shadow-lg`.

Попутно выяснилось, что дисбаланс `/*` и `*/` в `style.css` **был до меня**:
в HEAD 123 против 119. Значит наивный regex-вырез комментариев на этом файле
врёт — именно поэтому verify сначала показывал ложное «используются без
объявления», хотя объявления были на месте.

## 7. Чего шаг не делает

- **Не трогает локальные `<style>`.** Задача шага — токены, а вынос стилей в
  `style.css` это шаги 1-4, которые уже сделаны для header, sup, interactions
  и sidebar. Оставшиеся 12 страниц со своими `<style>` разбираются отдельно.
- **Не убирает `10px`.** Самая заметная оставшаяся аномалия — `.card` радится
  `10px`, а шкала максимумом имеет `12px`. Причина в том, что `10px` идёт
  из локальной системы `sup/*`-карточек, и менять его — это визуальная правка,
  а не токенизация.
- **Не переносит инлайновые `style=""`.** Их 23 с радиусом или тенью, они вне
  области шага (общий бэклог — 179 инлайновых `style=""`).
- **Не трогает 16 оставшихся теней-литералов** — по решениям плана, не по
  недосмотру.
