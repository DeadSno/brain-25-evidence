## 2. Часть A — тест создан

`tests/test_visual_snapshots.py`, 470 строк, 37 тестов: 18 страниц × 2 разрешения
+ модалка. Порог **0,05%** (не 0,5%). Маркер `snapshots`, в `pytest.ini`
добавлено `-m "not snapshots"` в addopts, поэтому обычный `pytest -q` их не
запускает.

Что делается перед съёмкой — всё по замерам, не по догадкам:

1. анимации и transitions выключаются инъекцией CSS, **и результат инъекции
   проверяется** (`getComputedStyle(body).transition === 'none'`);
2. граф на canvas (`graph`/`atlas`/`interactions`, vis-network@9.1.9) живёт с
   `physics.enabled: true`, `stabilization: false` — симуляция не останавливается.
   Замерено: 2,2-3,7% / 1,3-1,5% / 0,04-0,07%. Узлы раскладываются по кольцу,
   physics выключается, `fit()`; **свойства узлов сохраняются** — меняется
   только геометрия;
3. анимации Chart.js патчится в геттере `window.Chart` (UMD делает
   `global.Chart = {}` и наполняет позже — в сеттере `defaults` ещё `undefined`,
   патч падал бы в тихом `try`);
4. ждём сходимости версии и сетки карточек — **но страницу не чиним**, чтобы
   возврат гонки падал, а не маскировался;
5. каждый снимок — второй заход: первый в холодном браузере рисует index иначе;
6. `#loadingBar` на `graph.html` скрыта: её ширина зависит от скорости загрузки
   (замерено 730-1279 пикселей разброса), а в покое у неё `display:none`.

скриптом или через переменную окружения, **иначе скачивает с GitHub Releases**.

### Одна ошибка, найденная и исправленная

Первая версия собирала URL руками из `shssoichiro/oxipng` — репозиторий
переехал на `oxipng/oxipng`, и скрипт получал **HTTP 404**. Исправлено: адрес
берётся из GitHub API по имени файла под текущий релиз, поэтому переезд
репозитория его больше не сломает. Проверено: `PATH` был пуст, скрипт сам
скачал бинарь и отработал.

## 5. Что пришлось сделать сверх задания, и почему

### 5.1 `docs/version.json`: `tests` 754 → 791

Без этого `pytest -q` падал: `test_version_json_tests_match_reality` требует,
чтобы число в `version.json` совпадало с числом собранных тестов. Добавление 37
снапшотов сдвинуло счётчик, и тест об этом честно сообщает.

```
$ pytest --collect-only -q | tail -1
754/791 tests collected (37 deselected)
```

Арифметика сходится: 791 − 37 deselected − 18 skipped = **736 passed**. JSON
валиден, UTF-8 без BOM.

### 5.2 `index-412` и `index-1280` пересозданы — и вот тонкость

После смены `tests` на главной поехала плашка `Тестов: N` — на `index` это
единственная страница с `data-version="tests"` (`index.html:299`).

Проверил, поймает ли это тест:

| | дрейф | вердикт |
|---|---:|---|
| `index-412` | 0,0019% (305 px) | PASS |
| `index-1280` | 0,0016% (300 px) | PASS |

**Тест бы это пропустил.** Три цифры в плашке — это ~300 пикселей, то есть
0,0016% от полотна 1280×14715, а порог 0,05% в **31 раз** выше. Смена счётчика
тестов прошла молча.

Пересоздал оба файла вручную. Это не дефект набора, но о нём стоит знать:
**изменения меньше ~900 пикселей на полотне `index@1280` невидимы для
теста.** При пороге 0,05% это примерно половина плашки.

### 5.3 `version.json.data` = 2026-09-25 — гонка тут не воспроизводится

В прошлой сессии баг `version.js` (проверка `window.supplements` при top-level
`let supplements`) давал 20% устаревших дат. Проверил на этой копии:

| | правильная дата | устаревшая |
|---|---:|---:|
| прошлая копия | 4 из 20 | 16 из 20 |
| эта копия | **19 из 20** | 1 из 20 |

Метрика слабая, и вот почему: `version.json.data` здесь `2026-09-25`, а такой
датой помечены **только 10 карточек из 130 (8%)**. Остальные 120 показывают
`2026-09-16`, `-22`, `-23`. То есть «правильный» результат почти всегда
получается **устаревшей** отрисовкой — гонка просто не проявляется визуально
на первой карточке. Отсюда и 95%.

Проверил по всем 130 карточкам сразу: гистограмма дат одинакова при 6
загрузках, все карточки показывают `2026-09-25`, дрейф **0,0000%**. То есть в
этой копии гонка либо вымерла, либо не проявляется на всех карточках — а
снапшот всё равно стабилен, потому что карточки рисуются уже после прихода
`version.json`.

Сам баг в `version.js:39` на этой копии **не тронут** — он в коде остался
(`window.supplements` при `let supplements` в `script.js:7`). Тест при этом
проходит. Если гонка вернётся, тест упадёт с внятным текстом, а не промолчит.

**Расхождение с ожиданием: 38 против 37.** Причина — каталог
`tests/snapshots/_actual/` с единственным файлом `.gitignore`:

```
37 PNG + 1 DIR (_actual) = 38
```

Каталог нужен для артефактов падения (`*.actual.png`, `*.diff.png`) и не должен
попасть в git. Он создан намеренно, PNG-эталонов ровно 37. Если предпочитаете
строго 37 записей — удалю каталог, артефакты будут создаваться при первом
падении, но тогда их нечем будет исключить из индекса.

Пункт 4 совпал с ожиданием, кроме порядка строк (git сортирует по-своему).

## 9. Про 220 МБ и оптимизацию процесса

Набор после сжатия — **17,24 МБ**. При 10 итерациях миграции арифметически это
~172 МБ против ~223 МБ до сжатия. Арифметика — верхняя оценка: соседние версии
PNG git частично жмёт дельтами.

> ### Что делать при 10+ итерациях миграции
>
> **Не пересоздавать все 37 снапшотов после каждой правки CSS. Только
> затронутые:**
> ```powershell
> $env:UPDATE_SNAPSHOTS="1"; pytest -q -m snapshots -k "index or calculator"
> ```
> Шаг 1 (отступы) бьёт по всем страницам, а Шаг 3 (цветовые токены) может
> тронуть только `index` и `sup/*`. Перезаписывать весь набор, когда изменилось
> два файла, — и есть основной источник роста.
>
> **git сжимает похожие PNG дельтами** — реальный рост меньше арифметического.
>
> **Если репозиторий перерастёт 100 МБ — хранить эталоны вне git** (Cloudflare
> R2, бесплатный тариф), CI сравнивает с артефактом.
>
> **Не делать сейчас.** Записано как «если понадобится». Перенос за пределы
> репозитория означает, что визуальная защита перестаёт защищать: без эталонов
> в ветке проверка не воспроизводится у другого разработчика.

## 10. Открытые вопросы

1. **`tests/snapshots/_actual/`** — оставить (тогда 38 записей) или удалить
   (строго 37, но артефакты падения придётся исключать иначе)?
2. **Порог 0,05% не видит изменения меньше ~900 пикселей на `index@1280`** —
   счётчик тестов прошёл молча (§5.2). Для миграции это, скорее, плюс: не
   создавать шум. Но если нужен контроль над мелочами вроде цифр в плашке,
   порог надо снижать, и тогда важнее становится верхняя оценка шума.
3. **Снимки только тёмной темы** — пробел для Шага 3 (цветовые токены правятся
   в обеих темах). Из прошлой сессии, по вашему решению.
4. **Баг `version.js:39`** в этой копии не тронут (§5.3).
