## 3. Этап 4 — `tests/test_graph_interaction.py`

### 3.1 Дыра, которую закрывает

Обработчик экспорта на обеих страницах устроен так:

```js
document.getElementById('pngBtn').onclick = () => {
  const canvas = document.querySelector('#int-graph canvas');
  if (!canvas) return;                       // ← тихий выход
  const url = canvas.toDataURL('image/png');
  ...
};
```

При разошедшемся селекторе `canvas` равен `null`, срабатывает ранний
`return`, и кнопка «Скачать PNG» **молча не делает ничего**: ни ошибки в
консоли, ни файла, ни изменения на странице.

Почему это не ловили остальные проверки:

| проверка | почему не ловит |
|---|---|
| визуальные эталоны | снимаются **до** клика; экспорт при загрузке не выполняется |
| статический grep | видит `#int-graph canvas`, но не проверяет, что селектор срабатывает |
| «canvas создан» | контейнер и canvas существуют, у `canvas` просто читается несуществующий селектор |
| тест вкладок | про кнопку экспорта ничего не знает |

Дыра была найдена негативным контролем на этапе 3 — то есть **уже после**
того, как переименование было сделано. В коде поломки не было, дыра была
в проверке.

### 3.2 Состав — 42 теста

10 проверок на пару движок × страница (4 пары) + 1 на движок (2 движка).

| Проверка | Что защищает |
|---|---|
| `test_graph_id_found_once` | контейнер найден ровно один раз |
| `test_graph_has_size` | граф не схлопнулся (< 200 px) |
| `test_graph_fits_container` | flex-раскладка не разъехалась |
| `test_container_found_once` | обёртка найдена ровно один раз |
| `test_container_display_flex` | правило класса совпало с разметкой |
| `test_container_height_not_collapsed` | обёртка не схлопнулась в высоту содержимого |
| `test_canvas_created` | vis-network создал canvas |
| **`test_export_handler_reaches_click`** | **главная: обработчик дошёл до `a.click()`** |
| **`test_export_payload_is_real_png`** | **payload — настоящий PNG > 10 000 символов** |
| `test_old_selectors_absent` | старые `#graph` и `.layout` исчезли |
| `test_both_graphs_have_ink` | на обоих графах что-то нарисовано |

### 3.3 Почему подменяется `HTMLAnchorElement.prototype.click`

Экспорт — это `a.click()` с `href` вида `data:image/png` и атрибутом
`download`. Такой клик не порождает сетевой запрос, и `expect_download()`
на таком ненадёжен.

Перехват выбран потому, что срабатывает **ровно на той строке, до которой
дошёл обработчик**, и попутно даёт payload для проверки размера.
Обработчик при этом настоящий, клик по настоящей кнопке — перехватывается
только финальное действие браузера. Это не «проверка проверки».

### 3.4 Пороги и откуда они

| Порог | Значение | Обоснование |
|---|--:|---|
| `MIN_PNG_PAYLOAD` | 10 000 | замерено 47 418 … 127 554; взято вчетверо ниже минимума и выше пустого холста |
| `MIN_GRAPH_HEIGHT` | 200 px | ниже — контейнер схлопнулся |
| `MIN_CONTAINER_HEIGHT` | 400 px | то же |
| плотность сети | > 500 px | замерено 17 017 … 20 488 |

Порог «нарисовано» отделён от «canvas создан» намеренно: пустой canvas
даёт валидный PNG малого размера, поэтому без него экспортировать нечего,
и проверка экспорта сама по себе бессмысленна.

### 3.5 Негативный контроль — все три сценария ловятся

| Сценарий | Упало проверок | Ключевые |

## 4. Этапы 5–6 — `.site-title` и `.top`: переименование отменено

### 4.1 Что спрашивали

Проверить, одинаковы ли эти классы на всех 17 страницах. Если одинаковы —
не переименовывать. Если разные — разветвить.

### 4.2 Замер: статика

| | `.site-title` | `.top` |
|---|---|---|
| форм разметки | **1** (`class="site-title"`) | **1** (`class="top"`) |
| вхождений на страницу | ровно 1, на 17 страницах | ровно 1, на 17 страницах |
| в `style.css` | 25 селекторов | 17 селекторов |
| локальных правил в страницах | 37 на 7 страницах | 50 на 6 страницах |

### 4.3 Замер: браузер, 17 страниц × 2 движка

| | `.site-title` | `.top` |
|---|---|---|
| тег | `div` везде | `header` везде |
| непосредственный родитель | `header.top` везде | `body` (14) / `div.wrap` (3) |
| потомки | `a` (+ `span.v` на 11 из 17) | `div.site-title` + `div.actions` — **один набор на все 17** |
| потомков по порядку | — | всегда `.site-title`, затем `.actions` |
| экземпляров внутри | — | `.site-title` = 1, `.actions` = 1 везде |

Вычисленные значения различаются, и это видно:

| Свойство | Значения на 1280 |
|---|---|
| `font-size` | 21.6 px (15 страниц), 20.8 px (calculator, trends) |
| `line-height` | 32.4 / 31.2 / 24.96 px |
| цвет ссылки | `rgb(250,250,250)` (16), `rgb(245,245,247)` (trends) |
| `gap` у `.top` | 16 px (16 страниц), `6.4px 9.6px` (trends) |

На 412 px `font-size` сходится к одному значению — то есть различия
сделаны осознанно для широкого экрана.

### 4.4 Решение: не переименовывать

Различаются **значения**, а не сущности. И это принципиально разные вещи:

> Переименование здесь **не устранило бы расхождений, а продублировало
> бы одинаковые правила 17 раз** — увеличение CSS вместо уборки.

Чтобы разветвление имело смысл, под именем должны лежать разные сущности.
Под `.top` и `.site-title` лежит одно: контейнер шапки и заголовок внутри
него. Расхождения в кегле — это настройка страницы под себя, а не
следствие неоднозначного имени.

Это же отличает их от классов, которые действительно пришлось
переименовать:

| класс | что не так было | что стало |
|---|---|---|
| `.tab` | рядом `.tabs` и `.table` | разведены по именам |
| `#graph` | два **разных элемента** под одним id | разведены по id |
| `.layout` | два **разных правила** под именем | разведены по именам |
| `.top`, `.site-title` | ничего | **оставлены** |

### 4.5 Бонус: пункт плана был невыполним

В плане стояло «`.top` + `.site-title` — **свести к одному**». Это
невозможно:

- `.top` — это `<header>`, контейнер шапки
- `.site-title` — это `<div>` **внутри** него, с названием сайта

Разные элементы на разных уровнях вложенности. Объединить их в один класс
нельзя, не сломав шапку. Замер это и показал, поэтому пункт заменён
решением «оставить оба», а не переименованием.

Коммит без первых трёх упал бы на CI. `ROADMAP.md` — не техническая

## 8. Ошибки этого захода

Три, все пойманы проверками.

**1. Якорь в ROADMAP не нашлось: разделитель таблицы прочитан неверно.**
Строка `|---|---|--:|--:|` выглядит в искажённом выводе консоли как
`|---|---|--:|---|`, и я переписал её по памяти. Нашёл сравнением строк
по позициям. Последний столбец тоже выровнен вправо.

**2. Проверка однородности `.site-title` объявила структуру
неоднородной из-за дедушки.** Критерий считал полную цепочку родителей,
а различались только `div.wrap` между `header.top` и `body` — это вёрстка
вокруг заголовка, а не разные сущности. Критерий переписан на то, что
определяет сущность: тег, непосредственный родитель, число ссылок.

**3. Проверка гейта ждала код 0, а гейт возвращает 5.** Код 5 —
«ничего не собрано», то есть ровно нужное поведение. Ошибка была в
проверке, а не в гейте; заменено на смысловой признак.
