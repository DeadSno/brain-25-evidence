## 3. Проверки перед переносом

Перенос правила из локального `<style>` (грузится **после** `style.css`) в
`style.css` (грузится **до**) делает правило **более ранним** в каскаде. Оно
может начать проигрывать равному по специфичности правилу, которое раньше
перебивало. Проверено в обе стороны:

**1. Конкурентов в `style.css` нет.** Ни один токен ни одного из 29 селекторов
не встречается в `style.css` до переноса. Специфичность при этом не меняется:
id остаётся id, то есть `#atl-sidebar` = (1,0,0), `#atl-sidebar .badge.A` =
(1,2,0).

Для полноты проверены и элементы, которые задевают эти правила — `h2`, `h3`,
`ul`, `li`, `aside`. В `style.css` для них есть правила с максимум (1,1,1), но
все они под другими предками (`#modal h2`, `#qaSection .qa h3`,
`#trustSummary li`, `.sb-links li`) и на элементы сайдбара не попадают.
`aside` в `style.css` не упомянут ни разу.

**2. Оставшихся локальных правил, делящих свойства, нет.** Это и есть та проверка,
которую стоило сделать первой: правило может проиграть не `style.css`, а
соседу в том же блоке. Сравнениеproperty-by-property по обеим страницам:

```
interactions: 7 переносимых, 54 остаются — общих свойств 0
atlas:        22 переносимых, 54 остаются — общих свойств 0
```

Ни одно оставшееся локальное правило не делит ни одного свойства с
переносимыми, поэтому порядок в каскаде на результат не влияет.

## 4. `@media` сохранены

Задача предупреждала: потеря `@media` ловится только на одной ширине. Round-trip
сверка числа контекстов до и после:

```
@media/@supports до: 2   после: 2   совпадают
@supports (padding: env(safe-area-inset-bottom))
@media (max-width: 640px)
```

Перенесено по 3 правила в `@media (max-width: 640px)` и 1 в `@supports` на
каждую страницу — 8 контекстных правил из 29. Остальные 21 базовые.

Сверка количества после записи:

```
atlas.html:         локальных правил 54, из них про сайдбар 0  (ожидалось 0)
interactions.html:  локальных правил 54, из них про сайдбар 0  (ожидалось 0)
style.css:          правил про сайдбар 29                      (ожидалось 29)
```

Скрипт переноса **отказывается писать**, если число замен разошлось с
ожидаемым, и после записи проверяет каждое из трёх чисел.

Ровно то, что должно быть. Проверка на будущее: **хирургический вырез не

Порядок, который даёт наибольший выигрыш дальше:

   тем же приёмом, что и `#sidebar`.
2. **`.layout`** — 6 правил, обращений из JS нет вовсе.
3. **`.top` + `.site-title`** — 39 и 24 варианта правил на 7 страницах. Сначала
   свести к одному правилу, потом переименовывать.
4. **`.btn`** — 172 вхождения и скрипты на 4 страницах, последним.

Шаги 6-9 (цвета, `:root`-переменные, `body`/`header`) требуют отдельного
решения: это не перенос, а изменение палитры, и снапшоты там будут падать
всеми 37 сразу — что правильно, но означает другой формат работы.
