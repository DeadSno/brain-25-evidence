## 3. Главная находка: «точные дубли» меняли каскад

Первая версия скрипта удаляла правило, если его тело совпадает с `style.css`.
Снапшоты сразу показали: **`atlas@1280` упал**. Замер `getComputedStyle` до и
после дал причину:

| Свойство | было | стало |
|---|---|---|
| `.top` margin-bottom | 16px | **9,6px** |
| `.top .site-title` font-size | 21,6px | **20,8px** |
| `.top .site-title` margin | 0px | **3,2px** |

Причина: на `atlas` (и `map`) локальные «дубли» стоят **после** страничных
правил и потому **выигрывают каскад**. Например на `atlas`:

```
.top { … margin-bottom:.6rem }          ← страничная
.top { … margin:0 0 1rem }              ← «дубль», стоит позже и побеждает
```

«Дубль» не был no-op — он перекрывал страничное правило. Его удаление отдавало
победу обратно первому правилу, то есть меняло отступы и кегль.

**Отсюда правило, добавленное в скрипт:** правило считается дублем только если
для его селектора **нет второго тела** в том же медиаконтексте. Сравнение
намеренно грубое — по всему телу, а не по свойствам: первая версия сравнивала
свойства поимённо и пропустила пару `margin-bottom` / `margin`, потому что это
одно свойство в двух нотациях. Снапшоты поймали и это.

## 6. Порог снапшотов: было 0.0, стало 0,05%

Заявление в задании — «порог 0,05%, не strict». В репозитории стояло
**`DIFF_TOL_PCT = 0.0`**. Поставил 0,05%.

Основание — замер, а не осторожность. При 0 на `index@1280` **первый** снимок в
холодном браузере расходился с эталоном на **0,0266%** (5011 пикселей, дельты
8…136 из 255 по краям глифов), а следующие девять — ровно ноль:

```
0: 0.0266%  px=5011  FAIL
1..9: 0.0000%  px=0  ok
```

Это субпиксельный дребезг сглаживания, и при нулевом пороге он давал ложные
падения. Проверено, что 0,05% ловит настоящие правки: фиктивный
`body{padding:1px}` роняет **27 снимков из 37**.

⚠️ Замечание по предыдущей сессии: в отчёте я писал, что «откатил порог на
0,05%», но правки в файл не внёс. Сейчас исправлено фактически.

## 7. Две ошибки в моём же скрипте (пойманы до коммита)

1. **Склейка соседних селекторов.** Первая версия редактировала текст на месте и
   склеивала `.top .site-title` из двух правил, плюс сносила посторонние
   (`.btn`, `.kpis`, `#graph`). Поймано dry-run-проверкой «0 добавлений».
2. **Грубая уборка пробелов.** `re.sub(r"[ \t]+\n", …)` тихо правил пробел в
   конце строки внутри комментария на `interactions.html`. Убрано; теперь
   трогается только созданное мной.

Обе нашлись только потому, что dry-run сравнивал **мультимножества полных
тройок (селектор, медиаконтекст, тело)**, а не ключи.
