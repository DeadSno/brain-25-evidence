## 1. Механизм: откуда `#8ecbff`

Обычный и полностью объяснимый: **`body.dark a { color:#8ecbff }`** в
`style.css`.

```
docs/style.css:548   body.dark a{color:#8ecbff;text-decoration:underline}
```

Дальше — почему это выглядело загадкой, и почему загадкой не было.

### 1.2 Что происходит на самом деле

Страница принудительно тёмная, пока в `localStorage` не записано ровно
`'light'`:

```js
// graph.html, инлайн-скрипт 1 (в <head>, до загрузки CSS)
if (localStorage.getItem('theme') !== 'light') {
  document.documentElement.classList.add('dark');
}
// инлайн-скрипт 2
if (localStorage.getItem('theme') !== 'light') {
  document.body.classList.add('dark');
```

**`prefers-color-scheme` эта проверка не читает вообще.** Эмуляция светлой схемы
не даёт светлой темы — скрипт всё равно ставит `.dark`.

Воспроизведено ровно то, что делает пассивный аудит: `colorScheme: 'light'` +
пустой `localStorage`.

| Страница | `body.class` | `#8ecbff` |
|----------|--------------|-----------:|
| index | **dark** | ×11 |
| **graph** | **dark** | **×10** |
| atlas | dark | ×10 |
| map | dark | ×11 |
| interactions | dark | ×10 |
| calculator | dark | ×10 |
| trends | dark | ×12 |
| methodology | dark | ×11 |
| faq | dark | ×11 |
| glossary | dark | ×11 |
| feedback | dark | ×11 |
| support | dark | ×11 |

**Все 12 страниц**, не только `graph`. `graph` при этом даже не максимум —
`trends` даёт 12.

Тот же замер при `localStorage.theme = 'light'`, выставленном **до** загрузки:

```
graph / theme=light ДО load → body.class=(нет)  a.btn.c-home = rgb(28,28,30)  #8ecbff = 0
index / theme=light ДО load → body.class=(нет)                                    #8ecbff = 0
```

Светлая тема — **ноль** вхождений. Проверено и снятием класса на живой странице:
`.dark` снят → `#8ecbff` = 0, цвет `rgb(28,28,30)`.

### 1.3 Почему именно эти элементы

Аудит записал `a.btn.c-home ; a.btn.c-calc ; a.btn.c-mech`. Это навбарные
кнопки, и в тёмной теме их красит именно `body.dark a`:

```
a.btn.c-home → body.class=dark → computed rgb(142, 203, 255)
```

 specificity: `body.dark a` = (0,1,1) против `.btn { color: var(--text) }` = (0,1,0) — тёмная тема выигрывает;
в светлой `body.dark` не подходит, остаётся `.btn{color:var(--text)}` = `#1c1c1e` = `rgb(28,28,30)`.

То есть «9 вхождений `a.btn.c-*` в светлой теме» — это «9 вхождений
`a.btn.c-*` **в тёмной** теме», которые в тёмной теме и должны быть
`#8ecbff`.

### 1.4 Откуда тогда «0 на 5 страницах»

`localStorage` общеперсистентный для origin. Как только аудит записал
`theme='light'` хоть раз, все следующие страницы в том же контексте грузились
реально светлыми и давали 0. `graph` оказался измерен **до** этой записи — в
свежем контексте, где `localStorage` пуст.

Проверяемо: тот же аудит записал «DARK 12 страниц ×11-13» — те двенадцать
считались тёмными, и это правда, а «светлый graph» был девятым замером в
неинициализированном контексте.

## 4. Решение

**Правок в коде не требовалось** — и не потребовалось. Блокер был артефактом
аудита, а не свойством сайта.

`--accent-2` применён 2026-10-03: объявлен **только в тёмной ветке**
(`html.dark, body.dark`) со значением `#8ecbff`, 15 вхождений в `body.dark`
заменены на `var(--accent-2)`. Проверено слепком всех вычисленных цветов,
17 страниц × 2 темы — **0 различий из 34**. Отчёт: `reports/STEP8_FINAL.md`.

### Что предлагаю сделать — по отдельному решению владельца

**A. Починить измеритель тем (блокирует любые будущие цветовые аудиты).**
Тема переключается через `localStorage.theme`, а не через `prefers-color-scheme`.
Замер должен ставить `theme='light'` **до** загрузки и проверять, что
`document.body.className` действительно пуст, иначе — не считать замер
светлым. Одно поле, но без него любой следующий аудит повторит ошибку.

**B. Пересчитать `--accent-2` по-настоящему** — в светлой теме он, судя по
замерам, не нужен вообще. Если так, токен становится **одноцветным для тёмной
ветки** и применяется как `--border-hover`/`--accent-hover` — то есть без
риска. Снимки должны остаться зелёными, а проверить надо и в тёмной, и в
светлой.

**C. Перепроверить `#f1c40f` (52 вхождения в светлой по аудиту)** — после A.
Это самая дорогая находка из двух, и она держится на том же замере.

Ничего из этого **не применено** — по условию задачи.

## 5. Ограничения этого расследования

- Переключение света/тьмы проверялось через `localStorage`, а не через
  `prefers-color-scheme`. Это не побочный эффект: скрипт страницы
  `prefers-color-scheme` не читает.
- Первые замеры этой сессии попали под **service worker** — он отдавал
  `style.css?v=405` из precache, и `--border-hover`/`--accent-hover` были
  не видны. Все числа выше — после сноса SW и `cache: 'no-store'`.
- В процессе один замер дал ложное «цвет остался `#8ecbff` после снятия
  класса». Контрольный повтор с явным ожиданием 1200 мс дал 0 вхождений, то
  есть аномалия — артефакт перехода (`transition: color 0.15s`) в headless.
  На выводы это не влияет: решающие замеры сделаны по свежей загрузке, а не
  снятием класса на живой странице.
- 18 страниц не проверял — 12 снапшотных покрывают вопрос; `sup/*` используют
  тот же `style.css` и не имеют собственных правил для ссылок.
