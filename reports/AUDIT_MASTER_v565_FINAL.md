### SEO-01 — план реализации (фикс в 5.6.5)

Цель: у каждой контентной страницы появляется второй адрес `/en/…`, обе версии
ссылаются друг на друга через `hreflang`, поисковик видит английский HTML без
выполнения JS.

**Почему нельзя иначе.** GitHub Pages — статика, SSR нет. Вариант `?lang=en` или
переключение по cookie поисковик не индексирует как отдельный документ, поэтому
`hreflang` на него не сослаться. Остаётся генерация второго дерева файлов.

**Что генерируем.** 141 EN-страница: 10 контентных корневых (`index`, `faq`,
`feedback`, `glossary`, `methodology`, `privacy`, `support`, `terms-of-use`,
`trends`, `hactar`) + `sup/index.html` + 130 карточек. Раскладка — зеркальная:
`docs/en/index.html`, `docs/en/sup/<slug>.html`. `404.html` и `offline.html`
остаются только на русском (`noindex`, в sitemap их нет), 6 заглушек-редиректов
EN-версий не получают.

**Шаги.**

1. `scripts/build_en.py` — новый генератор, два разных механизма под два типа
   страниц:
   - **карточки (131 файл)** — не переписывать готовые файлы, а прогнать уже
     существующий `scripts/build_sup.py` с `--lang en --out docs/en/sup`.
     `templates/sup.html.j2` и `templates/sup_index.html.j2` получают переменные
     `page_lang`, `og_locale`, `canonical_url`, `alternate_urls`; данные берутся
     из `docs/data_en.json` (паритет 130/130 уже есть), контекст собирает тот же
     `build_context()`. Это идемпотентно и не даёт дрейфа шаблона — тот же урок,
     что с `?v=` в `style.min.css`.
   - **10 корневых страниц** — они написаны руками, шаблонов нет. Переводим
     DOM-перезаписью через `lxml` (6.1.3 в venv): подставляем значения
     `data-i18n*` из словаря, `data-i18n-vars` — с подстановкой `{vars}`,
     затем правим `<html lang>`, `<title>`, `meta[name=description]`,
     `og:*`, `twitter:*`, `canonical`, `og:url` и относительные ссылки на
     ассеты (у `/en/` глубина другая). Словарь берём не регэкспом, а из
     браузера: `page.evaluate(() => JSON.stringify(I18N))` → `docs/i18n_dict.json`

2. **Свитчер.** `#langSelect` перестаёт быть «переводчиком на месте» и становится

   на EN-странице — обратно. `localStorage['lang']` остаётся как подсказка для
   RU-страниц и для первого визита.
3. **Ловушка приоритета локали.** Сейчас `LOCALE = localStorage['lang'] ||
   <html lang> || 'ru'` (`docs/i18n.js:80+`), то есть пользователь с
   `localStorage.lang='ru'` на `/en/index.html` получит русский текст на
   английском URL. Нужен принудительный выбор по пути: `/en/` → всегда `en`.
   Изменение этой строки ломает `tests/test_i18n_locale.py` (он пин-кодит
   `LOCALE = document.documentElement.lang || 'ru'`) — тест правится в том же
   батче.
4. **`hreflang`.** На каждой паре три `<link rel="alternate">`: `ru` → RU-URL,

   `lastmod` для EN берётся из того же источника, что и для RU.
6. **`robots.txt`.** Правок не нужно: `Allow: /` покрывает `/en/`, `Sitemap:`
   уже указан. Заглушки не индексируются через `noindex`, а не через `Disallow`
