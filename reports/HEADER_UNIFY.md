# Шапка — унификация: аудит без правок

Ветка `v5.6-dev`, якорь `6839c5a`. Рабочее дерево чистое — **ни один файл
не изменён**, кроме этого отчёта.

**Остановился по правилу из задания:** «если есть сомнение в эталонном
наборе кнопок — СТОП, вынести в отчёт как вопрос. Не угадывать». Сомнение
не теоретическое: замер показал, что расхождение между страницами
**системное и осмысленное**, а не случайное. Унификация «к самому
полному набору» уничтожила бы эту логику.

---

## Почему СТОП — три причины

1. **Расхождение в кнопках намеренное.** На каждой внутренней странице
   отсутствует ровно одна кнопка — та, что ведёт на неё саму. Это
   самоссылка, а не ошибка. Полный набор означал бы «на главной есть
   ссылка на главную».
2. **Эталон из задания противоречит замеру.** В постановке сказано
   «map.html — 9 кнопок (без Светлая тема)», но на `map.html` кнопка
   темы **есть** — она на всех 13 проверенных страницах. Расхождение
   в 1 кнопку, и это меняет вывод о том, что именно чинить.
3. **Найдена настоящая поломка, и она не про кнопки.** Два липких блока
   подряд перекрывают друг друга; логотип в шапке прячется под плашкой.
   Это стоит чинить независимо от вопроса о кнопках.

## Часть B1 — эталонный набор кнопок

### Что предлагало задание

> Главная, Калькулятор, Механизмы, Связи, Атлас, Тренды, BI, Граф связей,
> Обратная связь + Поддержать, Светлая тема

Это 11 кнопок. Замер: полный набор из 11 есть на трёх страницах —
`methodology`, `faq`, `glossary`. То есть предложенный «эталон» это
существующее поведение, а не новое.

### В чём проблема с переносом на все 143

Если поставить 11 кнопок везде, появятся самоссылки:

| Страница | Стало бы | Реальная целевая |
|---|---|---|
| `atlas.html` | Атлас → atlas.html | пользователь уже на ней |
| `trends.html` | Тренды → trends.html | то же |
| `index.html` | Главная → index.html | то же |
| `sup/kreatin.html` | +6 кнопок | шапка вырастет с 47 до ~152px |

Для 130 страниц `sup/` это +6 кнопок каждая. На 412px шапка сейчас
136px в две строки; после изменения станет 229-280px, как у `map.html`
сейчас. Увеличение липкой шапки на 130 страницах съедает экран и усиливает
ту самую проблему перекрытия, которую эта задача чинит.

**Вывод: «эталон = самый полный» неприменим без исключения для текущей
страницы, а это уже не унификация, а новая навигационная модель.**

### Рекомендация

Не трогать состав кнопок. Причина расхождения — не баг, а самоссылочная
логика, и она читается правильно: «вы здесь». Унифицировать нужно CSS
(часть B2), где расхождение настоящее.

## Часть B2 — эталонный CSS: где расхождения

### Где объявлен `.top`

**style.css:991** — единственное базовое правило:

```css
.top {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: var(--space-4);
  flex-wrap: wrap;
  margin: 0 0 var(--space-4);
}
```

**Ключевая находка:** здесь **нет** `position: sticky`. Липкость приходит
из другого правила — `style.css:298`:

```css
header, .header {
  position: sticky; top: 0; z-index: 50;
  backdrop-filter: blur(12px);
  padding-top: env(safe-area-inset-top, 0px);
}
```

Селектор `header, .header` бьёт все `<header>` без разбора. То есть липкой
шапку делает не `.top`, а «любой хедер» — неявное правило вместо
задуманного контракта.

### Локальные `<style>` с `.top`

| Страница | Правил | Характер |
|---|:---:|---|
| `index.html` | 8 | 4 в `@media (max-width:640px)`, включая `padding-top` |
| `map.html` | 6 | дубли базовых + mobile |
| `atlas.html` | 7 | дубли + `body.fs .top{display:none}` — полноэкранный режим |
| `calculator.html` | 2 | mobile |
| `trends.html` | 7 | **`position:static!important`**, свой gap, высота кнопок |
| `interactions.html` | 2 | mobile |
| `feedback.html` | 4 | дубли + mobile |
| `graph`, `methodology`, `faq`, `glossary`, `support` | 0 | чистые |

Многие из этих правил — дословные копии `style.css`: страницы тащат с
собой уже вынесенное в общий файл.

### Инлайн-стили и модификаторы

- `style="..."` на `<header class="top">`: **0** на всех 13 страницах.
- Модификаторы `.top-*` (`.top--sticky` и подобные): **не найдено** ни
  в `style.css`, ни в разметке.

### Два липких блока подряд — настоящая поломка

`.trustbar` (`style.css:417`): `position: sticky; top: 0; z-index: 100`.
`.top` — через `header`: `position: sticky; top: 0; z-index: 50`.

Оба липнут к `top: 0`, и плашка с `z-index: 100` перекрывает шапку с
`z-index: 50`. Подтверждено скриншотом `methodology.html` при
`scrollY=600`: логотип «brain-25-evidence» **не виден**, первым
отрисовывается `div.trustbar`.

Замер по 25 комбинациям (5 страниц × 5 вьюпортов) при `scrollY=600`:

| Метрика | Значение |
|---|---|
| Комбинаций с перекрытием | **11 из 25** |
| Скрытых кнопок всего | **39** |
| Худшие случаи | `atlas@1920` — 10 из 10, `index@1280` — 4 из 4 |
| Тач-таргеты < 44px на 320/412 | **0** |
| Перекрытия между кнопками | **0** |
| Кнопки вне вьюпорта | **0** |

### Оценка трёх вариантов, снято в рантайме

Файлы не трогал — стили подставлялись через `add_style_tag`, чтобы
показать последствия числами, а не ощущением.

| Вариант | Скрыто кнопок | Видно кнопок | Плашка видна |
|---|---:|---:|:---:|
| **C** базовая (сейчас) | 39 | 140 | 25/25 |
| **A** `.top { position: static }` | 0 | **0** | 25/25 |
| **B** `.top { position: sticky; top: 35px }` | 0 | **140** | 25/25 |

Вариант A убирает перекрытие, но **убирает шапку с экрана совсем** —
видно 0 кнопок, навигация при прокрутке исчезает. Это не унификация, а
потеря функции.

Вариант B сохраняет и плашку, и шапку: 140 видимых кнопок, 0 скрытых.
Но `35px` — зашитая высота плашки; при переносе текста на мобильном
она вырастет и снова начнёт перекрывать.

**Это тоже требует решения владельца**, а не молчаливого выбора между
двумя способами что-то сломать.

### Про `trends.html`

Единственная страница с `position: static` — из-за локального
`position: static !important`. Она же единственная, где перекрытия нет
при прокрутке. То есть расхождение, которое задание описывает как
«10 кнопок у trends против 9 у map», симптомом не является: у `map`
кнопок не меньше, а перекрытие есть у обеих.
