## 1. local-fast на instruct: работает

### 1.1 Что закреплено

```jsonc
"agents": {
  "local-fast": {
    "description": "Лёгкий локальный исполнитель: поиск, чтение, разбор. Использовать для простых задач.",
    "mode": "subagent",
    "model": "ollama/qwen-instruct-top:latest"
  }
}
```

Синтаксис проверен: `ConvertFrom-Json` — OK.

### 1.2 Проверка делегирования

Задача выполнялась **через агента из конфига**, без подмены модели в
вызове — то есть ровно так, как будет работать в обычной сессии.

| Проверка | Ожидание | Факт |
|---|---|---|
| «прочитай `docs/version.json`, скажи `app`» | `app: 5.6.1` | ✅ `app: 5.6.1` |
| «все ключи + `data` + `tests`» | 4 ключа, `2026-09-25`, `989` | ✅ совпало |

Значения неугадываемые (`989`, `2026-09-25`), ответ совпадает с реальным
файлом — модель прочитала файл, а не угадала.

### 1.3 Важная деталь про селектор

Без тега модель не резолвилась:

```
Model unavailable: ollama/qwen-instruct-top
```

С тегом — работает. В конфиге должно быть
**`ollama/qwen-instruct-top:latest`**, иначе агент падает на запуске.
Это же объясняет, почему в примерах документации селекторы выглядят как
`ollama/gemma3:4b`: тег `:latest` подставляется не всегда.

## 3. Модели: размеры и рекомендации

### 3.1 Реальное потребление места

`ollama list` показывает **4.7 GB на каждую из четырёх моделей** — это
размер общей модели, а не реальное потребление. Замер по диску:

```
~/.ollama/models  →  8.72 GB   всего
blob-ов > 100 MB  →  ровно 2, по 4466 MB каждый
```

Производные модели весят **0 МБ сверх базы**: их манифесты — отдельные
blob'ы нулевого размера, все слои переиспользуются.

| Модель | Роль | Своё место на диске |
|---|---|---|
| `qwen2.5:7b-instruct` | база instruct | ~4.4 GB |
| `qwen2.5-coder:7b` | база coder | ~4.4 GB |
| `qwen-instruct-top` | **агент** | ~0 |
| `qwen-coder-top` | нерабочая как агент | ~0 |

### 3.2 Главный вывод по удалению

**Удаление `qwen-coder-top` не освободит практически ничего.** Он
переиспользует слои `qwen2.5-coder:7b`; удаление одного лишь производного
модели оставит базу на месте.

Освободить ~4.4 GB можно только парой:

```powershell
ollama rm qwen-coder-top qwen2.5-coder:7b
```

### 3.3 Рекомендации

| Модель | Решение | Обоснование |
|---|---|---|
| `qwen-instruct-top` | **оставить** | рабочая модель агента |
| `qwen2.5:7b-instruct` | **оставить** | база instruct-top; удаление может сломать производную |
| `qwen-coder-top` | **оставить** (по умолчанию) | занимает 0 МБ; годен для ручных запросов по коду вне агента. Проблема только в tool calls |
| `qwen2.5-coder:7b` | на усмотрение | удалять только вместе с `qwen-coder-top`, ради ~4.4 ГБ |

**Ничего не удалено** — по правилу задания (C3). Решение за владельцем.

### 3.4 Про coder-варианты

`qwen-coder-top` как агент бесполезен — установлено в
`LOCAL_DELEGATION.md`. Для ручных запросов он остаётся пригоден: там
инструменты не нужны, нужен только текст, а код он пишет лучше instruct.
Поэтому рекомендация — оставить, а не удалять: места не занимает, а
задачу «спросить у локалки про код вручную» закрывает.
