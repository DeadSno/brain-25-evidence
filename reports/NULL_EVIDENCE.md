# NULL_EVIDENCE — почему поле пустое (v5.6.5, 19.10.2026)

Этот файл заменяет версию из коммита `45e7ed2`, которая утверждала, что данные
«зафиксированы», хотя два скрипта (`scripts/fill_citations.py`,
`scripts/fill_forms.py`) записывали **выдуманные** значения. Оба скрипта
удалены, выдуманные значения откатаны.

Правило этого файла: для каждого `null` указано, **где именно искали** и что
именно нашли (или не нашли). Формулировок «зафиксировано» и «данных нет» без
источника здесь нет.

## 1. `citations` — это ЧИСЛО, а не библиографическая строка

`45e7ed2` записал в `citations` карточки «Омега-3» строку:

```
"The Cochrane database of systematic reviews — 2020 — PMID:32114706 — NLMID:100909747"
```

Это регресс типа: в остальных 129 записях `citations` — `int`
(например, Креатин 119, Витамин D 212, B12 251, Магний 590).

Чем доказано, что поле числовое:

* `scripts/fetch_metrics.py` (docstring): «citations — сумма `cited_by_count` по
  всем `key_sources` карточки (OpenAlex)», CLI `--only {wiki,citations,ongoing}`.
* Потребители читают его как число:
  `scripts/build_graph_data.py:58` — `c = rec.get("citations") or 0` (размер
  узла графа); `scripts/canonicalize_graph_data.py:57,109` — `size_of(...)`;
  `tests/test_build_timeseries.py` — суммы для KPI на `docs/trends.html:516-517`.
* `data/timeseries/citations.json` — по-годовые ряды для всех 130 id.
* Коммит `5e9c17a` («Omega-3 null not false 0», DATA-P2-03/07) сознательно
  оставил у Омега-3 `null`, потому что истинное число цитирований — 0, а `null`
  не должен смешиваться с ложным нулём.

Дополнительно: сумма ряда `data/timeseries/citations.json` для Омега-3 = **0**
за 11 лет — то есть `null` у этой карточки обоснован, а не потерян.

**Почему нельзя было «построить citation по PMID из nlm_catalog»** (как
предполагала задача): `data/journals/nlm_catalog.json.gz` содержит метаданные
**журналов**, а не цитирования по PMID. Ключи: `by_title` (37 908),
`by_abbrev` (38 048), `by_issn` (0), `_meta`. То есть каталог позволяет
сопоставить «журнал → NLMID», но не даёт числа цитирований.

Проверка покрытия (для протокола): в `key_sources` **373 уникальных PMID** и
**211 уникальных журналов**; после приведения к нижнему регистру (ключи
каталога в нижнем регистре) резолвится **208 из 211** (182 по `by_title`,
44 по `by_abbrev`). Не резолвятся 3: `Advances in nutrition`,
`Journal of clinical oncology`, `Phytotherapy research` — в NLM они называются
иначе (например, «Advances in nutrition (Bethesda, Md.)»).
Вывод: NLMID собрать можно, число цитирований — нет.

**Итог по citations: 129/130. Единственный `null` — «Омега-3», по делу**
(`5e9c17a`), сумма по-годового ряда = 0.

## 2. `forms` — это ФОРМА ВЕЩЕСТВА, а не «капсулы/таблетки»

`45e7ed2` записал 83 значения вида `капсулы` (60), `порошок` (12),
`таблетки` (10), `жидкость` (1). Это не форма вещества и ломает логику сайта:

* Подпись в UI — «Формы/штаммы» (`modal.forms`), «Формы» (`cmp.table.forms`),
  «Формы выпуска» (`<h2>` на страницах `docs/sup/*.html`).
* `scripts/build_sup.py:352-362` строит `shop_query = name + " " + first_form`,
  где `first_form` — первый сегмент до `;—–` (`:379-380`). С выдуманным
  значением получается запрос «Магний капсулы» вместо «Магний цитрат».
* `docs/script.js:192` — `s.forms.split(/[;—–]/)[0]`; `:141` — `forms`
  участвует в списке «чего не хватает в карточке».
* Легитимные значения (47 до фальсификации): `моногидрат`, `цитрат, глицинат`,
  `D3 (холекальциферол)`, `MK-7, MK-4`, `метилкобаламин, цианокобаламин` и т.п.

### Как заполняли сейчас (95/130)

Значение ставилось **только** при наличии дословной цитаты в той же карточке
(`how_to_choose` / `caution` / `about` / `dosage` / `course`). Скрипт
`_tmp_fill.py` / `_tmp_fill2.py` падал, если цитата не находилась, — поэтому
ни одного значения «по догадке» нет.

**Итог по forms: 95/130.** Остальные 35 — либо в карточке прямо сказано, что
