## P1

### P1-1. Поле `with` в `interactions`: четыре разных значения-заглушки

**51 из 199 строк (25.6%)** означают «взаимодействий нет», но закодированы четырьмя
разными способами:

| Значение | Строк | id |
|---|---:|---|
| `"нет данных"` | 32 | B1, Холин, EPA, Витамин A, B2, B3, B5, B6, Лизин, Кремний, HMB, Карнозин, Молибден, Витамин K1, Ниацинамид, Цистеин, S. boulardii, LGG, B. lactis, DHA, GLA, Медь, Марганец, Бор, Бетаин, Метионин, Орнитин, Майтаке, PABA, Пролин, Серин, Аланин |
| `""` (пустая строка) | 10 | Фосфатидилсерин, Alpha-GPC, CDP-холин, Готу кола, Бузина, Мака, Хром, Шатавари, Глутатион, PQQ |
| `"—"` (тире) | 9 | 7 с note «нет известных взаимодействий», 2 с «мало данных, нет известных взаимодействий» |
| (плюс note) | — | note тоже варьируется тремя формулировками |

**Почему P1:** любой потребитель данных обязан знать все четыре заглушки, иначе фильтр
по `with` молча пропустит 25% взаимодействий. Пустая строка уже уехала в аналитику:
в DuckDB `interaction` 10 строк с пустым `with_target` — их не отличить от «нет данных»
запросом по имени.

**Что не сломано:** рендер. Шаблон печатает только `note`, поэтому на странице
корректно выводится «Взаимодействия: Известных взаимодействий нет». Дефект чисто
в данных и в их потреблении.

### P1-2. `timeseries.json` не покрывает 19 карточек, у которых `citations > 0`

- В `data.json` поле `citations` заполнено у **113** карточек, серия в `timeseries.json`
  есть только у **94**.
- Без кривой: B1, B2, B3, B5, B6, EPA, HMB, Витамин A, Витамин K1, Женьшень, Йод,
  Карнозин, … (19 всего).
- **Почему P1:** на страницах трендов у этих карточек **есть число, но нет кривой** —
  это видимая нестыковка в интерфейсе, а не только в данных.
- Для сравнения: покрытие `ongoing` — 94/94, `wiki` — 90/90, полное.

## Ложные срабатывания, отсечённые до отчёта

По правилу верификации скилла («данные: запрос к файлу, не к памяти») четыре
находки не попали в список — каждая была воспроизведена и опровергнута:

| Что показала первая проверка | Почему это ложь |
|---|---|
| «Поля отсутствуют на 52 страницах» (caution 18, food_sources 10, dosage 3 …) | Значения есть, но **HTML-экранированы** в исходнике (`&amp;`, `&#945;`). Сравнение по тексту страницы даёт 0 промахов |
| «10 взаимодействий без `with`» как поломка рендера | Шаблон печатает только `note` — пользователь видит корректный текст. Как проблема данных — реальна (P1-1), как баг UI — нет |
| «Расхождение `Связей: N` в 128 узлах графа» | **Ошибка самого скрипта**: считались только исходящие рёбра. С обоих концов совпадает 128/128 |
| «`hedges_g_ci: null` выводится как null на странице» | CI **вообще не рендерится** на sup-страницах: 0 вхождений «CI» и «95%», в `templates/sup.html.j2` ссылки на `ci` нет |

Три ловушки в самих скриптах, которые пришлось обойти (записано, чтобы не повторить):
`edges` в `graph_data.json` — это формат vis.js (`from`/`to`, не `source`/`target`);
степень узла считается по обоим концам ребра; `timeseries.json` — это dict `{год: значение}`,
а не список, и «последнее значение» = `list(values)[-1]`, а не `values[0]`.

**Ловушки этой проверки, на будущее:**
- `print()` в stdout не годится для кириллицы и JSON — отчёты пишутся в UTF-8-файл
  и читаются оттуда.
- Кириллические литералы в `.py`, записанные Write-тулом, иногда приходят битыми
  (KeyError). Надёжнее сравнивать по уже загруженным данным, чем по хардкоду имён.
- Скрипты перезаписывают один общий `out.txt` — старый вывод нельзя читать после
  следующего прогона.
