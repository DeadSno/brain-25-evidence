## 3. Находки P1

### DATA-P1-1 — `src/config.py:6-81`: 56 карточек потеряют `ma_top3` при повторном прогоне

**Что не так.** Словарь `SUPPLEMENTS` в `src/config.py` содержит **74** записи. В `docs/data.json` ключ `ma_top3` заполнен у **80** карточек, из них **56** не имеют запроса в конфиге.

**Доказательство.**
```
python -c "import json,sys; sys.path.insert(0,r'C:\analytics\brain-25-evidence');
from src.config import SUPPLEMENTS;
d=json.load(open(r'C:\analytics\brain-25-evidence\docs\data.json',encoding='utf-8'));
noq={r['name'] for r in d}-set(SUPPLEMENTS);
w=[(r['name'],len(r['ma_top3'])) for r in d if r['name'] in noq and r.get('ma_top3')]
print(len(SUPPLEMENTS), len(noq), len(w), sum(x[1] for x in w))"
→ 74 56 56 165
```
Кросс-таб «есть запрос в конфиге → состояние `ma_top3`»:
| | `absent` | `[]` | заполнено |
|---|---:|---:|---:|
| **запрос есть** (74) | 49 | 1 | 24 |
| **запроса нет** (56) | 0 | 0 | **56** |

Все 80 заполненных распределены ровно наоборот тому, что ожидает скрипт: 56 карточек с данными не имеют запроса, а 49 карточек с запросом данных не имеют.

**Механизм.** `scripts/build_key_sources.py:104-107`:
```python
q = SUPPLEMENTS.get(name)
if not q:
    s["ma_top3"] = []
    continue
```
Скрипт не дописывает, а **перезаписывает** поле. Прогон сейчас уничтожит 165 записей `ma_top3` у 56 карточек (Железо, Коллаген, Мелатонин, Хром, Цинк-подобные — весь «хвостовой» когорт).

**Почему это важно.** Это не «грязные данные», а **мина на будущее**: текущие `data.json` целы, но любой повторный прогон сборки тихо срежет 165 записей у трети карточек, а `git diff` покажет это как обычное уменьшение. Конфиг покрывает именно «хвостовую» когорту (`Йод`, `Молибден`, `Цистеин`…), тогда как данные есть у «головной» (`Железо`, `Коллаген`, `Мелатонин`) — то есть конфиг и данные расходятся не случайно.

### DATA-P1-2 — `docs/data.json`: `hedges_g_outcome` пустая строка у 42 карточек с полными данными

**Что не так.** Поле `hedges_g_outcome` объявлено у 86 карточек. У **42** из них значение — пустая строка `""`, при том что у всех 42 заполнены `hedges_g` и (у 41) `hedges_g_ci`.

**Доказательство.**
```python
sub=[r for r in d if r.get('hedges_g_outcome')=='']
print(len(sub),                                  # 42
      sum(r.get('hedges_g') is not None for r in sub),        # 42
      sum(r.get('hedges_g_ci') is not None for r in sub))      # 41
# пример: Омега-3 hedges_g=0.21, ci=[0.04, 0.38], outcome=''
#         Магний  hedges_g=-0.67, ci=[-0.89, -0.45], outcome=''
```
Из 86 карточек с ключом непустых значений только **44**.

**Важно.** Это **не** в списке пропусков базовой линии (`hedges_g_ci` 48, `ma_top3` 50, `citations` 18) — линия это поле не считала. Пропуск здесь другой по природе: данные есть, а подпись исхода не заполнена. Оба случая разделены:

| Поле | нет ключа | `null` | `""` | **нет значения** |
|---|---:|---:|---:|---:|
| `hedges_g_outcome` | 44 | 0 | **42** | **86** |

**Почему это важно.** «Исход» (`performance`, `sleep`, `bone`) — это то, что делает Hedges' g интерпретируемым: g=0.6 на «силу» и g=0.6 на «сон» — разные утверждения. 42 карточки отдают число без указания, к чему оно относится. Сейчас поле **не рендерится ни в одном `.js`/`.html`** (проверено `grep`), поэтому пользователя не вредит, но это мина при включении в UI. Словарь при этом распадается на почти-синонимы: `cognitive` (2) и `cognition` (1), `hba1c` (3) и `a1c` (1), плюс обрезанное `exercis` (2) — 23 уникальных значения против 44 непустых записей.

### DATA-P1-4 — `scripts/build_key_sources.py:59-62`: топ-3 мета-анализов не ранжирован по релевантности

## 6. Что НЕ является находкой (ложные тревоги)

Эти пункты выглядят как проблемы, но при проверке оказались штатным поведением. Проверено и снято.

1. **~90 ошибок `validate_proposal.py` на `reports/q14_batch_*.json` — не регрессия, не P0.** По решению владельца 19 файлов — исторические черновики proposals, валидации не подлежат. Ожидаемый результат.

2. **Мёртвые ключи `PRIOR_G` — не дефект.** `tests/test_content_module.py:109-120` документирует ровно три ключа (`L-теанин`, `Гинкго билоба`, `Родиола розовая`) и прямо пишет: «ПОЧЕРКУ НЕ ПРАВИМ … переименование ключей изменило бы грейды, видимые пользователю. Это продуктовое решение». Тест следит, чтобы список мёртвых ключей **не рос**. Поведение намеренное и защищено тестом.

3. **`source_sha256_16` в `data_index.json` расходится с `data.json` — ложная тревога (моя ошибка).** Первый замер дал `87ab0e48c91e3294` против заявленного `da320fd0dd99d90f`. Причина: файл в CRLF (14 337 `\r\n`), а `build_index.py:64` считает `DATA.read_text(encoding="utf-8")` — Python в текстовом режиме переводит `\r\n` в `\n`. С учётом перевода хэш **совпадает**: `da320fd0dd99d90f`. Контрольно — тот же хэш даёт `git show HEAD:docs/data.json`. **Отпечаток корректен.**

4. **`effects` в `data.json` ⊄ канонических 18 тегов — проверка неприменима.** `data.json.effects` — свободный русский текст («Боль при остеоартрите: эффект ≈ плацебо»), 160 уникальных значений. Канонические 18 живут в `effect_tags.json` (130 ключей, 18 тегов) и в таблице `effect_tag`, и **множества совпадают точно**. Подменять одно другим нельзя; расхождение в 160 vs 18 — это разные сущности, а не дрейф.

5. **`key_source.pmid` без строки в `paper` — 190 — не дефект.** Строки приходят из отдельного источника (мета-анализы, `fetch_papers.py`), в глобальный корпус статей они не попадают. Все 393 `key_source` строки валидны (`^\d+$`), DOI заполнены во всех, `year` без NULL и без будущих.

6. **`paper` без `key_source` — 37 420 — не сироты.** `paper` накапливает корпус целиком; статья может существовать без привязки к веществу.

7. **Годы `paper` вне 2000–2026 — не дефект.** `year < 2000` — 4 729 записей с минимумом 1926: легитимная старшая литература.

8. **Выбросы 3σ по `scienceIndex` — не плохие данные.** Порог μ+3σ = 7301.39 даёт ровно 4 записи: `Омега-3` (9791), `Витамин D` (9002), `Пробиотики` (10666), `Калий` (9614) — четыре крупнейших вещества. Фильтр находит большие вещества, а не ошибки.

11. **Пропуски `hedges_g_ci` 48 / `ma_top3` 50 / `citations` 18 — известная базовая линия.** Совпали до цифры, включая разбивку «нет ключа / null / иное пустое». Это зафиксированное состояние, не регрессия. Пропуск `hedges_g_outcome` (DATA-P1-2) в линии не был — потому он и вынесен отдельно.
