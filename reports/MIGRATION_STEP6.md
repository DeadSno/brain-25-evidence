## 2. Главное: имена `--space-2.5` из плана не работают в браузере

Это самая существенная находка шага, и она стоила 23 упавших снапшота.

**Имя кастомного свойства — это `--` + `<ident>`, а `<ident>` не может содержать
`.`.** Браузер выбрасывает такое объявление **молча**: ни ошибки в консоли, ни
признака в DevTools.

Изолированно воспроизведено:

```
:root{--space-2.5:10px;}     -> не разрешается, getPropertyValue пуст
:root{--a.1:4px;}           -> не разрешается
:root{--space-1:4px;}       -> 4px, работает
```

Дальше `var(--space-2.5)` подставляет пустоту, и **всё объявление** уходит в
invalid-at-computed-value-time. Дальше срабатывает каскад: правило с меньшим
приоритетом. Замерено на `index`:

```
button.tagPreset   padding: 3px 10px   ->  padding: 3px var(--space-2.5)
                   провалилось, сработало .btn -> 8px 16px
span.cat           margin-bottom: 3.2px -> 0px
strong.card-title  margin-bottom: 4.8px -> 0px
```

высота страницы **14129 → 14715px**, падали **23 снапшота из 37**.

`DESIGN_SYSTEM_PLAN.md` §2.1 предлагает `--space-2.5` и `--space-1.5` — в
браузере они не работают. Заменены на дефисные, названные по значению:
`--space-0-2` = 0.2rem = 3.2px, `--space-0-3` = 0.3rem = 4.8px,
`--space-2-5` = 2.5 × 4px = 10px.

**Мой первый тест на это был бесполезен.** Я назвал переменные `--bad-dot`, но
написал их с **дефисом**, а не с точкой, и убедился, что «точка работает».
Точку я по-настоящему не проверил ни разу. Помог только срез по правилам,
прочитанным из самого `style.css`.

## 3. Второе: `margin: 10` в JS — это не CSS

Первая версия прохода применяла замену ко **всему тексту файла страницы**, а не
к содержимому `<style>`. На `atlas` опции vis-network задаются объектом прямо в
`<script>`:

```js
margin: 10,                            ->  margin: var(--space-2-5),
size: 20 + Math.min(n, 5) * 3,         ->  size: var(--space-5) + ...
```

Результат в браузере: `PAGEERROR: Unexpected token 'var'`, скрипт не
выполняется, **граф не рисуется вообще**, atlas отваливался на 8.6% пикселей.

Починено двумя правилами:

1. Правится **только содержимое `<style>`**; `<script>` не трогается никогда.
2. **Голые числа отбрасываются.** В CSS без единицы допустим только ноль, так
   что `10` в spacing-объявлении — это либо опечатка, либо вообще не CSS.

Проверено: 0 вхождений `var(--space-` внутри `<script>` по всем страницам.

Отдельно: `node --check` даёт ошибки в 6 инлайн-скриптах (`offline` и пять
`sup/*`), и они **предсуществующие** — сравнение до/после даёт тот же самый
список и то же сообщение. Это шаблоны, а не регресс.

## 3.1. Третье: `offline.html` нельзя токенизировать

`offline.html` **намеренно не подключает `style.css`** — в коде страницы так и
написано: «чтобы не тянуть в кэш ещё один зависимый файл». Палитру он
объявляет сам.

Проход заменил там 7 литералов на `var(--space-*)`. Без объявления токенов
такие свойства падают в начальное значение — и страница ломается **тихо**: ни
ошибки в консоли, ни падения тестов, просто пустые отступы на офлайн-странице.

Страница исключена целиком. Это осознанное исключение, а не недосмотр, и оно
закреплено тестом.

## 4. Почему заменено 324, а не все 821

Задание требовало свести 29 значений к 9 ступеням и утверждало, что токены —
не визуальное изменение. **Эти два требования несовместимы**, и вот измерение.

Таблица §2.1 в плане написана **до** шагов 1–4. Сегодня в проекте:

| | План утверждал | Измерено |
|---|---:|---:|
| Различных значений отступов | 29 | **51** |
| Из них на шкале | 9 | **10** |
| Вхождений на шкале | ~545 | **298** |
| Вхождений вне шкалы | 176 | **521** |

План предлагает 13 «хвостовых» значений (6, 5, 7, 9, 11, 13, 14, 18, 19, 22,
26, 29, 35px) перевести на **ближайшую ступень** с риском «средний-высокий».
Но округление двигает пиксели:

```
 6.4px × 52  ->  8px   сдвиг +1.6px
 9.6px × 55  -> 10px   сдвиг +0.4px
12.8px × 40  -> 12px   сдвиг -0.8px
 5.6px × 28  ->  4px   сдвиг -1.6px
19.2px × 15  -> 20px   сдвиг +0.8px
```

По условию задачи «если пиксели поехали — это баг миграции, откатываем».
Значит округление 521 вхождения — это отдельное решение, а не рефакторинг.
Оно выполнено **не в этом шаге** и требует отдельного прохода с новым
эталоном.

### Что пропущено и почему

| Причина | Вхождений | Почему |
|---|---:|---|
| вне шкалы | 293 | округление сдвинет пиксели |
| голые числа | 194 | в CSS допустим только `0`; остальное — не CSS (см. §3) |
| внутри `calc()`/`var()` | 2 | составная длина не является ступенью |
| в комментариях | 2 | комментарий — не правило |
| `offline.html` | — | страница самодостаточна (§3.1) |

Крупнейшие оставшиеся значения, если решать их позже:
`6.4px ×52`, `9.6px ×55`, `12.8px ×40`, `5.6px ×28`, `19.2px ×15`,
`7.2px ×15`, `11.2px ×12`, `8.8px ×10`.

## 8. Что дальше

1. **Решить, округлять ли 521 вхождение вне шкалы.** Это меняет пиксели, то
   есть требует нового эталона снимков и ревью диффа глазами. Сейчас самые
   массовые: `6.4px`, `9.6px`, `12.8px`, `5.6px`. Пока они живут литералами,
   шкала работает как единый язык для 324 мест — это уже польза.
2. **Шаги 7 (радиусы, тени) и 9 (типографика)** устроены так же: объявить
   токены, заменить только совпадающие значения, округления — отдельным
   решением. Нашёлся прецедент: у `h1 a` и `#resetFilters` в `style.css`
   уже стоят `!important` с пояснением в комментарии — там значения не на
   сетке и подменять их нельзя.
3. **`offline.html` придётся либо держать на литералах, либо продублировать
   в него шкалу.** Дублирование создаёт обязательную синхронизацию; решение
   за владельцем офлайн-страницы.
4. **179 инлайновых `style=""`** остались нетронутыми — они вне объёма шага и
   были помечены как отдельный бэклог ещё в Шаге 3.
