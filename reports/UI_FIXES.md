## 1. Блок A — interactions.html, производительность графа

**Вердикт: закрыт без правок кода.** Проблема из отчёта владельца не
воспроизводится на текущей версии — граф «Добавки и лекарства» идёт по
предрасчётным координатам, физика не считается в рантайме.

### Замер вкладки «Добавки и лекарства» (`data-mode="drugs"`)

| Метрика | Значение |
|---|---|
| Узлов | **121** |
| Связей | **124** |
| Клик по вкладке → отрисовка | **22 мс** (2 кадра) |
| FPS в простое | 145 |
| Drag (mousemove 2 с) | 289 кадров / 2.00 с = **144 FPS** |
| Zoom (100 wheel-шагов) | 163 мс = **62 FPS** |
| Поиск (5 запросов: м→ме→мед→магн→магний) | 11 / 15 / 13 / 14 / 14 мс |

Порог из критерия A3 — 500 узлов. Фактически 121, то есть **в 4 раза ниже**,
поэтому ни кластеризация vis-network, ни lazy-load по клику не потребовались.

### Почему физика не мешает

`state.fixedCount = 121` — все узлы получили координаты из
`docs/graph_positions.json` (`layouts.interactions_drugs`, 121 запись;
есть и `layouts.interactions_supplements`, 11 записей). В `drawGraph`
условие `physics.enabled: !(fixedCount > 0 && fixedCount >= filtered.nodes.length)`
при полном покрытии даёт `physics: false`. Раскладка считается не в браузере,
а заранее. Тот же файл покрывает оба режима вкладок, поэтому переключение
между ними тоже не запускает симуляцию.

### Гипотеза «первый заход тяжёлый из-за data.json» — опровергнута

На `interactions.html` файл `data.json` (742 КБ) **вообще не запрашивается**.
По `performance.getEntriesByType('resource')` страница тянет только:

| Ресурс | Размер | Время |
|---|---|---|
| `vis-network-9.1.9.min.js` | 673 КБ | 136 мс |
| `interactions_graph.json` | 51 КБ | 9 мс |
| `graph_positions.json` | 25 КБ | 8 мс |
| Inter (5 файлов woff2) | ~110 КБ каждый | 49–63 мс |

Отдельный холодный `fetch('data.json', {cache:'no-store'})` отдаёт файл за
54 мс — но сама страница его не грузит, поэтому в её бюджет это не входит.

Навигация: DOMContentLoaded 229 мс, load 341 мс, transfer 33 КБ.

## 2. Блок B — map.html, пустое место справа

**Исправлено.**

### Причина

Локальный `body { margin: 0 }` в `map.html` (строка 57) перебивал
`margin: 0 auto` из `style.css:100`. Контейнер шириной 1200 px прилипал к
левому краю: замер давал `bodyX = 0`, `bodyW = 1200`. На 1920 справа
оставалось ~720 px пустоты, причём асимметрично.

Комментарий в коде (строки 212–220) осознанно оставлял потолок 1200 px,
объясняя это читаемостью текста. Решение владельца — растянуть правую
панель с цепочками механизмов, текст оставить в прежней ширине.

### Правка

В `docs/map.html`, перед блоком «Единая шапка для всех страниц»:

```css
/* v5.6.2 B2: на широких экранах растягиваем правую панель с цепочками
   механизмов на всю ширину. Локальный body{margin:0} перебивал
   margin:0 auto из style.css, из-за чего контейнер 1200px лип к левому
   краю и справа на 1920 оставалось ~720px пустоты. Текст (h1, вводные
   абзацы, футер) оставляем на 1200px — длинная строка нечитаема. */
@media (min-width: 1400px) {
  body { max-width: none; }
  .wrap main > h1,
  .wrap main > p,
  .wrap .site-footer { max-width: 1200px; }
}
```

### Замеры

| Ширина | `.cols` | Правая колонка | Пусто справа | overflowX |
|---|---|---|---|---|
| 1920 | 1809 | **1450** (было 745) | 63 | нет |
| 2560 | 2449 | 2090 | 63 | нет |
| 1600 | 1489 | 1130 | 63 | нет |
| 1400 | 1289 | 930 | 63 | нет |
| 1366 | 1104 | 745 | — | нет |
| 1280 | 1104 | 745 | — | нет |
| 390 | 337 | 337 | 34 | нет |

63 px — симметричные боковые padding + полоса прокрутки, а не пустота.
Вёрстка ниже 1400 px не тронута. Горизонтального скролла нет ни на одной
ширине.

### Побочная правка: `tests/test_silent_handlers.py`

Pre-commit hook заблокировал первый коммит: тест пин-кодит номера строк
в `script.js` через ключи `ACCEPTED_NON_ELEMENT_GUARDS`. Вставка
`CAT_GROUPS` + `catGroup()` и двух атрибутов `data-cat-group` в
`renderCards` сдвинула все девять записей ровно на +38 строк.

Проверено, что это не регресс, а только сдвиг: каждая из девяти строк на
новом месте содержит ровно ту конструкцию, что описана в её комментарии
(`$('modalOverlay')` → 727, `!list.length` → 730, `supplementsFull[id]` → 762,
`!cfg.$band` → 925, `!els.length` → 985, `chartSupByEl` → 987,
`!a || !b` → 1085, `!html` → 1213, `!r.ok` → 1269). Номера пересчитаны,
причины оставлены прежними. Это ровно тот же техдолг, что **#52** для
`sw.js`: пин-код номеров строк в тестах ломается на любой вставке.

## Приложение: ловушки, потратившие время

1. **Кэш вложенных ресурсов.** `?cb=<timestamp>` в URL страницы сбрасывает
   кэш HTML, но **не** кэш `script.js` / `style.css` — их версия задаётся
   только query `?v=N` в тегах `<link>` / `<script>`. Первый прогон проверки
   блока E показал «CSS применился, `data-cat-group` везде `null`», хотя на
   диске скрипт был новый. Помог только бамп `?v=` до 286 / 418.
2. **`transition: color .25s` в style.css.** Мгновенное чтение
   `getComputedStyle` после переключения темы возвращает промежуточное
   смешанное значение. Первый замер цветов был неверным; нужен
   `await new Promise(r => setTimeout(r, 500))`.
3. **Маркеры pytest снимаются через переменные окружения, а не `-m`.**
   `RUN_SNAPSHOTS=1 pytest -m snapshots` — без переменной получается
   `813 deselected` с кодом выхода 1, что выглядит как пустой прогон.
4. **`UPDATE_SNAPSHOTS=1` перезаписывает все эталоны** (техдолг #98). Перед
   пересъёмкой сняты MD5 всех 73 файлов, после — сверено: изменились только
   падавшие.
