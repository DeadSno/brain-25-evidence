## 1. README.md: блок Git hooks исправлен

Причина поломки оказалась не в бэктиках, а в **смешанных окончаниях строк**.
Сломанный блок был записан с CRLF, остальной файл — с LF. Из-за этого
`Edit` не находил текст (это ровно та ловушка, что описана в AGENTS.md
для кириллицы; здесь та же причина, но на невидимых символах).

Диагностика:

    CRLF count: 7 ; bare LF: 434

Все 7 CRLF приходились ровно на битый блок (строки 435-441). Правка
выполнена скриптом по номерам строк — fallback, предписанный AGENTS.md.
Скрипт был чисто ASCII, кириллица лежала в отдельном UTF-8 файле,
чтобы PowerShell не испортил её при чтении .ps1 в однобайтовой кодировке.

Диф относительно HEAD: **+12 / -0**. Ни одной удалённой строки —
значит, битый блок никогда не был закоммичен, он остался мусором в
рабочем дереве, и правка стала чистым добавлением.

Было (строки 437-441):

    ## Git hooks
    После клонирования выполни:
    `ash
    git config core.hooksPath .githooks
    `

Стало (строки 436-446):

    - Обход при аварии: git commit --no-verify

Команда оформлена отступом 4 пробела, бэктиков в блоке нет.

Проверки после правки: BOM нет, CRLF 0 / LF 446, файл кончается
переводом строки, кириллица на месте (9099 символов).

### Про exit code 1 при первом коммите

Первый `git commit` отработал с exit 1 при том, что хук напечатал
`OK: tests passed`. Причина — не хук, а мой пайп
`| Select-Object -Last 25`: PowerShell закрывает stdout, git ловит
broken pipe и возвращает 1. Коммит при этом создался корректно.
Проверено: тот же коммит без пайпа (редирект в файл) дал exit 0.
Вывод обрезать пайпом не стоит — писать в файл.
