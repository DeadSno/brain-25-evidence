## 4. T1: причина — не sticky-обёртка v5.6.0

### Что показывает git

`git log -S ".site-header { position: sticky" -- docs/style.css` → единственный
коммит, вводящий липкость на обёртку:

```
c19574c fix(v5.6.0): sticky wrapper + light theme + BOM normalization +
        modal z-index + graph determinism + cache v414 + quote
```

До него липким был внутренний `.top`; в v5.6.0 липкой стала обёртка
`.site-header` (style.css:444-446), причём `.trustbar` и `.top` получили
`position: static`.

### Что показывает замер

Разложил шапку на слои на `methodology.html` @320:

| Слой | px |
|---|---:|
| `.trustbar` | 54 |
| `.top` (`.site-title` 27 + `.actions` 419) | 454 |
| **Итого `.site-header`** | **508** |

Отсюда: **до v5.6.0 липким был бы `.top` = 454px, то есть 71% вьюпорта.**
v5.6.0 добавил ровно **54px** (trustbar) — 71% → 79%.

То есть v5.6.0 **усугубил** проблему, но не создал её. На порядок хуже
полоски доверия липкой была всё та же `.actions` — **419px**.

### Настоящая причина — 11 кнопок в `flex-wrap`

| Страница | Кнопок в `.actions` | Высота `.actions` @320 |
|---|---:|---:|
| index, sup/*.html | 4 | 94–101px |
| 10 кнопок | 10 | 195–246px |
| 11 кнопок | 11 | 419–422px |

Высота линейна по числу кнопок: 11 кнопок в `flex-wrap` дают **8 рядов**.
Корень — не липкость, а то, что внутренние страницы выкладывают **всю навигацию
сайта** в шапку.

### Два подтверждения из самого проекта

1. **Компактный вариант уже есть.** `index.html` кладёт в `.actions` всего
   4 кнопки (Обратная связь, Обновить, Поддержать, Тема), а основную навигацию —
   в тело страницы. Отсюда 188px вместо 508px. Правильный образец лежит в
   репозитории.
2. **Проект сам уже обошёл эту шапку на страницах с графиками.**
   `body.trends-page .site-header { display: contents }` (style.css:505) —
   комментарий рядом объясняет, что липкая шапка несовместима с графиками.
   То есть проблема липкой высокой шапки признана и обойдена локально, вместо
   того чтобы быть решённой.

Вывод: T1 — **системный дефект разметки внутренних страниц**, а не регресс
липкости. Откат v5.6.0 дал бы −54px и ничего не решил.

## 5. Рекомендация по фиксу

Основной рычаг — **сократить `.actions` на мобильном до одного ряда**. Тогда
шапка становится ~90px вместо 419–511px, и на 320px освобождается порядка
400px высоты.

Варианты, от дешёвого к дорогому:

**A. Одна строка CSS — горизонтальная прокрутка `.actions` на узких экранах.**
```
@media (max-width: 620px) {
  .site-header .actions { flex-wrap: nowrap; overflow-x: auto; }
}
```
Ряды 11 кнопок схлопываются в один, шапка ≈ 90px. Правок разметки нет,
применяется сразу ко всем страницам. Нюанс: появляется намеренный
горизонтальный скролл **внутри шапки** — это осознанный паттерн, в отличие от
непреднамеренного скролла всей страницы, который чинили в батче A. Скроллбар
при этом надо скрыть, иначе он съест высоту. Риск минимальный, откат — снять
правило.

**B. Одно правило — не липкая шапка на мобильном.**
```
@media (max-width: 620px) { .site-header { position: static; } }
```
Шапка прокручивается вместе с текстом, ничего не перекрывает. Дёшево, но
теряется постоянный доступ к навигации — на странице `sup/*.html` без этого
единственная навигация в подвале.

**C. Перенос навигации в тело + бургер.** Правильный путь, примерно как
сделан `index.html`. Но это правка разметки **17 страниц** плюс состояние
burger'а, скрипт, обработка Esc и фокуса. Оправдано, но это отдельная
задача, не совместимая с «одной пересъёмкой».

**Рекомендация: A сейчас** (дёшево, обратимо, даёт основной эффект), с
переходом к C позже, если владелец захочет. B — хороший запасной вариант,
если горизонтальный скролл в шапке сочтут неприемлемым.

Любой из вариантов меняет высоту страницы, поэтому пересъёмка нужна в любом
случае — это ровно тот аргумент, по которому T1, #94, #95 и T5 объединены в
одну задачу.

Отдельно к T5 (#97): правка контентная, высота страницы не обязана измениться,
но она попадёт в `methodology.html` — вероятно, стоит делать в том же заходе,
раз уж файл открыт.

## 6. Вопросы владельцу

1. **Версии в техдолге разошлись.** #96 (T1, P0) и #97 (T5, P1) помечены
   `v5.6.1`, а #94 и #95 — `v5.6.2`. При этом все четыре объединены в одну
   задачу с одной пересъёмкой, то есть попадут в один релиз. Оставить как есть
   или свести #96/#97 к `v5.6.2`?
2. **Способ фикса шапки.** Рекомендую вариант A (одно правило, `.actions` в одну
   строку со скроллом) — обратимо одним удалением строки. Вариант B (не липкая
   шапка на мобильном) тоже дешёв, но убирает постоянную навигацию на `sup/`.
   Вариант C (бургер, как на `index.html`) — правильный, но это отдельная
   задача на 17 страниц.
3. **Порог.** Считать ли 188px на `index.html` нормой? Это 29% на 320×640 и
   вьюпорт всё равно заняты на четверть. Если цель — «шапка не выше 120px на
   телефоне», то править нужно и `index.html`, а не только внутренние страницы.
4. **`trends.html` не трогаем?** Он выходит из проблемы через
   `display: contents`. Вариант A его не заденет, но проверить стоит: при
   `display: contents` правило на `.actions` может примениться иначе.
5. **Порог 200px из задания** перевыполнен на порядок: 12 страниц из 14 выше
   него. Возможно, масштаб стоит поднять до P0-инцидента, а не P0-задачи.
