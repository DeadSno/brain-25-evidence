## 2. Почему Artifacts — правильное решение

Цена хранения копий в git посчитана, а не оценена:

| вариант | за прогон | за 30 дней | за год |
|---|--:|--:|--:|
| git, 2 файла (было) | 1.36 МиБ | 40.8 МиБ | 0.48 ГиБ |
| git, 20 файлов | 2.17 МиБ | 65.0 МиБ | 0.77 ГиБ |
| **Artifacts** | **2.17 МиБ** | **65.0 МиБ квоты** | — |
| из них gzip | 0.38 МиБ | 11.5 МиБ | — |

Ключевое: **в git это не 65 МиБ, а +65 МиБ навсегда.** `find -delete`
убирает файлы из рабочей копии, но блобы остаются в коммитах, и
`git gc` не умеет их выкинуть — на них ссылаются коммиты. Плюс столько
же в каждом полном клоне.

Artifacts живут ровно `retention-days` и исчезают. Квота GitHub free —
500 МБ; при 30-дневном хранении расход 65.0 МиБ, это 13% квоты.

Gzip дал бы 4.8x по объёму, но, как верно сказано в решении, история
git от этого не перестаёт расти — просто медленнее.

### 3.2 Плоское копирование заменено на `cp --parents`

Задание предлагало `cp docs/*.json backup/` и `cp docs/api/v1/*.json
backup/` — обе команды кладут файлы в **один** каталог. Сегодня коллизий
нет (проверено: 14 уникальных имён в `docs/`, 4 в `api/v1/`), но
`docs/api/v1/data.json` — гипотетическое будущее, и бэкап не место, где
такое выясняется постфактум: копия есть, но не того файла.

`cp --parents` сохраняет путь внутри архива. Коллизия невозможна по
построению, а распаковка в корень репозитория восстанавливает файлы на
места без ручного раскладывания.

### 3.3 Добавлен `openapi.yaml` — вне правила «все JSON»

`tests/test_api_contract.py` валидирует данные **именно по нему**. Его
потеря молча отключила бы проверку контракта: тест стал бы пустым, и
никто бы не узнал. Одна строка стоит дешевле, чем тихая потеря.

Схемы `.schema.json` при этом тестами не используются — проверка контракта
идёт по `openapi.yaml`, а `schemas/README.md` описывает их как
документацию для внешнего `jsonschema`.

### 3.4 Страховка: список, а не счётчик

Сначала стояла проверка «найдено меньше 20 файлов → ошибка». **Она не
работает**, и это доказано прогоном: при удалённом `openapi.yaml`
остаётся ровно 20, порог `< 20` проходит, бэкап молча становится
неполным — ровно то, что страховка обязана ловить.

Заменена на явный список из 8 обязательных файлов:

```
docs/data.json            docs/api/v1/index.json
docs/data_index.json      docs/api/v1/supplements.json
docs/timeseries.json      docs/api/v1/openapi.yaml
docs/graph_data.json
```

Проверено на трёх сценариях:

| сценарий | результат |

| всё на месте | код 0, «Все 8 обязательных файлов на месте» |
| удалён `openapi.yaml` | **код 1**, назван отсутствующий |
| удалён `timeseries.json` | **код 1**, назван отсутствующий |

Схемы в список обязательных не входят: они попадают в бэкап, но потеря их
не ломает ни данные, ни тесты. Список отражает то, без чего сайт или
проверки не работают.

## 4. Часть B — watchdog.yml

### 4.1 Что он делает

`.github/workflows/watchdog.yml`, 22 строки, понедельник 06:00 UTC,
`timeout-minutes: 15`.

| шаг | что делает |
|---|---|
| `scripts/audit_links.py` | `requests.head` по каждому URL из `docs/data.json` и `README.md`; при 405/403/429 повторяет через `get`; падает при любом коде ≥ 400 |
| `pytest tests/test_schema.py tests/test_site_data.py` | 5 + 3 теста: соответствие данных схеме и согласованность данных с кодом |
| `gh issue create` | при `failure()` создаёт issue — уведомление **не требует настройки** |

Права: `contents: read`, `issues: write` — минимально необходимые.

### 4.2 Пересечение с backup

| ситуация | кто ловит |
|---|---|
| внешняя ссылка в `data.json` → 404 | `audit_links` |
| структура данных нарушена | `test_schema` |
| данные разошлись с кодом | `test_site_data` |
| файл данных **потерян** | backup, но поздно: он защищает восстановление, а не обнаружение |
| данные устарели, но валидны | **никто** |
| сайт не отдаётся извне | **никто** — это задача UptimeRobot |

**Пересечения по существу нет.** watchdog проверяет **корректность**
данных, backup — **сохранение**. Разные вопросы.

### 4.3 Объединять нельзя

- разные триггеры: еженедельно против ежедневно
- разные права: `issues: write` против «только чтение»
- разный отклик: issue в репозитории против артефакта
- **главное:** backup должен работать, даже если аудит сломан. Иначе
  отказ watchdog-а уронит ещё и резервные копии — два независимых
  механизма, связанные отказом одного

### 4.4 Проверена работоспособность watchdog

Подозрение: `watchdog` ставит только `requests pytest`, а
`requirements.txt` объявляет 17 пакетов. Если тестам нужен ещё пакет,
джоб падал бы каждую неделю и открывал issue каждую неделю — то есть
неделями висела бы ложная тревога.

**Подозрение не подтвердилось.** Оба теста импортируют только `json` и
`pathlib` из стандартной библиотеки. Проверено в чистом venv с установкой
ровно `requests pytest` — **8 тестов проходят**. Спекулировать и
сообщить о неисправности было бы неверно.

## 7. Ошибки этого захода

Три, все пойманы проверками.

**1. Страховка по счётчику оказалась бесполезной.** Порог «меньше 20»
проходил при удалённом `openapi.yaml`, потому что оставалось ровно 20.
Проверялось прогоном на удалённом файле, а не рассуждением. Заменено на
список обязательных файлов.

**2. Мой чекер «нет лишних совпадений» дал ложное срабатывание.**
Строка `permissions contents:write: True` в выводе — это моя же строка в
комментарии workflow («`contents: write` больше НЕ нужен»), найденная
наивным поиском подстроки. YAML-разбор показал, что `permissions` не
задан вовсе. Наивный grep по тексту конфигурации бесполезен — доверять
надо разбору.

**3. Неверная цифра попала в предыдущий коммит.** В роадмапе, отчёте и
сообщении стояло «15 json в `docs/`». Замерено: 14 в корне, 4 в `api/v1`,
2 в `schemas`, итого 20. Это уже четвёртый случай за серию, когда число в
трекере не сходится с кодом.

Побочно: два сценария в песочнице сначала показали падение
`test_site_data.py::test_files_present`. Причина была в моей песочнице —
я не скопировал `map.html`, `style.css`, `script.js`. После
докопирования 8 тестов проходят. Ошибка была в проверке, не в коде.
