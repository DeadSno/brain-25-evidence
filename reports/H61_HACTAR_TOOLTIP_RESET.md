# H-6.1 — Project Hactar: чистые тултипы и рабочая кнопка «Сброс»

Ветка: `v5.6.5-dev` · база: `934fff0a` (H-6) · дата: 2026-10-22

## Задача

Два дефекта вкладки «Связи» (H-6):

1. подсказки узлов показывали сырой HTML (`<b>Креатин</b><br>Грейд: A<br>…`);
2. кнопка `[ Сброс ]` визуально ничего не делала — перетащенный узел
   не возвращался на место.

## Диагностика

### 1. Тултипы

`docs/vendor/vis-network-9.1.9.min.js` — класс подсказки (`div.vis-tooltip`)
вставляет текст **через `innerText`**:

```js
{key:"setText",value:function(g){
  if(g instanceof Element){ /* ...appendChild... */ }
  else this.frame.innerText=g
}}
```

`innerText` не разбирает HTML, поэтому любые теги в строке `title`
показывались как есть. Проверено в браузере: текст подсказки был
`<b>Креатин</b><br>Грейд: A<br>Эффекты: Рабочая память под нагрузкой`.

Обратная сторона: `innerText` сам превращает `\n` в настоящий перевод
строки — то есть формат «простой текст + `\n`» и есть правильный.

### 2. Кнопка «Сброс»

Обработчик был и был привязан (`graphResetBtn.addEventListener('click', …)`),
но внутри стоял `renderEgo(lastSelection)` — полная перерисовка графа с
**повторным запуском физики**. Симуляция стартовала от текущих (то есть
перетащенных) координат и приходила к *другой* раскладке, поэтому узел
«возвращался» не туда. Замеры до/после (12 узлов, выбор «Креатин»+«Кофеин»):

| узел | до перетаскивания | после перетаскивания | после «Сброса» (было) |
|---|---|---|---|
| `Креатин` | 214,-155 | 425,8 | 242,-130 — **не то место** |
| `drug:диуретики` | -10,-363 | -10,-363 | -105,-209 — уехал на 181 px |

Итог: кнопка выглядела как «ничего не делающая».

Проверенные факты по API vis-network 9.1.9:

* `network.setPositions` — **нет**;
* `network.moveNode(id, x, y)` — **есть**, работает (двигает узел на экране,
  `getPositions()` это отражает);
* `network.body.data.nodes.update({id:{x,y}})` — узел **не** двигает;
* `network.body.nodes[id].setPosition` — не функция (фолбэк — писать
  `node.x` / `node.y` вручную);
* `network.getPositions()` — возвращает округлённые целые;
* `network.fit({animation:true})` — есть.

## Что сделано

### `docs/hactar.js`

**Подсказки — простым текстом.** HTML-теги убраны из всех `title`,
`\n` вместо `<br>`, `esc()` из подсказок убран (innerText не разбирает HTML,
`esc` дал бы «&amp;» в тексте):

| узел | было | стало |
|---|---|---|
| добавка | `'<b>' + esc(name) + '</b><br>Грейд: ' + esc(grade) + …` | `name + '\nГрейд: ' + grade + '\nЭффекты: ' + effText` |
| мишень | `'<b>Мишень:</b> ' + esc(tlabel)` | `'Мишень: ' + tlabel` |
| механизм | `title: mech.html` (`'<b>Механизм:</b> ' + esc(text) + …`) | `title: mech.tip` (`'Механизм: ' + text + '\nЭффект: … + '\nСила связи: …'`) |
| лекарство | `'<b>Лекарство:</b> ' + esc(withName) + '<br><b>Взаимодействие:</b> ' …` | `'Лекарство: ' + withName + '\nВзаимодействие: ' + sev.label + '\n' + it.note` |

Поля `mech.html` → `mech.tip` (в `resolveMech` и `matchMech`); `mech.plain`
(текст на ребре) не тронут.

Перевод строки вынесен в константу `NL = '\n'` — **не** литералом рядом со
знаком плюс. Аудит классов (`scripts/audit_classes.py`) ищет форму
«слово + закрывающая кавычка + плюс» (`JS_DYNAMIC`) и решил бы, что имя
класса собирается динамически с префиксом `n`. Из-за этого класс `.noPrice`
«оживал» бы, выпадал из списка мёртвых — и падал тест
`test_known_dead_list_matches_measured` (проверено: с литералом `'\n' + it.note`
префикс `n` появлялся в `dyn_prefixes`, после замены на `NL` — исчезает).

**Позиции — два снимка.**

* `homePos` — исходные координаты, посчитанные `placeNodes` из
  `graph_positions.json` (заполняется в том же цикле, где узлы получают
  `x`/`y`);
* `drawnPos` — раскладка, с которой граф реально нарисован: снимается в
  `freezePhysics()` (`network.getPositions()`), когда физика застыла.

**Новые функции.**

* `captureDrawn()` — снимок текущих позиций в `drawnPos`;
* `moveNode(id, x, y)` — `network.moveNode()`, фолбэк — `node.x/node.y`;
* `placeHome()` — вернуть узлы в `homePos`;
* `resetGraph()` — гасит физику, возвращает каждый узел в `drawnPos`
  (фолбэк — `homePos`), затем `network.fit({ animation: true })`.

**Кнопка «Сброс»** теперь вызывает `resetGraph()` вместо `renderEgo()`.

**`applyEgo()`** пересобирает граф предсказуемо: физика выключается →
`setData` → `placeHome()` → физика включается. Раньше симуляция стартовала
от текущих координат, и раскладка зависела от того, что нажимал
пользователь. Теперь один и тот же выбор всегда даёт одну и ту же картину.

**Бонус:** подсказка гаснет, когда курсор уходит с холста. vis-network
9.1.9 прячет её только при движении мыши *внутри* canvas — если увести
курсор за пределы графа, подсказка оставалась висеть. Добавлен слушатель
`mouseleave` на canvas (в `ensureNetwork`).

### `docs/hactar.html`

`hactar.js?v=6` → `hactar.js?v=7` — бамп версии (файл изменился).
CSS кнопки не менялся.

## Проверка

Сервер: `python -m http.server 8000 --directory docs`; страница
`http://localhost:8000/hactar.html?tab=graph`; выбор — «Креатин» + «Кофеин»
(12 узлов, 13 рёбер). Проверка в браузере (Playwright), координаты —
`network.getPositions()`.

| проверка | результат |
|---|---|
| текст подсказки | `Креатин\nГрейд: A\nЭффекты: Рабочая память под нагрузкой` |
| HTML-теги в подсказке | нет (`hasBoldTag: false`, символа `<` в тексте нет) |
| переносы строк | есть (3 строки) |
| подсказка гаснет при уходе курсора | да (`visibility: hidden`) |
| перетаскивание | `Креатин` 268,-124 → 527,74; остальные 11 узлов не сдвинулись |
| «Сброс» | все 12 узлов вернулись **точно** в исходные координаты (расхождений 0) |
| «Сброс» + центрирование | `network.fit({animation:true})` — граф в центре холста |
| физика после «Сброса» | выключена (`graphState().physics === false`) |

Скриншоты (в `reports/`):

* `hactar_h61_tooltip.png` — чистая подсказка из трёх строк, без `<b>`;
* `hactar_h61_dragged.png` — узел «Креатин» уведён мышкой;
* `hactar_h61_reset.png` — после «Сброса»: узел на месте, граф отцентрирован.

Тесты: `python -m pytest -q` (сервер на :8000 поднят, иначе снапшот-тесты
молча скипаются) — **1965 passed, 24 skipped, 0 failed** за 9:23
(1989 тестов = 1965 + 24, совпадает с `version.json`).

Отдельно: `tests/test_no_orphan_classes.py::test_known_dead_list_matches_measured`
падал на промежуточной версии — из-за литерала `'\n' + it.note`, который
регулярка аудита классов читала как «динамический префикс `n`», и класс
`.noPrice` переставал считаться мёртвым. После выноса перевода строки в
константу `NL` тест зелёный, `.noPrice` снова в списке мёртвых.

## Итог

* Тултип: чистый текст с переносами строк, без сырого HTML.
* «Сброс»: узел возвращается ровно туда, откуда его перетащили, граф
  центрируется, физика не срывает раскладку снова.
* Побочно: раскладка графа стала воспроизводимой (один и тот же выбор →
  одна и та же картина), подсказка не залипает при уходе курсора.
