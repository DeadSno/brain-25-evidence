### Что было (замер computed, 1280px)

|---|---|---|---|---|

| map | 21.6 | 18 | 12 ⚠ | — |
| interactions | 21.6 | — | — | — |

Два нарушения: `h3` на calculator = **13.6px** и `h4` на trends = **14.72px** — оба
*меньше* основного текста (16px). В `style.css` не было ни одного базового правила для
`h3`/`h4`/`h5` вообще: их размер давал UA-дефолт или локальный `<style>` страницы.

### Почему не 1.75 / 1.5 / 1.25 / 1.1 / 1

Запрошенная шкала несовместима с фактическим h1. На всех 145 страницах заголовок
зажат правилом с `!important`:

```css
main h1{font-size:1.35rem !important}   /* 21.6px на всех страницах */
```

Под ним `h2` в базе = `1.125rem` (18px). Если поставить `h2: 1.5rem` (24px), получится
**инверсия `h2` > `h1` на ~135 страницах** — ровно та проблема, которую этап и чинит.
Чтобы сохранить `h1 > h2` при `h2 = 24px`, пришлось бы поднять `main h1` до 28px, то есть
переписать `!important`-пин на 145 страницах. Это за пределами «добавить базовые правила» и
за пределами стоп-порога «ломает >5 страниц» → **решение владельца: консервативно,
`main h1` не трогаем**.

### Что сделано

```css
h3{font-size:1.1rem;font-weight:600}    /* 17.6px */
h4{font-size:1.05rem;font-weight:600}   /* 16.8px */
h5{font-size:1rem;font-weight:600}      /* 16px  */
.block h3{font-size:1rem !important}     /* вытесняет локальный <style> calculator.html */
.method-body h4{font-size:1rem !important} /* вытесняет локальный <style> trends.html */
h3,h4,h5{line-height:var(--lh-tight)}
h3{margin:var(--space-4) 0 var(--space-2)}
h4{margin:var(--space-3) 0 var(--space-2)}
h5{margin:var(--space-3) 0 var(--space-1)}
```

`!important` на двух скоупах — не перебор, а необходимость: размер приходит из локального
`<style>` внутри `calculator.html` и `trends.html`, который загружается **после** `<link>`
на `style.css` при равной специфичности. Без `!important` правило страницы побеждает,
и 13.6px / 14.72px остаются.

## П5 — Дубль `.empty`

В `style.css` правило **одно**:

```css
.empty{grid-column:1/-1;text-align:center;padding:var(--space-12) var(--space-4);opacity:.8}
```

Второе определение находится в **локальном `<style>` файла `calculator.html`**
(`padding:var(--space-2) 0`). Оно не входит в границу «только `docs/style.css`» и не может
быть изменено из таблицы стилей — каскад разрешает его в пользу локальному правилу.

**Решение:** объединение невозможно в этом этапе. Вместо правки добавлен комментарий
прямо над `.empty` в `style.css`, фиксирующий наличие дубля, источник и причину
(правило страницы сильнее по порядку). Объединение — в этапе 1C вместе с правкой
`calculator.html`.

## П6 — Некруглые токены `:root`

```css
--space-0-2: .2rem     /* 3.2px  */
--space-0-3: .3rem     /* 4.8px  */
--space-2-5: 10px
```

Это все три некратных 4px токена. **Значения НЕ изменены, и это не упущение:**
`tests/test_css_tokens.py` содержит словарь `EXPECTED`, который сверяет значения
`--space-*` **посимвольно**, и любое округление (`0.2rem → 4px`, `0.3rem → 4px`,
`10px → 12px`) роняет `test_spacing_tokens_are_declared`.

**Решение владельца на этапе разбора: документировать.** Добавлен комментарий над `:root`
с объяснением, что токены закреплены тестом и потому by-design. Правка самих значений
требует сначала правки теста — это отдельная задача, не типографика.
