# ЧАСТЬ 1 — v5.1.5, раздел «Аналитика»

Раздел **был**, но в нём стояли **вопросы**, а не решения:

```

- Нужен ли GA4 / Clarity / Search Console?

```

Первый вопрос закрыт измерением: Метрика стоит, cookie-баннера нет. Второй —
решён в `reports/ANALYTICS_DECISION.md`. Переписал в решения с фактами и
ссылкой на отчёт.

Добавлено сверх перечисления, потому что без этого решение не выполнимо:

- **счётчик и пиксель названы отдельно** — это два разных запроса
- **`ssr:true` и `ecommerce:"dataLayer"` бессмысленны** при статике на GitHub
  Pages, а `clickmap:true` пишет координаты кликов на сайте о здоровье
- **пиксель `<noscript>` нельзя закрыть JS-проверкой согласия** — это обычный
  `<img>`. Любая схема согласия обязана предусматривать и его, иначе получится
  «согласие есть, а запрос ушёл»
- **свой хостинг Umami/Matomo отпадает** — сервера нет, сайт на GitHub Pages
- **что требует юриста** вынесено отдельной строкой: и достаточность раскрытия
  без баннера, и правомерность сбора через Метрику

# Мой баг, найденный сразу после правки

Первый вариант раздела «Аналитика» был **нумерованной таблицей** `| 1 |` … `| 5 |`.
Мой же скрипт проверки на дубликаты номеров показал: **1, 4 и 5 задвоились** —
потому что таблица решений в v5.1.5 попала под ту же регулярку, что и трекер.

Это ровно тот класс ошибки, который я уже находил в этом проекте: два трекера,
две «версии». Здесь — одна нумерация, два употребления.

Переделал на маркированный список с эмодзи-статусами. Проверка теперь чистая:

```
номера в ТЕХНИЧЕСКОМ ДОЛГЕ: 1, 4-28
дубликаты: нет
строк вида | N | вне ТЕХНИЧЕСКОГО ДОЛГА: нет
```
