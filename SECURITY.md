# Политика безопасности

brain-25-evidence — статический сайт (GitHub Pages) и набор скриптов-генераторов
данных. Серверной части нет: весь код исполняется в браузере посетителя, а
данные лежат открытыми файлами в `docs/`. Поэтому классы уязвимостей тут
ограничены — но не отсутствуют: XSS через данные карточки, подмена файлов в
Service Worker, ошибка в скрипте, который пишет в репозиторий.

Мы ценим сообщения об уязвимостях. Спасибо, что нашли время.

|---|---|

## Как сообщить об уязвимости

**Не открывайте публичный issue с описанием уязвимости.** До выхода
исправления такое сообщение работает как инструкция для атакующего.

Приватные каналы, в порядке предпочтения:

1. **GitHub Security Advisories** —
   <https://github.com/DeadSno/brain-25-evidence/security/advisories/new>
   Приватный отчёт, доступный только мейнтейнеру; здесь же выходит
   подтверждённое advisory после исправления.
2. **Приватное сообщение мейнтейнеру** — аккаунт [@DeadSno](https://github.com/DeadSno)
   на GitHub, если форма advisory недоступна.

Публичный [issue](https://github.com/DeadSno/brain-25-evidence/issues/new)
годится только для того, что не является уязвимостью: ошибка в данных
(шаблон `data-error`), опечатка, непонятный вердикт.

### Что приложить

- Где именно: файл и строка (`docs/script.js:1234`), URL страницы.
- Что происходит и что должно происходить.
- Шаги воспроизведения: минимальные, без лишних условий.
- Версия: `docs/version.json` (`app`, `data`) или тег.
- Если есть — снимок экрана, фрагмент консоли, PoC.

Пожалуйста, без реальных персональных данных и без чужой инфраструктуры.

## Чего ждать

| Этап | Срок |
|---|---|
| Подтверждение получения отчёта | 7 дней |
| Первичная оценка (принято / не воспроизводится / вне области) | 30 дней |
| Исправление | Зависит от сложности; обсуждается с автором отчёта |
| Публикация advisory | После выхода исправления, по согласованию |

Мы не удаляем и не «заминаем» обоснованные отчёты: после исправления
публикуется advisory с указанием автора (если он не против).

## Что в области действия

- **XSS и инъекции в разметку** — `docs/*.js`, `docs/*.html`, шаблоны
  `templates/*.j2`: данные карточек подставляются в DOM, и ошибка
  экранирования в них — уязвимость.
- **Service Worker и кэш** — `docs/sw.js`: подмена закэшированного файла,
  кэширование ответа не того источника, обход проверок версии.
- **Supply chain** — зависимости и вендорные библиотеки (`requirements*.txt`,
  `vis-network` и прочие файлы в `docs/`): версия с известной уязвимостью,
  исполняемая в браузере.
- **Безопасность скриптов репозитория** — `scripts/*.py`: запись за пределы
  каталога, исполнение содержимого из внешнего файла, перезапись данных по
  недоверенному вводу.
- **Утечки** — секреты, токены, персональные данные в отслеживаемых файлах.

## Что вне области действия

- Отсутствие security-заголовков (CSP, HSTS, X-Frame-Options) — ограничение
  GitHub Pages, задать их в проекте нельзя.
- Устаревшая версия библиотеки без воспроизводимого сценария использования.
- Достоверность медицинских данных и формулировки карточек — это
  `data-error` issue, а не уязвимость; см. [CONTRIBUTING.md](CONTRIBUTING.md).
- Отказ в обслуживании (DoS) на статических файлах — доступность
  обеспечивает хостинг, а не проект.
- Сообщения сканеров без описания влияния.
