# Learning Content Audit

Триггер: "аудит учебных материалов", "проверь конспект", "learning audit".

## Правило верификации находок

Прежде чем фиксить находку — воспроизведи её:
- данные: запрос к файлу, не к памяти
- факт: сверь со стандартом или оригинальным источником
- ссылка: перейди по якорю в VS Code / GitHub, убедись, что цель существует

Если не можешь воспроизвести — находка не подтверждена, в отчёт идёт со статусом «требует верификации».

## Лимит находок

Ориентир — 60 в отчёте. При превышении:
- группировать однотипные (130 звёзд = 1 находка, не 130)
- P0/P1 — не резать никогда
- P2 — сжимать до паттернов
Число в отчёте — что нашлось, а не что влезло.

## Специфика проекта brain-25-evidence

См. .opencode/skills/CONVENTIONS.md — структура проекта и правила.

## Локаль: RU + EN (обязательно для всех проверок)

Материал на русском с английскими терминами, оба языка — столпы. Проверять:
- все EN-термины с переводом при первом упоминании
- нет артефактов CJK/немецкого/французского/испанского/корейского
- переводы корректны (не кальки с английского)

## Назначение

Проверяет учебные материалы (конспекты, учебники, гайды) на точность, самодостаточность, полноту, консистентность, переводы и артефакты машинного перевода. Используется владельцем для проверки файла `.opencode/System Analysis low.md` — учебника для ежедневного чтения и подготовки к интервью Middle SA. Скилл переиспользуем для модулей 2–4 конспекта.

## Что проверять

### 1. Точность фактов

Стандарты: ISO 25010, ISO 29148, ГОСТ 19.201-78, ГОСТ 34.602-89, BABOK, UML 2.5.1, BPMN 2.0. Протоколы: REST, SOAP, gRPC, OpenAPI, OAuth 2.1, JWT, mTLS. Паттерны: CAP, ACID, BASE, CQRS, Saga, Outbox, Circuit Breaker. Безопасность: OWASP Top 10, STRIDE. Проверять 3–5 случайных фактов на достоверность (например, PostgreSQL Repeatable Read **не** допускает phantom read — MVCC).

### 2. Самодостаточность

Нет ссылок на `brain-25-evidence`, `localhost`, `deadsno`, `:8000`. Нет «см. статью»/«подробнее тут» без конкретной ссылки. Все внешние ссылки — на стандарты/книги с пояснением, зачем читать.

### 3. Полнота для заявленного уровня (Junior/Middle/Senior)

Все темы уровня присутствуют. Для Middle SA:
- BPMN: Events, Subprocesses, Collaboration, Gateways
- UML: Component, Deployment, Package, Object диаграммы
- C4 Model: 4 уровня
- DDD глубже: Repository, ACL, Context Map, Domain Event
- SQL глубже: индексы, EXPLAIN
- API: GraphQL, WebSocket, AsyncAPI
- Безопасность: OWASP, STRIDE
- Observability: SLI/SLO/SLA
- ADR, CQRS/ES
- Тестирование: пирамида, contract testing
- Agile-церемонии, оценка: Story points, WSJF, RICE, Kano
- RACI, Event Storming, Domain Storytelling, Job Stories
- AI: RAG, MCP, prompt injection, guardrails, evaluation

### 4. Консистентность терминов

`СА`/`системный аналитик`, `БА`/`бизнес-аналитик`, `ФТ`/`функциональные требования` — единообразно. Первое упоминание в разделе — полная форма + аббревиатура, дальше — аббревиатура.

### 5. Переводы EN-терминов

У каждого английского термина при первом упоминании — перевод в скобках. Список must-have: CAP, ACID, BASE, OWASP, STRIDE, OAuth, OIDC, PKCE, JWT, mTLS, RAG, MCP, LLM, Agentic AI, ADR, CQRS, SLI/SLO/SLA, Event Storming, Domain Storytelling, Job Stories, Story points, Planning Poker, MoSCoW, RICE, WSJF, Kano, RACI, DDD, C4, BPMN, UML, REST, SOAP, gRPC, OpenAPI, AsyncAPI, WebSocket, SSE, GraphQL, CDC, Pact, Test doubles, Stub, Mock, Fake.

### 6. Артефакты машинного перевода

`grep -P "[^\x00-\x7Fа-яА-ЯёЁ\s\p{P}\p{S}\d]"` — 0 совпадений. Проверить: CJK (`運维`, `公開`, `弱шифрование`), корейский (`다루ть`), немецкий (`Sammlung`, `hält`, `Prinzip`), французский (`événement`), испанский (`resultado`), кальки (`samo`, `Sporiadic`, `optimised`, `проеция`, `эточки`, `ограличение`, `novoenum`, `поprojects`, `скрум`, `unoe`, `substitutable`, `newcomers`, `silos`, `navigates`, `trade-off`, `ambiguous`).

### 7. Структура

- Оглавление (ссылки на все части)
- Глоссарий (≥60 терминов)
- Вопросы для самопроверки (≥40, с `<details><summary>Ответ</summary>`)
- Шаблоны артефактов (SRS, User Story, Use Case, OpenAPI, RTM, реестр бизнес-правил, ADR, RACI)
- Ссылки на стандарты (≥15)
- Практика (≥8 упражнений)

### 8. Читаемость

Заголовки `##`/`###`, таблицы, блоки кода (SQL, YAML, PlantUML), единый стиль эмодзи, нет «стены текста».

## Workflow (строго по шагам)

1. Прочитать файл целиком.
2. `grep` артефактов — **до** (сколько найдено).
3. `grep` самодостаточности — **до**.
4. Проверить 3–5 фактов (вручную).
5. Проверить структуру (оглавление, глоссарий, вопросы, шаблоны, ссылки, практика — есть/нет).
6. Проверить переводы (список must-have).
7. Проверить консистентность (СА/БА).
8. Применить фиксы (если разрешено владельцем).
9. **После фикса — повторить `grep` артефактов и самодостаточности. Если не пусто — СТОП, фикс не применился.**
10. Записать отчёт с ID (`LEARN-01`, `LEARN-02`, …) в `reports/LEARNING_CONTENT_AUDIT.md`.

## Формат отчёта

| ID | Крит. | Раздел | Что именно | Рекомендация |
|----|-------|--------|------------|-------------|

Раздел «Проверено — чисто».

Раздел «Сводка: A/B/C».

Раздел «Оценка готовности: Junior/Middle/Senior — %».

## Критичность

- **A**: грубая ошибка (неверный стандарт, устаревший факт, утечка проекта, невозможность читать из-за артефактов).
- **B**: серьёзный пробел для Middle (нет C4/ADR/Event Storming/Component UML/BPMN Events), нет перевода у ключевого термина, артефакт машинного перевода в тексте.
- **C**: опечатка, стилистика, мелкий пробел, отсутствие практики по теме.
