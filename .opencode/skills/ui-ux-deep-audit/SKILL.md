## Что проверять

### 1. Иерархия и типографика
- H1 > H2 > H3 > body — размеры убывают
- Межстрочный интервал 1.4-1.6
- Отступы между блоками 16/24/32/48 (система 4/8)
- Нет двух элементов одного размера с разной ролью

### 2. Ритм и отступы
- padding/margin кратны 4px
- Одинаковые отступы у похожих блоков
- Между секциями больше, чем внутри секции

### 3. Пустые состояния (empty states)
- Что показывается если нет данных?
- Есть ли текст объяснения?
- Есть ли CTA?
- Например: поиск не нашёл → «Ничего не найдено, попробуйте другое»

### 4. Loading states
- Что показывается во время загрузки?
- Скелетоны/спиннеры/placeholder?
- Не «белый экран 3 секунды»

### 5. Error states
- Что показывается при ошибке?
- Понятное сообщение?
- Есть ли кнопка «Повторить»?
- Не «❌ TypeError»

### 6. Микроинтеракции
- Hover на кнопках (кроме mobile)
- Active состояние (:active)
- Transition 150-300ms
- Не «мгновенно»

### 7. Визуальная обратная связь
- Клик на кнопку → видно что нажалась
- Отправка формы → видно что отправилось
- Изменение фильтра → видно что применилось

### 8. Иерархия внимания
- Самое важное — самое заметное
- Главный CTA выделен
- Нет визуального шума

## Формат находки

Примеры правильных:

"index.html:196 — .trustbar font-size 12px, ниже минимальных 14px для основного текста. Воспринимается как неважный. Фикс: 13-14px + opacity .8."

"index.html — при пустом результате поиска нет сообщения. Пользователь видит пустую сетку без объяснения. Фикс: показать «Ничего не найдено по запросу X» с кнопкой Сбросить."

"style.css:182 — переход между темами 250ms, но фон и текст transition разной длины → мерцание. Фикс: одинаковый transition у всех переменных."

## Что НЕ проверять
- Цвета (это отдельный скилл)
- Мобильную адаптацию (mobile-deep-audit)
- Маркетинг
