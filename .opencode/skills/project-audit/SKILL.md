# Инструкция по полному аудиту

Триггер: пользователь просит "проведи аудит проекта" или "полное ревью".

## Жёсткие правила

1. НИЧЕГО НЕ УДАЛЯЙ И НЕ МЕНЯЙ в проекте
2. Единственный создаваемый файл — reports/AUDIT_REPORT.md
3. Работай в режиме только-чтение (read-only)
4. Все находки — с указанием файла и номера строки
5. Не додумывай: если не нашёл проблем — так и пиши

## Чек-лист из 12 проверок

### 1. Структура проекта
- Дерево верхних 3 уровней (исключая .venv, node_modules, .git, __pycache__)
- Файлы вне логичных папок
- Пустые папки

### 2. Устаревшие данные
Найди вхождения чисел: 103, 113, 94, 9074, 5135, 10759
Найди устаревшие версии: v3.6, v3.5, v3.4, batch 16, batch 17a
Формат вывода: файл:строка — найдено "103 добавки" — заменить на "130 добавок"

### 3. Мёртвый код
- Файлы .py в scripts/ без упоминаний в .md
- Функции внутри файлов без вызовов
- Импорты в начале файла, которые не используются

### 4. Дубли данных
- Сравни docs/data.json vs docs/api/v1/supplements.json (количество, поля)
- Сравни docs/data.json vs data/db/brain.duckdb (если БД есть)
- Проверь reports/ на старые версии отчётов

### 5. Битые файлы
- JSON-файлы невалидные (проверить через python -m json.tool)
- Файлы меньше 100 байт (кроме __init__.py)
- Пустые .md файлы
- Файлы с _test, _old, _bak, _tmp в имени

### 6. Зависимости
- Что в requirements.txt не используется в коде
- Что используется в коде, но отсутствует в requirements.txt
- Устаревшие версии (2+ года без обновлений)

### 7. Синхронизация документации
- Ссылки в .md на несуществующие файлы
- docs/glossary.md vs реальные термины в коде
- docs/data_dictionary.md vs реальные поля в data.json
- Упоминания версий (должны совпадать с текущей)

### 8. Безопасность
- Поиск по проекту: ключи API (exa, openai), пароли, токены, Bearer-токены
- Проверка .gitignore (что нужно добавить)
- Проверка какие файлы уже в git что не должны быть

### 9. Mermaid-диаграммы
- Найди все Mermaid-блоки в .md
- Проверь парность backticks (чётное число)
- Найди блоки с пустым содержимым

### 10. Большие файлы
- Файлы больше 10 MB в проекте (кроме .venv, node_modules)
- Файлы больше 100 MB в git LFS или основных папках
- Размер .git/ если доступен

### 11. Версионирование
- Текущая версия в docs/version.json
- Совпадает ли с последним тегом git
- Упоминания версии в README, ARCHITECTURE, остальных файлах

### 12. Тесты
- Все ли test_*.py содержат хотя бы 1 test_
- Пропущенные тесты (pytest.mark.skip)
- Тесты без assert

## Формат отчёта reports/AUDIT_REPORT.md

Отчёт должен содержать:

1. Шапка: AUDIT REPORT — brain-25-evidence, дата, автор (OpenCode)
2. Резюме: всего проверок 12, найдено проблем X, критичных Y, средних Z, мелких W
3. По каждому из 12 пунктов — раздел с находками или "чисто"
4. Раздел 9. Рекомендации — три уровня приоритета: критично / важно / можно отложить

Начни с резюме, потом по каждому пункту. Если пункт чист — пиши "чисто".
