# Repository Size Audit & Cleanup

> Граница: это углубление §10 «Большие файлы» скилла **project-audit**
> (там — только флаг «есть крупное»). Здесь — инвентаризация и план
> очистки. Не дублировать находки: project-audit фиксирует «крупный файл
> есть», repo-size-audit решает, что с ним делать.

## Локаль: RU + EN (обязательно для всех проверок)

Проверять в обеих локалях: RU (`lang="ru"`) и EN (`localStorage.lang='en'`).
Оба языка — столпы проекта, ни один не второстепенный. Каждая проверка выше
выполняется дважды — в RU и в EN; находку помечать локалью `RU` / `EN` / `RU+EN`.

| Локаль | Как включить | Откуда текст |
|---|---|---|
| RU | по умолчанию, `<html lang="ru">` | словарь `docs/i18n.js` (`I18N.ru`), данные — `docs/data.json` |
| EN | `#langSelect` или `localStorage.setItem('lang','en')` + перезагрузка | `docs/i18n.js` (`I18N.en`) + `docs/data_en.json` (паритет 130/130) |

- `docs/i18n.js` выставляет `document.documentElement.lang = LOCALE`;
  статический `<html lang="ru">` на всех страницах — это долг SEO-01, а не
  признак того, что RU главнее
- Переводятся атрибуты `data-i18n`, `data-i18n-text`, `-title`, `-alt`,
  `-aria-label`, `-placeholder`, `-tooltip`, `-vars`
- В EN не должно остаться кириллицы в интерфейсе (гейт
  `tests/test_i18n_no_russian.py`); русская строка в EN — находка
- Пока перевод не применён, `<html>` держит класс `i18n-pending`
  (`html.i18n-pending main{visibility:hidden}`) — проверять, что класс
  снимается и контент не остаётся скрытым
- Находка «только в RU» или «только в EN» — это находка, а не норма

`docs/data_en.json` (312 КБ) и `docs/i18n.js` (212 КБ) — живые
двуязычные артефакты, а не мусор: удалять нельзя.

- Крупный размер — повод для минификации или разделения, а не для
  удаления.

## Workflow

1. **Initial Scan & Inventory:**
   - Calculate the total tracked repository size (excluding `.git` and `.venv`).
   - List the top 10 largest tracked files.
   - Measure the size of key folders: `data/journals/`, `tests/snapshots/`, `docs/sup/`, and `reports/`.

2. **Project-Specific Analysis:**
   - **`data/journals/`:** Check if these files are read at runtime. If not, flag them for archival.
   - **`tests/snapshots/`:** Suggest compression using `scripts/compress_snapshots.py` (lossless).
   - **`docs/sup/`:** Confirm they are generated by `build_sup.py`. (Leave them if they are needed for static deployment).
   - **General Junk:** Scan for temporary files (`_tmp_*`, `*.log`), and `__pycache__` directories.

3. **Reporting:**
   - Present findings in a clear table with columns: Item, Size, Is it used?, Recommended Action (Delete/Compress/Archive/Ignore), and Potential Savings.
   - **Crucially:** Always present the report and ask for explicit confirmation before executing any destructive action (like `git rm`).
