# Repository Size Audit & Cleanup

> Граница: это углубление §10 «Большие файлы» скилла **project-audit**
> (там — только флаг «есть крупное»). Здесь — инвентаризация и план
> очистки. Не дублировать находки: project-audit фиксирует «крупный файл
> есть», repo-size-audit решает, что с ним делать.

## Workflow

1. **Initial Scan & Inventory:**
   - Calculate the total tracked repository size (excluding `.git` and `.venv`).
   - List the top 10 largest tracked files.
   - Measure the size of key folders: `data/journals/`, `tests/snapshots/`, `docs/sup/`, and `reports/`.

2. **Project-Specific Analysis:**
   - **`data/journals/`:** Check if these files are read at runtime. If not, flag them for archival.
   - **`tests/snapshots/`:** Suggest compression using `scripts/compress_snapshots.py` (lossless).
   - **`docs/sup/`:** Confirm they are generated by `build_sup.py`. (Leave them if they are needed for static deployment).
   - **General Junk:** Scan for temporary files (`_tmp_*`, `*.log`), and `__pycache__` directories.

3. **Reporting:**
   - Present findings in a clear table with columns: Item, Size, Is it used?, Recommended Action (Delete/Compress/Archive/Ignore), and Potential Savings.
   - **Crucially:** Always present the report and ask for explicit confirmation before executing any destructive action (like `git rm`).
