# Product Audit

Триггер: "проведи product audit", "аудит UI/UX", "product-аудит".


## Правило верификации находок

Прежде чем фиксить находку — воспроизведи её:
- mobile: реальный viewport в Playwright
- touch: getBoundingClientRect() с реальным кликом
- тест: мутация (сломать → тест падает)
- JS: node --check + реальный прогон
- данные: запрос к файлу, не к памяти

Если не можешь воспроизвести — находка не подтверждена,
в отчёт идёт со статусом «требует верификации».

Не «починил бы» и не «добавил бы clearRect на всякий случай» — сначала
воспроизвёл. В QA-аудите этого проекта **5 находок из 42** оказались ложными,
и все пять я бы выдала как критичные: `cv.width = ...` уже чистит canvas,
`Рёбер` не есть мозгибаки, `lib/` жив и нужен генератору отчёта.

## Формат находки — ОБЯЗАТЕЛЬНО

Каждая находка:
- файл:строка
- что не так (с цифрами, не "плохо")
- как исправить
- приоритет

ПРИМЕРЫ ПРАВИЛЬНЫХ НАХОДОК:

"style.css:718 — .btn.c-support padding 6px 12px, высота ~32px. Touch target < 44px (WCAG). Исправить: padding 12px 20px."

"sup/kreatin.html:47 — .verdict цвет #6e6e73 на #f5f5f7 = 3.1:1. WCAG AA требует 4.5:1 для обычного текста. Заменить на #5a5a5f."

"index.html — на главной нет явного CTA 'Начни с калькулятора'. Пользователь видит только поиск. Добавить CTA-карточку сверху."

ПРИМЕРЫ ПЛОХИХ НАХОДОК (не включать):
- "кнопка маленькая" (без цифр)
- "плохой контраст" (без ratio)
- "некрасиво" (субъективно)
- "нужно больше контента" (бизнес-решение)

## Что НЕ включать в отчёт

- Стилистические пожелания без цифр
- Субъективные оценки
- Задачи требующие бизнес-решений
- Дубли между страницами если уже отмечены

## Граница с deep-скиллами

`product-audit` — **быстрый обзор** 4 направлений за один проход (15-20 мин).
Глубокие скиллы (`ui-ux-deep-audit`, `marketing-deep-audit`,
`qa-deep-audit`, `mobile-deep-audit`) — отдельные длинные прогоны со своими
отчётами. Не запускать оба уровня на одну задачу: нужен разбор одного
направления — брать deep-скилл, а не расширять этот. Дубли между отчётами
не создавать: кто первый заметил — тот описывает, второй ссылается.

## Направления

### 1. UI/UX (docs/*.html, style.css)

Консистентность:
- Набор кнопок .actions на главных HTML идентичен (список — см. CONVENTIONS.md)
- Футеры идентичны
- Тёмная/светлая тема работает одинаково на всех
- Breadcrumbs на sup/*.html корректны
- Hover/focus у всех кликабельных

Доступность:
- Контраст по WCAG (4.5:1 текст, 3:1 крупный)
- Alt у img
- aria-label на иконочных кнопках
- Фокус видно
- lang=ru

### 2. Маркетинг

- title 40-60 символов, уникальный
- meta description 120-160
- og:title, og:description, og:image, twitter:card на всех главных HTML
- JSON-LD: есть на sup/, НЕТ на main HTML (это находка)
- CTA на главной
- Ценность понятна за 5 сек
- og.png существует и открывается

### 3. QA

- Тесты на analyze_coi.py, graph_interactions.py, build_api.py — их НЕТ (находка)
- Обработка ошибок fetch на фронте
- Валидация формы feedback (есть ли)
- Что если data.json не загрузился
- Клавиатурная навигация Tab/Enter/Escape
- A11y basics

### 4. Mobile

- viewport на всех главных HTML
- Touch targets >= 44px (кнопки в .actions, ссылки в футере)
- Шрифты >= 16px для inputs (иначе iOS зумит)
- Горизонтальный скролл (не должно быть)
- .quick-links адаптив
- Модалки помещаются в экран
- Media queries на 320/375/600/900/1200px
