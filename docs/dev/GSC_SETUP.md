# Google Search Console — настройка

**Дата:** 2026-10-04 (v5.4.2) · **Статус:** инструкция готова, верификация
за владельцем — техдолг 37.

GSC даёт: индексацию сайта, ошибки краулинга, запросы и клики, динамику
покрытия. Он же умеет отправлять карту сайта и проверять живость URL —
то есть частично заменяет мониторинг из `MONITORING.md`.

---

## 1. Регистрация

<https://search.google.com/search-console> → войти аккаунтом Google,
которым владеет владелец сайта (не общим рабочим — доступ к статистике
привязан к аккаунту).

---

## 2. Добавление ресурса

**Add Property** → **URL prefix** (рекомендуется для GitHub Pages, потому
что вариант «Domain» требует DNS-верификации, которой у проекта нет):

```
https://deadsno.github.io/brain-25-evidence/
```

Не `http://`, не с завершающим пробелом, именно с `/` на конце.

**Доменное имя** не подходит: `deadsno.github.io` — поддомен GitHub,
верифицировать его через DNS нельзя, а аккаунт один на все проекты.

---

## 3. Верификация

**Выбран HTML file, и он уже на месте:** `docs/google4a9d23e35c6c3e23.html`,
53 байта, одна строка `google-site-verification: google4a9d23e35c6c3e23.html`.

Осталось нажать **Verify** в GSC — проверка идёт по живому сайту, файл
уже опубликован через Pages.

### 3.1 Почему файл, а не HTML tag

Оба способа рабочие. Файл выбран, и у него есть особенность, о которой
нужно знать: **он лежит в корне сайта рядом со страницами**, и на этом
сломался один из инструментов проекта.

`scripts/audit_classes.py` отбирал страницы по расширению `.html` и принял
файл верификации за страницу: `tests/test_no_orphan_classes.py` упал с
«аудит разобрал 19 страниц вместо 18». Исправлено в
`scripts/audit_classes.py::is_page` — отбор по наличию тега `<html>`, а не
по имени файла. Ниже в разделе 6 описано, почему именно так, и почему
ошибка не может повториться молча.

По сравнению с HTML tag у файла два плюса: содержимое не трогает
`index.html`, и токен не надо вылавливать в коде. Минус — файл нужно
положить в `docs/` и не забыть про него при переезде на домен.

### 3.2 HTML tag — запасной вариант

Заглушка **уже стоит** в `docs/index.html:12`:

```html
<meta name="google-site-verification" content="ВСТАВЬТЕ-КОД-ИЗ-GSC">
```

Если файл по какой-то причине не сработает (например, при переезде на
свой домен путь к нему изменится), верификация делается через тег:

1. Скопировать значение `content`, которое даст GSC (строка вида
   `AbCdEf...=`)
2. Заменить в `index.html:12` текст `ВСТАВЬТЕ-КОД-ИЗ-GSC` на полученное
   значение
3. Закоммитить и запушить
4. В GSC нажать **Verify**

### 3.3 DNS — неприменимо

Домена нет, делегировать нечего. Вариант появится, если сайт переедет на
свой домен.

Проверка занимает до 48 часов, обычно минуты.

## 4. После верификации

### 4.1 Карта сайта

**Sitemaps** → **Add a new sitemap** → указать:

```
sitemap.xml
```

GSC подставит префикс домена сам. Файл `docs/sitemap.xml` содержит
17 URL и отдаётся статически; в `docs/robots.txt` он уже объявлен:

```
Sitemap: https://deadsno.github.io/brain-25-evidence/sitemap.xml
```

После добавления статус должен стать **Success** в течение суток.

Если статус **Error**, сверять два числа: URL в `sitemap.xml` и число
HTML-страниц в `docs/`. Сейчас обе величины равны 17, расхождение
означает, что какая-то страница забыта либо удалена.

### 4.2 Покрытие

**Pages** (ранее «Indexing → Coverage»). Что смотреть в первые недели:

| Проблема | Значит |
|---|---|
| «Проиндексировано» растёт | всё в порядке |
| «Обнаружено, но не проиндексировано» | Google нашёл страницу, но решил не включать. Обычно мелочь, бить тревогу рано |
| «Исключено — ошибка» | настоящая поломка: битая ссылка, 5xx, robots |
| URL в индексе, которых нет на сайте | бывает после переименования страницы |

### 4.3 Проверка URL

**URL Inspection** → вставить адрес → **Test live URL**. Это разовая
проверка «может ли Google её отдать», до и после верификации полезно
прогнать главную и одну страницу из `sup/`.

## 6. Файл верификации и инструменты проекта

`docs/google4a9d23e35c6c3e23.html` — не страница. Он лежит в корне
`docs/` рядом с 18 страницами, потому что GSC требует именно такой путь.

Из-за этого 2026-10-04 упал `tests/test_no_orphan_classes.py`: аудит
классов отбирал файлы по расширению `.html`, принял файл верификации за
страницу и насчитал 19. Что сделано:

| где | что |
|---|---|
| `scripts/audit_classes.py` | добавлена `is_page()`: страница — это файл с тегом `<html>`. Применяется и к CLI-инструменту, и к тесту |
| `tests/test_no_orphan_classes.py` | `EXPECTED_PAGES = 18` снабжена пояснением, почему число не 19 |

**Почему отбор по тегу, а не по имени `google*.html`.** Перечисление имён
перечисляет сервисы: верификация Bing или Яндекса потребовала бы ещё
одной строки, а настоящая страница с именем `google-search.html` молча
выпала бы из аудита. Тег `<html>` отвечает на вопрос по существу: аудит
разбирает страницы, а файл без полного HTML-документа страницей не
является.

**Почему это не дырявый фильтр.** Настоящая страница, потерявшая тег
`<html>`, уронила бы счётчик до 17, и `test_audit_covers_every_page`
упал бы. Проверено: сценарий с намеренно снятым тегом в `faq.html` даёт
падение «аудит разобрал 17 страниц вместо 18». Молча пройти не может.

**Что делать при переезде на домен.** Файл верификации GSC привязан к
`deadsno.github.io`. На своём домене его придётся заменить на новый
токен, а этот удалить — он больше не нужен и будет только занимать
корень сайта.
