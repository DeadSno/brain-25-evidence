## Multi-agent mode
This project is worked by several agents at once against one working tree.
Rules below are not etiquette — each one names a concrete way the run goes
wrong without it.

- **A read-only task may snapshot state before a write task finishes.**
  Measured: agent-4 reported that `docs/sup/index.html` was missing and
  filed it as a release defect while agent-2 was generating that same file.
  Read-only agents MUST re-read state after the write they were waiting on
  and must phrase findings as time-stamped ("as of <commit> <path> was
  absent") instead of asserting a defect. Order: read-only snapshots AFTER
  write. Tracked as tech debt #86.
- **One file, one owner.** Give each agent a disjoint file list and say
  explicitly which files are off-limits. Two agents editing one file do not
  produce a merge conflict the usual way — the later edit silently wins,
  and `git status` looks clean afterwards. Never hand `docs/index.html`,
  `docs/sw.js`, `docs/version.json`, `tests/` and `docs/vendor/` to two
  agents in the same pass.
- **Every agent writes its own report file** (`reports/<TASK>.md`) and
  lists its own changed paths there. Do not infer another agent's file list
  from `git status` — it mixes everyone's work, and taking credit for it
  corrupts the next agent's starting point.
- **Reports are evidence, not a source of truth for numbers.** Re-derive
  every figure from the tree. Example from this project: a report claimed
  `docs/data.json` holds 81 items and another claimed 130; the truth was
  measured per run and only the measurement counts.
- **Say what you did not check.** "Verified" with a command and its output
  is worth something; "verified" without either is worse than silence,
  because the next agent repeats it.

## Parallelism
- **Do not run the same browser gate twice at once.** Port `:8000` is
  claimed by exactly one agent per pass. Reason, measured: snapshot tests
  skip silently when the server is unreachable — the run turns green
  (`0 failed`) while 74 tests never executed. A green gate in that state is
  a gate that proved nothing.
- **Gate of record for every other agent is `pytest -q`.** If you need
  `RUN_SNAPSHOTS=1`, say so in your report and let the port owner run it,
  rather than starting your own server on the same port.
- **Watch the port before you take it.** `Invoke-RestMethod
  http://localhost:8000/version.json` — if it answers, the port is not
  yours. A server you did not start is someone's deliberate fixture.

## Playwright wrapper: `route.abort()` does not work here
Measured 2026-10-06: a registered `route.abort()` handler fires **zero**
times, including on the control pattern `**/vendor/**` that certainly
matches. So any "blocked the CDN" measurement made through request
interception reports a **false zero** — the request went through and the
measurement cannot tell. Do not claim "without CDN" or "offline" from
interception alone:
- measure on file variants instead (copy `docs/`, delete the tags, diff
  computed styles and screenshots), as `reports/VENDOR_CLOSE.md` §2.3 did, or
- prove interception works before trusting it — one known-matching route,
  then check the counter is non-zero.
Tracked as tech debt #85.
