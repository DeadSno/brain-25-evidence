# ADR-001: Хранение в JSON, а не в БД

- **Статус:** Accepted
- **Дата:** 2026-09-25
- **Контекст:** Нужно выбрать способ хранения 130 карточек с вложенными структурами (mechs, interactions, key_sources).

## Решение

Хранить в одном файле `docs/data.json` (UTF-8, без BOM).

## Альтернативы

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **JSON-файл** | Простой, работает на GitHub Pages без сервера, версионируется git | Не масштабируется > 10 000 записей, нет запросов |
| SQLite | SQL-запросы, ACID | Не работает на GitHub Pages без сервера |
| PostgreSQL | Полноценная БД, оконные функции | Требует VPS, ~500 руб/мес |
| MongoDB | Гибкая схема | Избыточно для 130 карточек |

## Обоснование

1. **Размер:** 76 KB на 130 карточек → оценочно 60 MB на 100 000. JSON справится.
2. **GitHub Pages:** отдаёт статику бесплатно. БД потребует VPS.
3. **Версионирование:** каждое изменение видно в git diff.
4. **Клиент:** браузер парсит JSON за 30ms.

## Последствия

- Простая публикация без backend
- Git-история всех изменений
- Нет транзакций, параллельных записей
- Полная загрузка в память (для 130 ок, для 100k — нужна пагинация)

## Когда пересмотреть

При росте до >5 000 карточек — миграция на SQLite + API.
