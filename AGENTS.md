# AGENTS.md — brain-25-evidence

Рабочий процесс и правила для агента в этом репозитории.
Создано v5.6.1 при переходе на одиночный агент (OpenCode 1.18.33).

## Рабочий процесс

- **Одна задача = одна сессия.** Закрывай сессию после коммита.
- **`/handoff <цель>`** — передача контекста в новую сессию. Плагин
  `@andrewhampton/opencode-handoff` ставит команду; она разбирает диалог,
  вытаскивает решения и ссылки на файлы, готовит промпт для новой сессии.
  Проверить: команда появляется после перезапуска OpenCode.
- **Пиши меньше.** Отчёты — на диск (`reports/`), не в чат. В чат — выводы
  и числа.
- Перед задачей проверь, есть ли подходящий скилл (список ниже), и назови
  его в задании.

## Git MCP — permission

MCP `git` даёт 12 инструментов:

- **Read-only (7):** `git_status`, `git_log`, `git_diff`,
  `git_diff_staged`, `git_diff_unstaged`, `git_show`, `git_branch`
- **Write (5):** `git_add`, `git_commit`, `git_checkout`,
  `git_create_branch`, `git_reset`

Правило:

- Read-only вызываются свободно.
- **Write — только по явной команде владельца в задаче.**
- `git_reset` и `git_checkout` не вызывать без явного разрешения даже
  в общем виде «приведи репозиторий в порядок»: сброс индекса и
  переключение ветки необратимы без `reflog`.
- При сомнении — спросить, а не догадываться.

MCP-вызов не проходит через `permission.bash`, поэтому ограничения из
«Правил безопасности» на эти инструменты сами по себе не
распространяются. Настоящий раздел — то, что их заменяет.

Две ловушки API, проверенные на деле 2026-10-07:

- **Неизвестные параметры молча игнорируются.** `git_log` принимает
  `max_count`, а не `count`; `count` ошибки не даст — вернётся
  умолчание (10 коммитов). Выборку всегда сверять по факту.
- **`git_diff` — диф против ревизии, а не против рабочей копии.**
  `target` читается как ref: `target: "unstaged"` вернёт
  `Ref 'unstaged' did not resolve to an object`. Для изменений в
  рабочем дереве — `git_diff_unstaged` / `git_diff_staged`.

## Subagents

- `local-fast` — локальный исполнитель для чтения / поиска / разбора.
  Модель `ollama/qwen-instruct-top:latest`. **Read-only:** `edit` и `shell`
  запрещены в `permissions` агента.
  **НЕ использовать для генерации кода** — качество ниже облачной
  модели. Зато не жжёт токены и отвечает за локальное время.

  Запрет `edit` сам по себе read-only **не** обеспечивает: модель обходит
  его через `shell` — редирект, `git`, `python`. Проверено: с одним лишь
  запретом `edit` агент успешно выполнял `git --version`, то есть вектор
  записи оставался открыт. Нужны оба запрета.

### Ограничения local-fast

Специализация — **чтение по известному пути**: один известный файл,
извлечь поле или фрагмент. На этом применении проверено 6 из 6.

**НЕ использовать для массовых задач.** Ограничения по результатам
теста 2026-10-07 («найди все хардкоженные числа в `scripts/*.py`»):

- 7B галлюцинирует на объёмных задачах — **выдумывает несуществующие
  строки**. Из 8 проверенных ссылок `файл:строка` подтверждено 2,
  ещё 3 указывали за пределами файла (строка 223 в файле из 47 строк).
- Не проходит по репозиторию целиком (90 `.py` в `scripts/`).
- Отличает плохо: из двух «верных» находок одна — расчёт отступа
  при выравнивании, а не конфиг.
- Массовые задачи — **облачный агент + Serena MCP**: она даёт настоящие
  `file:line` без конструирования.

Распознавать признак провала просто: агент выдаёт уверенный список
`файл:строка:значение` с пояснениями, но файлы при этом не открывал.
Отчёт выглядит безупречно и опасен именно поэтому — сверять такие
списки построчно перед использованием.

## Qwen-модели: tool calls

Проверено на Ollama 0.40.0 — `/api/chat` с настоящим `tools` и через
реального субагента:

- **`qwen2.5-coder:7b` и производные (`qwen-coder-top`) — НЕ
  поддерживают tool calls.** Модель выдаёт вызов инструмента обычным
  текстом: возвращает `{"name": "read_file", "arguments": {...}}` в
  поле `content`, структурное `tool_calls` пустое, инструмент не
  исполняется. Как subagent бесполезен — агент завершается, ответ неверен.
  Только для ручного `ollama run` из терминала, где инструменты не
  нужны.
- **`qwen2.5:7b-instruct` и производные (`qwen-instruct-top`) — работают
  с tool calls.** Годится как subagent.

Дело в **базовой модели**, а не в Modelfile: при одинаковых PARAMETER и
SYSTEM пересборка из instruct даёт работающие вызовы.

Побочный эффект: `qwen2.5:7b-instruct` иногда выдумывает имена
инструментов, которых нет, и печатает их как текст. Безвредно, но
портит ответ — учитывать при оценке.

Проверено 2026-10-07. Отчёты: `reports/LOCAL_DELEGATION.md`,
`reports/LOCAL_DELEGATION_FINAL.md`.

## LSP

Навигацию по коду даёт Serena MCP (29 tools): определения, references,
символы, структура. Работает через semantic retrieval, а не regex по
тексту. Для навигации Serena — основной инструмент; ручной `grep` по коду
использовать только как fallback.

Отдельные языковые серверы тоже подключены — блок `lsp` в `opencode.json`
явный, а не автоматический (устаревшая версия этого раздела утверждала
обратное):

- `pyright` / `pyright-langserver` — Python
- `typescript-language-server` — TypeScript

Оба в PATH (проверено 2026-10-07).

## Правила безопасности

Эти правила выведены из реальных потерь в этом проекте, а не из стиля:

- **НЕ regex по HTML/CSS.** Правки — через Edit вручную. Регулярка по
  разметке ломает файлы незаметно.
- **НЕ `git checkout`/`reset` без `git stash` или `git diff`.**
- **НЕ `git merge`** в этой ветке. `main` не трогаем, теги не ставим.
- **НЕ инлайновый Python через heredoc** — вешает TUI. Многострочное
  → `_tmp_xxx.py` → запуск → удалить.
- Кириллица в PowerShell-пайпах ломается — писать в файл.
- **`route.abort()` не работает** в этой Playwright-обёртке: 0 срабатываний
  даже на контрольном шаблоне. Замеры «без CDN» через перехват сети дают
  ложный ноль.

## Известные ловушки проекта

- **Эталоны снапшотов скипаются молча**, если сервер на `:8000` не
  отвечает: 74 skipped выглядит как успех. Всегда проверяй
  `Invoke-RestMethod http://localhost:8000/version.json` перед прогоном.
- **Edit иногда не находит текст с кириллицей** в некоторых файлах. Если
  `oldString` не подошёл — не повторяй ту же попытку, а замени по номерам
  строк скриптом.
- **`tests/test_silent_handlers.py` пин-кодит номера строк** в `sw.js`.
  Любая правка `sw.js` сдвигает строки и роняет тест. Обновляй номера по
  факту (техдолг #52).
